## 升级步骤（方案 A，推荐）

1. **先退出 Timing**（托盘图标 → 退出，别只关窗口）。
2. 解压 `Timing-0.11.17-portable.zip`。
3. 把解压出来的 `Timing.exe` **单独**复制到 `C:\Software\SmallTools\Timing\`，覆盖同名文件。
4. `data\` 与 `plugins\` 不要碰（zip 里只是占位 README）。
5. 启动，「设置 → 关于」应显示 `0.11.17`。

## 这一版修的三件事

1. **「测试连接」不再误报红字。** 原来第一步是对**目录**发一次读取，坚果云不允许这么读、回了个 403，程序把它当成「账号不对」——于是同步明明正常，界面却一直红。
   现在：目录读不动不再算失败，改由第三步「真的写进去一个探针文件再删掉」来裁定。**能写就是绿，写不进去才报红**，而且只报真正卡住的那一步。
   连带的第二种误报也修了：你在网页版已经建好 `Timing` 文件夹时，程序去建同名目录会被拒（403 而不是「已存在」），以前第二步也会红，现在同样交给写入结果裁定。
2. **默认远端目录改成 `/Timing`。** 输入框下方多了一行小字提醒：首次使用请先到坚果云网页版，在「我的坚果云」下新建名为 `Timing` 的文件夹。
   已经配过云端的人不受影响，原来的地址一个字不改。
3. **本地目录模式仍会对账。** 选「本地目录」时不会往 WebDAV 发任何请求，但那个目录里的 `.md` 与数据库有没有差异仍然照常比对——你在那份文件里手写的内容会导回数据库，「今天已上传」的状态也是按真实比对结果给的。

## 装完验一下

1. 设置 → 数据管理 → 第四块点「测试连接」→ 应该是三关全绿（**这一条只有你能验**，我这边连不上你的坚果云）。
2. 若第二步仍红，红字会明确说「哪一级建不出来」，并让你去网页版新建 `Timing` 文件夹——照着建完再点一次即可。
3. 第一块把日记文件名改成 `{date}-asd.md` 保存，落点目录里应只有一个 `2026-11-07-asd.md`。
