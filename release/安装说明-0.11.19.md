## ⚠️ 先读这一段：这一版会**永久删除**你云端的旧日记

这是 0.11.19 最大的一件事，也是最不可逆的一件。

**它会做什么**：Markdown 同步目录里，**只留今天那一份** `yyyy-MM-dd.md`，往期的**从磁盘上删掉**。云端（WebDAV 或你选的本地目录）两边都清。

**它不会做什么**：

- 只删**文件名严格是 `yyyy-MM-dd.md`** 的文件。别的一律不碰。
- 只删**今天之前**的。今天那份**任何时候都不删**。
- 如果同步目录和你的日记本目录**重合**（或互为父子），**整段拒绝**，一个文件都不删，界面上给你红字。
- 删之前**先备份**。备份没落地就**不删**（这条有专门的判据盯着）。

**你必须知道的三个事实**：

1. **这是永久删除**。Windows 上 `DeleteFile` 不进回收站。删掉就是删掉。
2. **备份只保最近 30 份**（`md_backup::KEEP = 30`）。第一次大扫可能删 200 份，分 10 批删完，**最终只有最后 30 份能从 `backups\md\` 捡回来**。别以为 200 份都在。
3. **这个目录是给别的软件读的传输目录**，不是你的资料库。你真正的资料是 SQL 里的数据——日记被删了，下一轮同步会重新生成当天的；但**被删那一天的手写内容**（别人写进那个 md 的部分）不会回来。

**如果你还没准备好**：先别升级，或者在「设置 → 数据管理 → 云端同步」里把自动同步关掉，等你确认过云端目录里没有你还需要的东西再开。

## 升级步骤（方案 A，推荐）

1. **先退出 Timing**（托盘图标 → 退出，别只关窗口）。
2. 解压 `Timing-0.11.19-portable.zip`。
3. 把解压出来的 `Timing.exe` **单独**复制到 `C:\Software\SmallTools\Timing\`，覆盖同名文件。
4. `data\` 与 `plugins\` 不要碰（zip 里只是占位 README）。
5. 启动，「设置 → 关于」应显示 `0.11.19`。

**方案 B（安装包）**：跑 `Timing-0.11.19-setup.exe`。注意它装到 `%LOCALAPPDATA%\Programs\Timing\`，那里是**空的 data 目录**，不会自动读到你原来的数据——要沿用旧数据得手工把 `data\` 搬过去。

## 这一版改的六件事

### 1. 云端只留当天，往期真删（上面那段已经说清）

「Markdown 同步」这个功能的定位本来是**传输**：把 SQL 里的当天内容渲染成一份 md，给别的软件读。以前它只写不清，于是一年下来云端堆了几百份。这一版开始，同步完成后会把往期清掉。

清理是**分两路取证**的，两边不共用一套判断：WebDAV 那路看本地镜像里有没有同名文件；本地目录那路要求「这行是我们自己写的、而且文件当前内容和记录的指纹一致」。**任何一条对不上就不删**，记一行日志说明原因。

失败不会静默：删到第 N 个失败，水位停在**失败项之前**，下一轮从那儿接着来，不会跳过。

日志在 `data\logs\md-cloud-purge.log`，每一行能追到具体哪个文件。

### 2. 汇总日记不再写（改成只写自己那一段）

以前同步会在你的 md 里写一整篇「汇总日记」。问题是那个位置**别的软件也会往里写日记**，两边互相覆盖。

现在 Timing **只写自己那几段**（计时记录、待办、便利贴那几个带标记的区块），**别人的内容逐字节不动**。你手写在别处的部分不会被它改写。

### 3. 中英切换去掉了，安装流程改全中文

那个「中英切换」看着像功能，其实只切了同步页一个地方，其余全是中文——留着只会让人以为切了没生效。这版删掉。

安装向导改成全中文（许可协议、快捷方式、卸载界面）。**这一条需要你亲手跑一次安装包确认**，自动化测不到。

### 4. 同步不再等 15 分钟

以前是定时轮询，最长要等 15 分钟才写一次。现在：

- **SQL 里一改就写**（800 毫秒去抖，连着改多次只写一次）
- **md 那边一改就导回来**（1.5 秒去抖）
- **兜底 60 秒**：万一前面的事件都没触发，一分钟必跑一次

界面上原来那个「间隔几分钟」的输入框没了，换成一个三档选择（关闭 / 定时 / 智能），默认智能。

### 5. 设置里「数据迁移」那张卡去掉了

那张卡是给老版本升上来的数据做一次性转换用的，早跑完了。界面上删掉，**但后端逻辑保留**——真需要的时候它还会自己跑，不影响你的数据。

### 6. 新增「SQL 数据管理」的方案（**只有方案，没有实现**）

你提的第 6 条：一个能快速删掉往年/几个月前数据、并且能导出导入的窗口。**这一版只出了方案，一行代码没写**，方案在 `for-forg/14-PRD-v0.11.19-增量与数据管理.md` §六（数据盘点 → 同类软件怎么做 → 候选方案 → 推荐 → md 回流问题 → 与真删功能的先后顺序）。

**方案里有一条结论值得你现在就知道**：清 SQL 之前必须先确认那一年份的云端已经被清理或已经导出——因为云端那份 md 是 SQL 的渲染，SQL 清掉了，那份就是最后一份。

## 出包后的三件人工验证（自动化测不到）

1. **中文安装向导**：跑一次 `Timing-0.11.19-setup.exe`，看许可协议 / 快捷方式 / 卸载界面是否全中文、有没有语言选择页。
2. **托盘「退出」先同步**：改一笔数据，立刻托盘右键退出，看是否出现灰字「正在同步…」、退出后那笔数据在不在。
3. **真坚果云真删端到端**：用真的坚果云跑一轮，确认远端只剩今天那一份、`md-cloud-purge.log` 逐条可追、`data\backups\md\` 里有 `folder__` 或 `webdav__` 前缀的留底。**这是本功能唯一没被自动化覆盖的终局验证。**
