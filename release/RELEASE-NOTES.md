## v0.11.31 — 常用事项由用户钉，事项页按事项合并，记录页可翻往期（只有手机包）（2026-11-09）

主人对上轮三条待定的回复，本轮全部落地。桌面零改动。

### 换事项面板：常用 / 最近用过 / 其他事项

「常用」不是算法算出来的，是用户自己钉的——电脑端那套 `pinnedItems`（`items.is_pinned`）
与 `recentItems`（`updated_at` 倒序前 5）原样复用，手机端缺的只是**入口**。
每行右边一个图钉，点一下 = `item_update { isPinned }`，电脑端的常用列表立刻同步
（同一个布尔字段，不是手机自己的一份偏好）。三段互斥，同一事项不会出现两次。

### 事项页第三段 → 已完成待办

新纯函数 `lib/todayDone.groupTodayDone`：按 `itemId` **完全合并**（不再是「事项 + 时间连续性」），
多段 = 一行 + 合计时长 + ×N 段；今天打了勾的待办即使一段计时都没有也会出现；
计了时没打勾的保留并标「未勾选」。认领顺序先 `itemId` 再标题（改名后不失配、没绑事项的也能认）。
**这一页不再有任何计时入口**（上一版加的行尾「▶ 开始」删掉了）：主人原话「应不与计时界面功能重复」。

### 记录页五档范围

`RecordsRange` 扩成 `day / week / last7 / month / date`，全部区间由 `lib/time.rangeBounds(range, reference?)`
算；「往日」用系统原生日期控件，`max` 卡在今天，`2026-02-30` 这类不存在的日期会被拒。
档位横滚（五个档各占 1/5 在 375px 屏上只有 66px）。

### 待办排时间 + 手机上终于能收到提醒

新面板 `TodoPlanSheet`：今天 / 明天 / 3 天后 / 7 天后 + 时刻，「不排期」= 两个时间都空。
字段口径照电脑版：**开启时间 → `remind_at`**（手机端不暴露截止时间 `planned_at`）。
后端 `jobs::nudge` 原来只 `emit_todo_nudge`，而手机端没有任何组件订阅它——待办提醒在手机上
**从来没响过**；现在 `#[cfg(mobile)]` 补一条系统通知（桌面留空实现，那边有 `ReminderPopover` 浮层）。

### 顺手加固

`SheetHost` 的 `default: return null` 换成穷尽 switch + `never` 断言：以后漏接一种面板是
**TS 编译期报错**，不是「点了没反应」。行数门禁逼出两次按功能拆分（`DoneRow.tsx` / `items-done.css`）。

## v0.11.30 — 点了没反应：五个面板的 X 一起修（只有手机包）（2026-11-09）

主人一次报了 9 条，其中三条（倒计时 X / 换事项 X / 事项编辑 X）是**同一个 bug**。

### 根因

`Sheet` 的关闭按钮写的是 `onClick={onClose}`，React 会把 MouseEvent 当第一个实参传给
`onClose`；而 `closeSheet(kind?)` 的旧实现用 `kind != null` 判断「有没有指定类型」——
事件对象对 `!= null` 也为真，于是 `s.sheet.kind !== <MouseEvent>` 恒成立 → 返回原 state
→ **面板一动不动**。

裸传 `closeSheet` 的地方有五个，主人碰到了三个，另外两个（记录编辑、便利贴归属）一样是坏的。

**为什么长期没被发现**：面板的另外两个出口（下滑抓取柄、Android 返回键）不走 `onClose`，
手动测试时很容易被它们掩盖；单测从来没点过那个 X。

### 改法

- `closeSheet` 只认字符串：非字符串实参一律当「不指定类型」→ 直接关（第二道防线，
  管已存在的调用点）；
- 五个面板各自 `closeSheet('countdown')` / `('switchItem')` / `('itemMenu')` /
  `('recordEdit')` / `('noteItem')`——语义也从「碰巧能关」变成「只关我这一张」；
- 门禁加源码判据：不许再出现 `onClose={closeSheet}` 这种裸传。

### 顺带修的

| # | 原来 | 现在 |
|---|---|---|
| 5 | 事项页点记录 = 直接开始计时 | 点 = 事项编辑；行尾「▶ 开始」负责计时（长按同义） |
| 6 | 便利贴删除只有长按 | 每行右上角垃圾桶，点了先确认 |
| 7 | 同步要翻到设置页 | 计时页工具条第三个按钮「同步」，复用同一个命令 |

### 没做的三条

快捷事项菜单（近期 / 常用）、事项页改「已完成待办」+ 待办预计时间与提醒、「本周没有往期数据」。
前两条是整轮的量；第三条查不出复现路径，需要主人给一句现场情况（总计有没有数字、当天是不是周一）。

### 产物

`release/Timing-android-0.11.30-release-arm64-debugsigned.apk`（11.1 MB），sha256 `d0b3b3bb…`。

## v0.11.29 — 点按切计时，长按才进 App（只有手机包）（2026-11-09）

主人一句话：「点按暂停 长按再跳转至界面」。上一版把「悬浮条 ↔ 主界面」两条路都接通了，
这一版把**「点一下」和「进 App」拆开**——前两版留下的三处会让点按跑偏：

| # | 原来 | 现在 |
|---|---|---|
| 1 | 圆点形态下点一下只是展开成条，计时不停（第二下才暂停） | **一下**就切状态；展开仍然给，但不再吃掉这一按 |
| 2 | 前端没在听（App 被划掉）时，点一下直接把人拽进 App | 不跳转：标记落盘 + 通知栏写明原因，回 App 时补做一次 |
| 3 | 长按能进 App，但没人知道 | 长按进 App，判定命中时**震一下**作为回应 |

第 1 条是从归档原生版（`android-app` 0.3.6）抄来的，那边写「避免误触暂停」——
可那边的圆点只在计时中出现，第一下展开等于确认意图；本仓圆点待机也常驻，
同一段代码就变成了「第一下没反应」。照抄代码抄不来它当时的前提。

第 2 条是 0.11.27 加的兜底，本意「宁可多一步，也不做点了没反应」。方向没错、代价错了：
点按的语义是停表，不是进 App。现在长按专门管进 App，这条兜底就退场了。

### 为什么不干脆把原因也省掉

「失败不可见」是本项目反复踩的病根。跳转被拿掉之后，眼前确实什么都不变，
所以原因必须落在**此刻唯一看得见的地方**——通知副标题：「没连上界面，这一按已记下：
回到 App 时补做」。同时动作的标记还在盘上，App 回前台时按类型补做一次。

### 产物

`release/Timing-android-0.11.29-release-arm64-debugsigned.apk`（11.1 MB，arm64，调试证书签，
覆盖安装不用先卸载），sha256 `bde019c7…`。桌面无代码改动，仍在 0.11.27。

## v0.11.28 — 悬浮条按归档原生版对齐（只有手机包）（2026-11-09）

主人问「悬浮条效果是否和 tickbar 一致」。这一版是逐文件比对后，把**掉队的四处**补齐。
桌面无代码改动，仍在 0.11.27。

### 对齐了什么

1. **倒计时不再少 1 秒**：改回向上取整（剩 4:59.5 显示 `05:00`），最后一秒不会挂着 `00:00`
   让人以为「是不是已经结束了」。
2. **满 1 小时补位**：`01:05:03`（原来 `1:05:03`）。
3. **结束有视觉落点了**：状态机结束后画 3 秒满圈绿环；暂停不再变灰
   （灰会让「暂停」和「本来就没计时」长得一样）。重新开始计时立刻撤掉绿环。
4. **通知栏三个按钮回来了**：计时中是 `暂停/继续` + `结束`，待机时是 `开始`。
   按钮**不直接改状态**——它把动作投给服务 → 服务投给前端 → 前端调 Rust；
   原生仍然一个字节都不写计时库。

### 动作链多了个「类型」

标记从「时间戳」升级成 `动作@时间戳`（`toggle` / `finish`），否则「点了结束但没人接」
会被当成交替执行，用户看到的是「我明明点了结束，它反而又跑起来了」。
0.11.27 留下的旧标记只读不写，升级后仍按「切换」补做一次。

### 没有变的

- **小圆点**：28dp 玻璃表盘，七层绘制与 8 个色值逐字节相同；
- **药丸几何**：高 32 / 内边距 9 / 环 16 圆角 5 / 宽度 64–240；
- **手势与节奏**：拖动 / 520ms 长按 / 短按三档，展开 3.5 秒，500ms 刷新 + 1Hz 闪烁；
- **药丸仍是透明底**（V0.11.10 的「透明背景、不透明文字」）。归档版是深色底 + 白边，
  这条**刻意没改回去**——它当初是照主人原话改的。

### 产物

覆盖安装不用先卸载），sha256 `9deeeab8…`。

## v0.11.27 — 设置页重排（桌面）+ 悬浮条接通（手机）（2026-11-09）

一版两件事。**桌面：设置页「数据管理」重排**（主人四条原话，见下）。
**手机：故障修复**——主界面在计时、悬浮条一直像待机；点悬浮条既不切换计时也不打开 App，
这一版两个方向都通了。

### 桌面 · 设置页四条

1. **「只用本地 / 本地 + 云端」通道选择器删了**——云端开不开，由每条通路自己的开关表达。
2. **所有设置默认折叠**，展开态不记忆；折叠态标题、一句说明、备份当条记录仍可见。
3. **云端同步加了开关**（与「启用 Markdown 同步」同形态）；开关管通路跑不跑，
   三档（关闭/定时/智能）管自动路径怎么跑。
4. **本地目录更名「本地同步」，与「云端同步」各自成块、各带开关与三档**。
   两条路可同开：一轮先本地镜像、后 WebDAV 推送，一条失败记自己的错、不挡另一条；
   调度链各自到点。

### 根因（一句话）

悬浮条的显示以前是**原生自己去读 `timing.db`**：读不到就落待机态，一行被吞掉的 warn 之后
什么都不说。点击是**原生投一个事件给 WebView**：WebView 已销毁时事件投进无底洞，
`hasListener` 照样返回 true，两端都不报错。**共同点不是算错，是失败不可见。**

### 这一版改了什么

1. **显示源换成「状态机推快照」**：Rust 在每次计时状态迁移时组装 `OverlaySnapshot` 推给
   Kotlin（`overlayPush`），落进 `Prefs` 后让服务立刻重画。冷启动再补推一次
   （前台服务可能比窗口活得久，记着上一个进程的那一帧）。
2. **读库退回兜底，并且会说话**：探路（`dataDir` / `data/` / `files/` / 一层子目录 /
   2 层内 `*.db`），必须**真有 `time_records` 表**才算命中；读不到把「试过哪些路径」
   写进通知副标题（`BigTextStyle`，长的能展开看全）。
3. **点击补兜底**：按下那刻先落一个时间戳标记（`pending_tap_at`），前端接到事件第一件事是
   清标记；没人接就留着，回前台（`visibilitychange` / `focus` / 挂载）补做一次，TTL 90 秒。
4. **打不开就说为什么**：`openApp()` 失败不再静默 `runCatching`，原因进通知副标题
   （部分 ROM 拦「后台拉 Activity」，这条以前是零信息的）。

### 红线

- **原生仍然一个字节都不写计时库**（`PillService` / `TimerReader` 里没有 `INSERT`/`UPDATE`/`execSQL`）；
- 契约 79 / 17 / 11 不动，无新错误码、无新迁移；
- 电脑端零改动（`app::overlay_push::push` 在桌面是空实现），只是跟版本号。

  调试证书签，覆盖安装不用先卸载），sha256 `666f343f…`。

## v0.11.26 — 修掉「连得上、存不进来」（2026-11-08）

**故障修复。** 手机同步报 `建不了云端落点目录 permission denied（os error 13）`；

## v0.11.25 — 修掉「手机点测试连接就闪退」（2026-11-08）

**故障修复。** 手机端 → 设置 → 「测试连接」→ App 当场消失；这一版不再消失。

### 根因（一句话）

验证 HTTPS 证书那一步在手机上会 panic。reqwest 0.13 的 `rustls-no-provider` 会拖
`rustls-platform-verifier`，而那个后端**在 Android 上必须先由 Kotlin 侧初始化 context**
（本项目没引那个 AAR），没初始化就 `expect(..)` panic；`release` 是 `panic = "abort"`，
进程当场被杀，连日志都写不出来。

桌面走 SChannel 不需要初始化，所以桌面正常；本地 WebDAV 用例打的是假 HTTP 服务端，
走不到证书校验——两个条件凑在一起，让这个洞从 0.11.21 藏到今天。

### 这一版改了什么

1. **根证书改成编译期内置**（`webpki-roots`）：无 JNI、无初始化动作、两端同一份根，
   「忘了初始化」这种失败模式从根上消失。
2. **拆掉三处 Client 里两个会 panic 的回退**：`Client::new()`（它内部就是 `build().expect(..)`）、
   `remove.rs` 那句 `expect("DELETE 专用 Client 必须带 Policy::none()")`（注释写着「不 panic」，
   代码却 panic）。现在构造失败如实回 `Err`，界面出红字。
3. 新增判据 `tests/md_webdav_tls.rs`：根证书非空 / Client 可建 / 依赖不许删 / 一条联网握手。

### 你会感觉到什么

- 手机点「测试连接」：三关逐步点亮，绿字或红字，**App 不再消失**；
- 手机「立即同步」「后台自动同步」：同一条通道，一起修好；
- 用自签证书的私有 WebDAV：**这版不认**（红字「证书校验失败」）。公网证书全部照常。

要不要做「导入自签 CA」，记在 `release` 之外的 `待决事项` 里等你。

## v0.11.24 — 异常退出恢复（2026-11-08）

**上次软件没正常关（强杀 / 断电），重启后弹的恢复框重做了：两条路都带数字，不用心算。**

### 这一版改了什么

1. **两个主按钮带具体时间**：`一直算到现在（13:40:12）`（关机那段也算工时）或
   `结束在 18:40（04:12:30）`（计到关机那一刻为止）。原来的复选框删了——它的意思已被两条路吸收。
2. **「按关闭时间」是真的按关闭时间**：结束时刻落在最后一次落盘那一刻（误差 ≤30 秒），
   不再按「现在」算。跨零点归关闭那一天。
3. **Esc = 按关闭时间结束**（原来是继续计时）：少算的时长重开一次就补回来，多算的要拆记录改，难的朝向留给少的那边。
4. **暂停中崩溃**：只有一个按钮`结束并保存（…）`，不显示也不编造关闭时刻。
5. **托盘「退出」接线**：退出时若有没结束的计时，先按关闭时间收尾保存，再做退出前的最后一轮同步。

## v0.11.21 — 手机端云端同步（2026-11-08）

**只动手机。** 桌面端一行代码没改，覆盖安装 0.11.20 那个包不会有任何变化。

手机上原来只有「同步开关 / 日记目录 / 立即同步」，云端那一套（地址、账号、应用密码、多久自动传）
**没有任何入口** —— 而程序内部早就能跑云端那一轮。这版补的就是那道门。

### 这一版改了什么

1. **新增「云端通道」块**：通道二选一（只用本地 / 本地 + 云端）、WebDAV 四字段、应用密码、
   测试连接、状态行。服务地址与远端目录预填坚果云默认值，只需要补账号与应用密码。
2. **自动同步三档**：关闭 / 定时（5–120 分钟）/ 智能（停手 5 分钟后一次，连续忙时 30 分钟兜底）。
   以前手机上不管选哪档都按 15 分钟跑，「关闭」是一句假承诺。
3. **测试连接分三关**：账号 → 目录 → 写入。红在哪关只说那一关，不甩状态码。
4. **状态行说实话**：密码存没存、今天传没传、欠几天、上次错在哪；填了一半没填全时只说一句
   「云端还没填全，暂时不会同步」，不叠「今天还没上传」。
5. **切通道不丢配置**：切回「只用本地」再切回来，地址 / 目录 / 账号 / 三档一个字节不改。

### 仍然不做

手机不删云端往期（删除不可撤销，交给电脑）；手机无备份查看与恢复；手机不支持「本地目录」云端通道。

## v0.11.20 — 桌面收尾版（2026-11-08）
2026-11-08 收尾版。**这一版不加功能**，四件事全是上一轮记账留下的债：两条「偶尔红一次」的测试、
包里的「出生证」、7 条没人用的样式、文档补齐。如果你从 0.11.19 升级，什么配置都不用动。

两种形态都在 `release/`：`Timing-0.11.20-portable.zip`（解压即用）与 `Timing-0.11.20-setup.exe`（安装版）。
校验和见 `SHA256SUMS-0.11.20.txt`；包是哪个 commit 编的，看 `BUILD-INFO-0.11.20.txt`（便携版解压后根目录里也有一份）。

## 这一版改了什么

### 1. 两条自动化测试不再偶发红

之前每次跑全量，有两条用例偶尔红、重跑就绿，每次都要人花时间分辨「真坏了还是假警报」：

- 前端那个是**时钟没钉死**：断言容差折算成时间只有 30ms，冷启动首跑轻松超过，于是看运气。
  现在时钟、逐帧、定时器全部由用例控制，容差反而收紧到微秒级。
- 后端那个是**影子目录清理残留**：上次被强杀留下的临时目录如果清不掉，测试会拿陈旧数据库残片
  做比对，得出与本次无关的结论。现在清不掉就明确跳过比对；残留审计也从「点名两个已知名字」
  改成「整根审计」，任何中间产物都逃不掉。这处顺手修掉了生产侧同样存在的静默风险。

### 2. 包里带「出生证」

以前装完包无法回答「这是哪个 commit 编的」——包里唯一的指纹是前端内容哈希，跟源码版本无关。
现在每个包都带 `BUILD-INFO.txt`（版本 / commit / 是否干净 / 构建时间 UTC / 构建档位），
便携版解压即见，安装版在 `release/` 同级有一份。报问题时拿着包就能倒推源码版本。

### 3. 设置页删掉 7 条没人用的样式

v0.11.19 删掉「数据迁移」卡后留下的空壳，界面一个像素没变。

### 4. 文档补齐

`CHANGELOG.md` 补齐 0.11.17 / 0.11.18 / 0.11.19 / 0.11.20 四段；本文件从 0.11.7 更新到这版。
