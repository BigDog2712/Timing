# 发布说明 · Timing v0.11.3

2026-11-05。这一版把上一轮列在 `待决事项.md` 里的五条全部落地。

## 这一版改了什么

### 1. 跨零点的记录会分成两条

晚上 23:40 开始、00:20 结束，以前整段算昨天，今天显示 0 分钟。现在**结束时按本地零点拆开**：

- 昨天 23:40–24:00 一条，今天 00:00–00:20 一条，各自出现在当天的日记里；
- 总时长不变（累计按墙钟占比分，余数归后一段）；
- 手动结束、倒计时到点、崩溃后「结束并保存」、切换事项四种收尾都走同一套。

历史记录不追溯拆分——改写老数据是破坏性操作。

### 2. 逾期待办删除：确认现状即符合

每 15 秒扫一次，计划时间早于今天 0 点、又没做完的待办一律软删（库里可追溯）。
应用没开就下次启动补。这条本轮没改代码，只补了文档。

### 3. Markdown 升为第一优先级

- **两边都改过时以 Markdown 为准**。以前比「谁最后写」，但文件时间戳会被 Obsidian 关窗补写、
  同步盘回写弄乱，偶尔把你手改的日记覆盖回去。现在只要你改了文件内容，就是文件说了算。
- **点「立即同步」会刷新所有窗口**。以前只把数据导进库，界面还得等下一轮轮询。
- 写入方向不变：文件没动、数据库动了 → 从数据库写进文件。

⚠️ **手机端目前还没有 Markdown 同步**：手机读写共享文件夹需要 Android 的目录授权（SAF），
和电脑端「填一个路径」不是同一套模型，得单独做一轮。现在电脑 ↔ 日记文件是通的，
手机 ↔ 日记文件还断着，手机上只用本地库。

### 4. 待办真的绑定事项（数据库版本 5）

- 新建待办时标题正好等于某个已有事项名 → 直接绑上；
- 开始计时时，有绑定就用绑定的事项；没有就按标题找/建，**并把结果记住**；
- 之后再改待办标题，归属不再变——不会因为改个名字就在统计里裂成两件事；
- 老数据不回填，第一次开始计时时自然绑上。

### 5. 同步降频：默认 15 分钟，可调

- 设置 → 同步新增「同步间隔」，默认 15 分钟，1 分钟到 24 小时随便填；
- 「立即同步」保留为主用法；
- 轮询任务每轮重读配置，改完不用重启；
- 顺带删掉每轮都要跑的三处数据库聚合查询。
