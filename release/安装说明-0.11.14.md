# Timing 0.11.14 安装说明

产物（都在 `D:\101-Workshop\261106-Timing\release\`）：

| 文件 | 体积 | 用途 |
|---|---|---|
| `Timing-0.11.14-portable.zip` | 3.6 MB | **推荐**。解压后覆盖现有 exe，数据原地不动 |
| `Timing-0.11.14-setup.exe` | 4.7 MB | NSIS 安装包（装到 `%LOCALAPPDATA%\Programs\Timing`） |
| `SHA256SUMS-0.11.14.txt` | — | 上面两个文件的校验和 |

数据备份已在 `D:\701-Backup\3-ForgeX\Timing-data-0.11.7-20261107\`（44 个文件，
`timing.db` 与原文件 md5 一致）。

---

## 方案 A（推荐）：便携覆盖，数据不动

现有安装在 `C:\Software\SmallTools\Timing\`，用的是便携形态（数据在 `<exe>\data`）。

1. **先退出 Timing**（任务栏图标 → 退出，不要只关窗口；它常驻托盘）。
2. 解压 `Timing-0.11.14-portable.zip`。
3. 把解压出来的 `Timing.exe` **单独**复制到
   `C:\Software\SmallTools\Timing\`，覆盖同名文件。
4. `data\` 与 `plugins\` **不要碰** —— zip 里这两个目录只是占位 README，覆盖它们没意义。
5. 启动。首次启动会跑迁移（`0005_v0113.sql`、`0006_v0113.sql` 及之前未跑过的），
   已确认全部是纯新增表/列，**没有 DROP / DELETE / TRUNCATE**。

覆盖后版本号可在「设置 → 关于」里看到 `0.11.14`。

## 方案 B：用 NSIS 安装包

双击 `Timing-0.11.14-setup.exe`，currentUser 模式装到
`%LOCALAPPDATA%\Programs\Timing\`。

⚠️ **注意**：Timing 的落点判定是「exe 同级目录可写 → 数据放 `<exe>\data`」。
`%LOCALAPPDATA%\Programs\Timing\` 是可写目录，所以新装出来的**数据根是空的**，
不会自动读你 `C:\Software\SmallTools\Timing\data` 里的现有数据。

若坚持用安装包且要沿用现有数据，装完后、首次启动前，把整个
`C:\Software\SmallTools\Timing\data\` 目录复制到
`%LOCALAPPDATA%\Programs\Timing\data\`。
（`timing.db`、`timing.db-wal`、`timing.db-shm` 三个要一起复制，WAL 未合并时缺一个会丢最近写入。）

## 装完验什么

`for-owner\待决事项.md` 的 v0.11.14 节有 6 条，三条不需要真机的最值得先点：

1. **恢复落点（O4）**：设置里关掉云端通道 → 备份页恢复一份 `folder__` 开头的备份
   → 应该看到**红字报错**说「云端通道没开启或没填完整」，而不是静默成功。
2. **测试连接（O8）**：填一个服务端对 GET 目录回 405 的 WebDAV（坚果云常见）
   → 应显示「地址与账号能通，但服务端不支持直接读目录（405）」且判定为通过。
3. **本地目录已上传（O3）**：云端通道选「本地目录」→ 同步一轮
   → 「今天已上传」应变成已上传；把目录改成不可写再同步 → 应回到未上传。

第 4/5/6 条（手机端）要真机，没有设备就跳过。

## 万一要回滚

1. 退出 Timing。
2. 把 `D:\701-Backup\3-ForgeX\Timing-data-0.11.7-20261107\` 里的内容
   整体复制回 `C:\Software\SmallTools\Timing\data\`（覆盖）。
3. 换回 0.11.7 的 `Timing.exe`（`release\archive\Timing_0.11.7_x64-setup.exe`
   里可提取，或你本地留有旧 exe）。

注意：迁移是单向的。0.11.14 跑过的库（schema 6）交给 0.11.7 的旧程序会读不了
新表，所以回滚**必须连数据一起回**，不能只换 exe。
