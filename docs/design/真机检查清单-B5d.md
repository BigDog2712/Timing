# Timing · B5c–B5d 真机检查清单

> **本清单对应批次 B5c–B5d**：B5c `7ece349`（把手绑定折入高级区 + 开机自启双开关合并）、B5c 修复 `d1f3c31`（折叠块丢样式 / 展开顺序）、B5d CSS `4cbb719`（样式按责任拆分 + 顶层卡片材质）、B5d-IA `d09ffe4`（最短记录时长搬入计时行为、定时导出提升为一行）、防复发注释 `356dbaf`（纯注释）。
> 配套规范：`docs/design/UI-REFACTOR-P2-体验规范.md` §3.1 / §5。
>
> 用法：启动桌面版 → 点药丸进主界面 → 打开「设置」。每条三行：**看什么 / 合格是什么样 / 不对的话大概查哪**。
> 这批改的都是"布局与外壳"，jsdom 不跑布局，所以以下每一条都必须**真机目视**，截图即可判断，不需要 devtools。
> 建议顺序：先做 4（悬浮条，不用开设置），再做 1→2→3→5→6（都在设置页里，从上往下滚一遍）。

## 1. 「把手绑定」折叠块 = 一张完整的卡

B5c 曾因令牌作用域失效而丢样式（没边框 / 圆角 0 / 内边距 0），B5d 补了 fallback 并加了顶层材质修饰类。**这是唯一没被自动化验证过的一环。**

- **前置**：设置 → 第 3 组「悬浮条与把手」→「把手绑定」块（默认收起）。
- **看什么**：它和下面那张「悬浮条外观」卡上下相邻时，**外框是否长得一样**。
- **合格**：
  - 四边都有 **1px 描边**（不是没有边框的一段裸内容）；
  - 四个角是**圆角 14px**，与「悬浮条外观」卡看起来一致（两张卡左边框上端应各有一段同样大小的弯）；
  - 底色与「悬浮条外观」卡**同一种底**（不是更浅 / 更浮的一层）；
  - 内容距卡片边缘 **20px**（窗口拉宽到 ≥768px 后变 **24px**），与旁边卡的内缩一致；
  - 标题「把手绑定」与下面内容之间约 **12px** 呼吸，标题本身不再额外缩进。
- **不对的话查**：`.data__block--standalone`（`activity/shell/styles/features/host/settings-data.css`：圆角 / 底色 / 内边距）与 `.data__block--standalone > .data__block-head { padding: 0 }`、`> .data__body { padding: 12px 0 0 }`。若又变成"没边框、圆角 0"，说明给宿主令牌加的 fallback 被改回去了。

## 2. 数据卡六块没被"卡中卡套卡"

B5d 改了它们共用的基础类 `.data__block`，这是回归点。

- **前置**：设置 → 第 4 组「数据与同步」→ 同步卡下面那六块折叠块。
- **合格**：它们**仍然是"卡里的小块"**——圆角 **10px**、内边距 **12px**、底色比外层卡**略高一层**，明显比外层卡"小一号"。**不能**变得和第 1 条里的卡一样大圆角 / 大内边距。
- **不对的话查**：顶层材质只应存在于 `.data__block--standalone` 这个修饰类上，基础类 `.data__block` 不能被改成卡片材质。

## 3. 「最短记录时长」搬进「计时行为 → 时间规则」之后的对齐

- **前置**：设置 → 第 1 组「计时行为」→「时间规则」组（组名以界面实际文案为准，早期草稿写的“记录规则”是错的）。组内现在应是三行：时间线合并间隔 / 空闲超时 / **最短记录时长**（第三行，仍在组内、不是新锚点）。
- **看什么 / 合格**：
  1. **外壳在**：第三行右侧应是一个 **26px 高、6px 圆角、浅底、1px 描边**的小控件，里面是数字 + 单位 `S`，数字区宽约 40px。**这条今天才第一次成立**：此前 `.num-field` 在分析窗用的全是宿主令牌（`--radius-sm` / `--bg-field` / `--line`），而分析窗一条都不引 `timing/styles/tokens/*`，所以那个输入框**一直是没边框、没底色、圆角 0** 的裸数字；本次搬行顺手补了 fallback，等于修掉一个肉眼可见的既有缺陷。**如果你在旧版本截图里见过一个“裸数字”，那不是设计，是缺陷。** 现在若还缺外壳，那是 fallback 被改回去了。
  2. **左标签对齐**：三行的标签文字**左边缘在同一条竖轴上**（窗口 ≥768px 时最明显）。
  3. **行高节奏**：三行之间的分隔线与上下留白**等距**；前两行因为带滑杆会比第三行高，这是正常的，但**留白本身不能一行宽一行窄**。
  4. **不挤**：数字 `300`（三位数）能完整显示、不贴边、不截断；单位 `S` 与数字之间有约 2px 空隙。
  5. **窄窗专项**（把窗口拉窄到 <768px）：前两行会变成"标签一行、滑杆一行"，第三行仍是"左标签右控件"。**如果这时第三行显得突兀 / 矮一截**，就是它该不该也改成堆叠的问题——记下来告诉 fe（规则在 `.settings-preference-row-responsive`，`features/settings.css`）。
- **不对的话查**：`.num-field` / `.num-field__input`（`features/host/settings-dialog.css`：高度 26px、内宽 40px、圆角 6px）与 `SettingsPreferenceRow` 是否 `stacked`。
- **顺手验四条行为**：清空后点别处 → **回退到原值、不写库**（不是 0、不报错弹窗）；填 `3` → 钳到 `5`；填 `400` → 钳到 `300`；填 `37` → **照存 37**（不强制 5 的倍数）。

## 4. 悬浮条 dot 态与把手（不用开设置，桌面直接看）

- **看什么**：把药丸收成 dot，鼠标移上去再按住左键；再移开看把手消失的速度。
- **合格**：
  1. **直径**：dot 是 **33px**（不是 32）——32 是条高 `--pill-h`。
  2. **hover 不放大**：鼠标移上去，dot **尺寸一点不变**（只出 tooltip 与一圈 1px 微亮）。
  3. **按下仍有反馈**：按住左键，dot 会**轻微缩到 0.94 倍**，松手弹回 —— 这个反馈是**保留**的，别当成 bug 报。
  4. **把手露出是即时的**：hover 药丸，把手立刻出现（淡入约 180ms，无延迟）。
  5. **把手收起有缓冲**：鼠标离开药丸后，把手**不会立刻消失**，会停约 **200ms** 再淡出（总长约 380ms）。判断方法：移开后心里数"一"，把手还在，就是对的。**如果一移开就没了**，是把延迟弄丢了。
- **不对的话查**：`timing/styles/dot.css`（33px / `:active` 0.94 / 无 `:hover` scale）与 `timing/styles/surfaces.css` 的 `.pill__handle svg` 显影矩阵（隐藏侧 `opacity 180ms` + `transition-delay 200ms`，露出侧 delay 归 0）。

## 5. 「定时导出」提升为数据组内的一行

- **前置**：设置 → 第 4 组「数据与同步」→「数据安全」卡 →「导出与导入」组。
- **合格**：
  1. **在组里**：应有 4 行，顺序为**数据导出 → 数据导入 → 定时导出 → 全额数据包**（读法：单次动作 → 定时动作 → 全量动作），都在同一组、同一列。
  2. **按钮同档**：定时导出右侧按钮与另三行**同一尺寸档（`compact`）**，高度、圆角、字重一致；不要出现一个明显更大的按钮。它的文案是**「配置」**（复用 `settings.webDavConfigure` 的**值**、键名是历史包袱——**键名撒谎但值没错**，已记 i18n 债，别当 bug 报）。
  3. **行高与分隔线**：与另三行等距、分隔线连续（不出现某一侧多一道线）。
  4. **入口唯一**：打开「数据导出」弹窗，**头部那个日历图标应已消失**（定时导出不该再从弹窗里进）。
- **顺手验一条语义**（容易做错）：在「数据导出」弹窗里把格式改成 CSV 但**不点导出**、直接关掉 → 再打开「定时导出」→ 它显示的格式应是**上次保存的偏好**，**不是**刚才临时改的 CSV。
- **不对的话查**：`SettingsDataExportGroup`（组内四行与 `size="compact"`）、导出弹窗头部的日历按钮应已删除、定时导出读取的是已保存的导出偏好（`readExportFormat()` / `readExportFields()`）。

## 6. 折叠块与导航的联动（顺手，30 秒）

- **前置**：设置页左侧导航。
- **合格**：
  1. 点「把手绑定」→ **块自动展开**，并且**滚到的位置能看见它的标题**（不是滚过去看到一片空白、也不是停偏一截）。
  2. 手动把块收起，再点一次导航 → **仍能展开**（不是"点一次开、再点没反应"）。
  3. 点别的组（如「数据与同步」）→ **不会**把「把手绑定」顺手展开。
  4. 用键盘：Tab 到左侧「把手绑定」→ 按 Enter → 与鼠标点一样展开并滚到位。
- **不对的话查**：`SettingsGroupNav.jump()` 的 `flushSync(requestFoldReveal)`（必须**先展开再测落点**）、`FoldBlock` 的 `id` 必须在块根节点而不是折叠体里。
