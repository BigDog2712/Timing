## 2. 组件契约（统一壳 / 尺寸栅格 / 最小尺寸）

### 2.1 统一壳：`ModuleShell` 扩权，不新造第二套

现有 `ModuleShell` 已经把「卡头 20 高 + 8 距 / 四态（loading·empty·error·ready）/ E2·E3 分层 / 骨架行高 = 真实行高」写死了一次。**新仪表盘的每张卡必须仍然是它**，只是加三个插槽：

| 新增 prop | 用途 | 约束 |
|---|---|---|
| `dragHandleProps` | 卡头左侧 6 点把手（`data-card-drag-handle`） | 只占卡头，不覆盖内容区；`touch-action: none` **只加在把手上** |
| `menu` | 卡头右侧 `⋯`：大/中/小 · 移除 · 恢复默认 | 与 `action` / `meta` 三选一（卡头 20 高锁死，塞两个会折行） |
| `density` | 按档位调行高（`--qp-row-*` 的档内取值） | **不新增字号**，字阶仍是既有 7 档 |

> 反例（明令禁止）：任何一张卡自绘卡头、自己写 `aria-busy`、自己判 `status === "loading"` 画骨架。
> 判据：`grep -rn "qp-card-head" src/features/dashboard/components/` 只允许命中 `ModuleShell.tsx`。

### 2.2 尺寸：列 × 档，只有离散值

- **宽度**：由所在列的 fr 与 `span` 决定，**组件不得传 px**。
  `span = 1`（单列）或 `2`（通栏）。通栏只在两列模式下有意义，是便利贴/趋势的常用档。
- **高度**：由 `tier ∈ {S, M, L}` 决定，取值只来自 `tiers.css` 的 `--qp-card-<id>-<tier>`。
- **列宽比**：3 个预设 `44:54`（默认，= 今天）/ `50:50` / `34:66`。不提供连续拖拽调宽（连续值会让四条数字列右缘验收失效）。

### 2.3 三档高度表（默认档必须逐像素等于现值）

| 卡 | S（小） | **M（中）= 今天** | L（大） | 短档（≤735.98px 高） |
|---|---|---|---|---|
| `focus` 专注窗口 | 3 条读数（环 ⌀120） | **264** | 8 条读数 | M → 232 |
| `items` 事项分布 | 4 行 | **284** | 9 行 | M → 244 |
| `apps` 应用排行 | Top 3 | **254**（Top 5 + footer） | Top 8 | M → 222 |
| `todos` 待办 | 3 行（含输入行） | **294**（输入行 + 5 行） | 8 行 | M → 254 |
| `notes` 便利贴 | **56**（1 行，通栏） | 120（2 行） | 184（3 行） | S → 52 |
| `trend` 应用趋势 | 140（火花线） | 220（趋势图） | 300（趋势图 + 区间控件） | M → 200 |
| `reminder` 提醒 | 150（下一条 + 3 条） | 230 | 310 | M → 210 |

落地纪律：S/M/L 的**具体 px 在落地时由「卡头 28 + 内容行数 × 行高 + 固定件（输入行 32 / footer 32 / compose 32）」实测推得并写进 `tiers.css`**；上表 M 列与短档 M 列是既有值，**不允许漂移 1px**（验收见 §7-P1）。

### 2.4 最小尺寸与溢出规则

| 项 | 规则 |
|---|---|
| 最小高 | = 该卡 S 档高度。`tier` 只提供离散值，因此天然守住下限 |
| 最小宽 | 单卡 `minmax(320px, …)`（既有声明）；两列在 900 档仍是 337.6 / 414.4，不破 |
| 列超出板高 | **该列内部滚动**（6px 滚动条，已有 token），**整页永不滚动** |
| 极端组合 | 7 卡全开 + 全 L 档 → 允许列内滚动；顶部出现在「添加组件」面板的提示：`该列已满，再放需要滚动` |

> 不变式（沿用 36 §三.7）：`document.documentElement.scrollHeight === clientHeight`，两档都成立。列内滚动是**允许**的，页滚动不是。

### 2.5 十条卡契约（能机械检查的写成判据）

| # | 条款 | 判据 |
|---|---|---|
| C1 | 壳唯一 | 上条 grep；`<section>` 卡根只出现在 `ModuleShell` |
| C2 | 尺寸离散 | `grep -rn "height:\s*[0-9]" src/features/dashboard/components/` 0 命中（只许 `var(--qp-card-*)`） |
| C3 | 最小尺寸 | 每卡 `tier=S` 渲染后 `offsetHeight >= 该卡 S 档 token` |
| C4 | 四态单一实现 | 全部走 `moduleState(status, refreshError, isEmpty)`，不得在卡内再判 `loading` |
| C5 | 刷新不闪 | 已有当天数据时刷新**不得**退回 `loading`（D-01 纪律，见 §6） |
| C6 | 组件不碰传输层 | L1 门禁：`components/` 下 0 个 `invoke(` / `ipc.` |
| C7 | 偏好进 `options` | 组件自身偏好只写 `layout.cards[].options`，不另开 localStorage key |
| C8 | 移除不改后台 | 移除卡片后：计时采集、提醒调度、日历刷新**照旧运行**（P3 前置重构，见 §5.2） |

## 3. 布局模型与持久化

### 3.1 三个候选（选 R1）

| # | 模型 | 默认几何 | 「可摆位」强度 | 成本 | 风险 |
|---|---|---|---|---|---|
| **R1（推荐）** | **双列轨道 + 列内卡序 + 跨列 + 三档高** | **零像素变化**（44fr:54fr、564 列高） | 列 × 序 × 跨列 | 中（全新约 400 行） | 低：所有破版组合都能枚举 |
| R2 | 自由摆位（绝对 x/y/w/h + 8px 吸附） | 需重算全部几何 | 强（任意位置、可重叠） | 高（碰撞/吸附/最小尺寸/904 档重排/坏数据处理，≈3–5×） | 高：空洞与重叠无解，破坏"恰好装满" |
| R3 | 12 列栅格（colSpan 1–12 + rowSpan） | **改**：1052 宽 12 列 gap16 → 1 列 73，5 列 = 429 / 7 列 = 607（今天 465.14/570.86，差 ±36） | 中强 | 中高 | 中：四条数字列右缘 443.14/548.86 立刻失效 |

**选 R1 的理由（三条，都可复核）**
1. 「两档恰好装满、无外层滚动」是 36 §三.7 的头号不变式，也是这轮最贵的验收值（443.14/548.86）。R2/R3 都要改它。
2. 用户要的三件事——**加卡 / 换位置 / 改档**——R1 全给；剩下没给的只有「像素级自由」和「卡叠卡」，这两件与"仪表盘"的语义相反（叠了看不清）。
3. 状态空间可枚举 = 可写判据 = 坏数据可自愈。R2 的非法状态是连续的。

> 若你要的是"任意位置、允许空洞"，那就是 R2，本方案 §4 的交互、§7 的验收、§10 的预算都要重写一遍（我会另出一份）。

### 3.2 数据形状

```ts
// src/features/dashboard/layout/contract.ts
export type ComponentId = "focus" | "items" | "apps" | "todos" | "notes" | "trend" | "reminder";
export type SizeTier = "S" | "M" | "L";
export type ColumnId = "c0" | "c1";
export type CardSpan = 1 | 2;

export interface CardInstance {
  id: ComponentId;          // 单实例：id === 组件类型（不做多实例，见 §9-6）
  col: ColumnId;
  order: number;            // 列内序：10 / 20 / 30…（稀疏，插入不重排全表）
  tier: SizeTier;
  span: CardSpan;
  grow: boolean;            // 是否吸收列内余量（默认：items 与 todos 为 true，即今天的 minmax(1fr)）
  options: Record<string, string | number | boolean>; // 组件参数：维度 / TopN / 区间 / 列数…
}

export interface DashboardLayout {
  version: 1;
  columns: Array<{ id: ColumnId; fr: number }>; // 默认 [{c0,44},{c1,54}]
  cards: CardInstance[];                        // 只存"已在板上"的卡；移除 = 删除条目
  updatedAt: number;
}
```

**默认布局（= 今天）**

```json
{
  "version": 1,
  "columns": [{ "id": "c0", "fr": 44 }, { "id": "c1", "fr": 54 }],
  "cards": [
    { "id": "focus", "col": "c0", "order": 10, "tier": "M", "span": 1, "grow": false, "options": { "dimension": "category" } },
    { "id": "items", "col": "c0", "order": 20, "tier": "M", "span": 1, "grow": true,  "options": {} },
    { "id": "apps",  "col": "c1", "order": 10, "tier": "M", "span": 1, "grow": false, "options": { "topN": 5 } },
    { "id": "todos", "col": "c1", "order": 20, "tier": "M", "span": 1, "grow": true,  "options": { "compose": true } },
    { "id": "notes", "col": "c0", "order": 30, "tier": "S", "span": 2, "grow": false, "options": { "columns": 3 } }
  ],
  "updatedAt": 0
}
```

> `grow` 是"今天 264 固定 + 事项吃余量"的显式化。列内高度算法：先按 tier 取高度，**余量全部给该列 `grow` 的那一张**；没有 `grow` 时给最后一张；不足则按 min-h 钳制后该列内部滚动。这正好复现 `grid-template-rows: 264px 284px`（事项 = 564−264−16）。

### 3.3 持久化落点

| 项 | 决定 | 理由 |
|---|---|---|
| 真源 | `localStorage["patina:dashboard-layout:v1"]` | 与仓库 4 处布局偏好同法；零契约、零 schema、零迁移；浏览器 mock 下同键可用（`browserStorageGateway` 已做降级） |
| 写入时机 | 变更后 **300ms 节流** + `pagehide` 强制 flush | 拖动过程中不能每帧写盘 |
| 读取时机 | 首帧同步读（localStorage 是同步 API）→ 无"先默认后跳变" | 避免二次 reflow 造成新的闪 |
| 坏数据 | 校验失败 → 用默认布局 + 立刻回写 + `console.warn` 一条 | **永不出现空板**；默认布局就是"今天"，最坏结果等于没自定义过 |
| 迁移 | `version` 只做 `v1 → normalize`；未来加字段进 `normalize()`，不写 `if version === 1` 分支散落 | 与 `useAppShellNavigation` 的旧值迁移同风格 |
| 为什么不落宿主 settings 表 | ① 布局宿主不消费；② `update_settings` 收 `AppSettings` 结构，加字段 = 改数据形状 + 迁移 + 契约评审；③ 现状 4 处布局偏好都在 localStorage，混用两个落点更糟 | 若将来要跨设备同步，把 `layoutStore` 换成宿主 KV 即可（端口只有 `load/save/reset` 3 个函数） |

### 3.4 校验与自愈（纯函数，可单测）

```
normalizeLayout(raw) →
  · 非对象 / 版本不认识 / cards 不是数组        → 默认布局
  · 未知 id、重复 id                            → 丢弃（重复保留首条）
  · col 不在 columns 里                         → 归到 c0
  · span=2 但只有 1 列                          → 降为 1
  · order 冲突 / 负数 / NaN                     → 稳定排序后重编号 10..N*10
  · tier 非法                                   → "M"
  · options 只保留该卡声明过的键（白名单）        → 多余键丢弃（防旧版本残留）
```

判据：`normalizeLayout.test.ts` 覆盖上表 8 条，**每条都有一个"故意写坏"的输入**；变异自证 = 删掉任一分支，对应用例必须红。

### 3.5 布局里**不存**什么（纪律）

不存颜色、不存 px 尺寸、不存字体、不存主题。理由：用户换主题 / 改 accent 后布局必须跟着走；存了颜色就等于在布局里埋一份"第二真源"，与 `deriveTheme` 的单一来源直接冲突。

## 4. 交互

### 4.1 添加

| 项 | 设计 |
|---|---|
| 入口 | 每列底部一个**空槽**（高 = S 档，虚线 `outline`，hover/focus 升 `--qp-border-strong`）+ 空板时居中的主按钮 |
| 面板 | 复用 `QuietDialog`：7 个组件，每行 = 名称 + 一句话 + 状态（`已添加` 置灰 / `添加`） |
| 落位 | 插到该列**末尾**，随即把焦点给新卡卡头（`aria-live` 播报「已添加：应用趋势，右列第 2 位」） |
| 面板底部 | `恢复默认布局`（二次确认，走 `QuietConfirmDialog`） |

### 4.2 移除

卡头 `⋯` → `移除`。**不弹确认**（可逆：组件库随时加回），`QuietToastStack` 给一条「已移除 应用趋势」。
判据：移除后 `layout.cards` 少一条、localStorage 已更新、**后台能力不受影响**（C8）。

### 4.3 拖动（pointer events，无新依赖）

```
pointerdown(handle)  → setPointerCapture + 阈值 4px（防误触点击卡头）
   ↓ 越过阈值
提卡（transform + z-index + 0.9 透明度）  目标列高亮（--qp-accent-muted）
   ↓ pointermove
算落点：指针所在列 + 该列各卡中线比较 → 插入位（2px 指示线，--qp-accent-default）
   ↓ pointerup / pointercancel / Esc
落位：applyLayoutChange()（唯一写入口）→ 300ms 节流落盘
```

- 拖动**只改** `col / order`（跨列时同时改这两项），绝不动数据、不动 tier。
- `pointercancel` 与 `Esc` 一律回滚（不落盘）。
- **不做**拖动动画（`transform` 可以有，`height/width` 动画被 `design-tokens.css:19` 明令禁止）。
- 落位后不重排整个列表 → 只用 `order` 重编号，避免整列 re-render（React key = `id`，稳定）。

### 4.4 档位与键盘

| 操作 | 鼠标 | 键盘 |
|---|---|---|
| 换序 | 拖动 | 卡头聚焦 + `Alt+↑/↓` |
| 换列 | 拖到另一列 | `Alt+←/→` |
| 切档 | `⋯` → 小/中/大 | `Shift+Alt+↑/↓` 循环（播报「已改为大」） |

## 6. 主界面「文字周期性闪烁」：结论与处置（P0）

### 6.1 主因：**每 2 秒一次**的 loading（算术可复核）

链条（每一跳都能在源码里指到行）：

```
releaseDefaultProfile.ts:76        refreshIntervalSecs = 2
useDashboardStats.ts:103-108       有活动会话 && tracker 健康 → setInterval(loadSnapshot, 2s)
useDashboardStats.ts:58-60  [修复前]  loadSnapshot 第一句：status = "loading"（无条件）
ModuleShell.tsx:39                 moduleState("loading", …) → "loading"
ModuleShell.tsx:119-123            "loading" → 渲染骨架条（4 张卡整块替换）
```

**结论：计时跑着的时候，主界面每 2 秒把四张卡换成骨架再换回来 —— 这就是"周期性"。**
另外 `tracking-data-changed`（每落一批会话 / 每次切前台应用）也会打一次 `syncTick++` → 同样退 `loading`，所以**不跑计时的时候也跟着操作闪**。

你的两个怀疑，第一条是**对的且是主因**；第二条（`--disable-gpu`）是**另一个候选**，但不是这条 2s 周期的成因（软渲染不会精确每 2s 闪一次）。

## 11. 一句话风险清单

1. **`AppShell.tsx` 374/374 冻结** —— 不先拆就不可能接新回调（这是全案唯一的硬堵点）。
2. **两个"事项"** —— 不先澄清，1 号卡会做出"名字对、数据错"的卡。
3. **移除卡 ≠ 关功能** —— 提醒调度不先上提，P3 会带着一个"静默失效"出包。
4. **`--disable-gpu` 与 0x8007139F 耦合** —— 别指望"只给分析窗开 GPU"；只改前端渲染（F1c）风险最低。
5. **默认布局必须逐像素等于今天** —— 一旦漂 1px，A 版精修 23 条验收里的几何项全废（443.14/548.86 是最贵的那两条）。
