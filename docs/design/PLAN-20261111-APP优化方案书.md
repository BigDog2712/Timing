# 方案书 · Timing APP 版优化（0.13.0 候选）

> 范围：**只做安卓 APP 版**。PC 端主界面与分析窗现在有另一条线在改（`ab2a8d4` / `38bcd94`），
> 本方案不碰它，避免两处同时动同一批文件。
> 写于 2026-11-11。这是**给你拍板的方案书**，不是已经动工的记录。

## 一、一句话

APP 版现在是「能用的记录器」，但要变成「愿意天天打开的东西」，还差三件事：
**看清楚（统计）、做得快（少点几下）、不出错（权限/后台/同步的失败要说得清）**。
本方案按这个顺序排，先补看得见的价值，再补手感，最后补稳定性。

## 二、现状（核过的事实）

| 项 | 事实 |
|---|---|
| 页签 | 五页：计时 / 事项 / 记录 / 便利贴 / 设置（`MobileShell` 的 `TABS` 驱动） |
| 页面体量 | 计时 162 · 记录 191 · 便利贴 205 · 设置 201 · 事项 281（行） |
| 统计能力 | **零**。全仓 `src/components/mobile/**` 里没有任何 `chart/Chart`，没有「本周用了多久」这类汇总 |
| 列表 | 记录页 / 便利贴页都没有虚拟化，直接全量渲染 |
| 悬浮条 | 原生自绘（`overlay/`：`PillService` / `PillView` / `PillDrag` / `PillGeometry` / `TimerReader`），已有手势语义与投递链路 |
| 权限 | INTERNET / POST_NOTIFICATIONS / SYSTEM_ALERT_WINDOW / FOREGROUND_SERVICE(+SPECIAL_USE)；**没有** `PACKAGE_USAGE_STATS` |

## 三、诊断：现在最痛的六条

### 1. 打开了不知道「今天过得怎么样」
没有统计页。用户在 APP 里只能看到「一条条记录」，看不到**排行、分类占比、和昨天比**。
PC 版有（Patina 分析窗），安卓没有 —— 这是两端体验差最大的一处。

### 2. 记录页越长越慢
`RecordsPage` 全量渲染。攒到几百条记录后滚动会掉帧（**未实测，按实现推断**：无虚拟化 + 每行自带日期格式化）。

### 3. 悬浮条命中区偏小
记忆里已记债：手柄命中宽 12px，低于 WCAG 建议的 24px。物理上 32px 条内三连排做不到，
但可以「扩大命中区而不改视觉」（透明热区向外扩 6px）。

### 4. 失败说不清
同步失败、浮条不开、权限被撤，这三类在手机上的文案都偏「系统调用失败，请重试」。
记忆里已经有教训：`IO_ERROR` 会把原文抹掉，同步页要直接显示 `err.message`。

### 5. 授权与权限的「状态」混着报
浮条已有 `enabled`（偏好）与 `permitted`（系统）分开的正确做法，但统计要新增的
`PACKAGE_USAGE_STATS` 是第三种状态，必须沿用同一套分报，不许混成一句「已开启」。

### 6. 五条待决口径压在手上
撤销条/命名面板打架等 5 条，都是「不定就做不下去」的交互决策，不是我该替他拍的。

## 四、分期（每期可独立出包）

### P0 · 看得清：应用使用统计（本轮主体，已单独出方案）

见 `docs/design/PLAN-20261111-安卓应用使用统计.md`。要点：
`UsageStatsManager` + `PACKAGE_USAGE_STATS` 特殊权限 → 按包聚合 → 落 `app_usage` 表（迁移 0008）
→ 新页签「统计」：今日排行 / 分类占比 / 昨日对比 / 7 天趋势。

**判据（摘要）**：未授权时**不许**显示 0 分钟排行（空态≠零数据）；与系统「数字健康」同段差 ≤ 60s；
锁屏 10 分钟不增时；迁移后五张老表行数逐表相等。

### P1 · 做得快：三处手感

| 项 | 做法 | 判据 |
|---|---|---|
| 记录页虚拟化 | 只渲染视口 ±1 屏（固定行高，无需测量） | 1000 条记录滚动 60fps（真机开发者工具，帧耗时 < 16.6ms） |
| 悬浮条命中区外扩 | 透明热区 +6px（视觉不动） | 12px → 24px；三种形态下点按不误触相邻槽 |
| 计时页一键直达 | 长按悬浮条进 App 时落在计时页（已实现）→ 补「最近 3 个事项」直选 | 从打开到开始计时 ≤ 2 次点击 |

### P2 · 不出错：状态与文案

| 项 | 做法 | 判据 |
|---|---|---|
| 三态分离 | 浮条/统计/同步各报 `偏好 · 系统权限 · 实际生效` 三行 | 分别撤销权限后，页面各自指出「哪一行不是绿的」 |
| 失败原文可见 | 同步/采集失败显示 `err.message`，不折成通用文案 | 断网同步一次，页面出现真实原因（含状态码或超时字样） |
| 补算与恢复 | 采集任务被杀 → 下次启动补算中断区间 | 中断 2 小时后启动，那 2 小时不计入任何应用 |

## 六、我的边界与纪律

- **只改 APP 侧**：`src/components/mobile/**`、`src/styles/mobile/**`、`src-tauri/gen/android/**`、
  以及为统计新增的 Rust mobile 命令与迁移。**不碰** `src/app/**`、`src/features/dashboard/**`
  （那条线正在改，`ab2a8d4` / `38bcd94`）。
- 一次只交一期；每期跑 `cargo check`（权限/迁移会在编译期炸，比装上去才发现好）+ `npm test` +
  `npm run check` + `node scripts/android-apk.mjs` 出包验证。
- **真机手感我替代不了**：滚动帧率、命中区手感、授权引导的观感必须你看一眼。我给的判据里会标清
  「我实测 / 我推算 / 待人工」。
- 契约与 schema 两条（②③）没点头之前，P0 只做到「原生侧采集 + 页面空态」，不写命令、不建表。

## 七、不做

- 不做跨端合并统计（与 PC 各自统计，避免口径混）。
- 不做「效率分」「专注度评分」这类把事实加工成结论的东西。
- 不采集应用内容/窗口标题（安卓也拿不到）。
- 不上传任何使用记录。
