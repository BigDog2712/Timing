## 3. 状态与交互

### 3.1 四状态视觉分层（核心 — 灰度可辨）

| 状态 | 名字 | 时间 | 时长 | 底 |
|---|---|---|---|---|
| **已完成** | `--ink-4` | `--ink-4` 等宽 11 | 等宽 11.5 + **删除线**（`text-decoration-color: --line-3`） | 无（hover `--todo-row-hover`） |
| **进行中**（当前） | `--ink` · 600 | `--ink-4` 等宽 11 | `--todo-time-current`（`--accent-ink`）等宽 11.5 | `--todo-row-current`（`--accent-wash` 14%）+ 左 3px `--todo-bar-current` 竖条 |
| **待办项** | 三级语气（见下） | 与计时行**同一列**（居中，等宽 11）：`remind_at ?? planned_at`，都没有则留白 | 右侧 12px 圆圈：黄 = 有提醒 / 空心 = 无（V0.3.11） | 分区，`--line` 分隔 |

> **状态不再有圆标记（V0.3.9 起）**：记录行与待办行左端都不画圆点／空圈。已完成的辨识靠**名字 `--ink-4` + 删除线**，进行中靠**底 + 竖条 + 名字提亮**；待办行的完成态同样只靠名字删除线（圆圈在**行尾**、且只表达「有没有提醒」，见 §3.6）。
> 四状态语义仍全部可达：**待进行** ＝ 待办区里 `planned_at` 在未来的「常规」语气行，由中间时刻列表达。

**待办项三级语气（不用图标也能分清）：**
- 进行中的待办：`--accent-ink` · 600 + 左 3px `--accent` 竖条。
- **逾期**：整行 `opacity: 0.62` + 名字一道 `--todo-overdue` 横线（V0.3.14 用户口径
  「透明度降低且有一条横线表示过期」；不再是「更红的红」—— 逾期是已经过去的语气，不是更醒目）。
- **未设时间**（两项都为空）：名字 `--todo-no-time`（`--ink-4`），时间列留白。
- 常规：`--ink-2`。

> **待办区显示全部未完成（ADR-034，取代 ADR-032 §1 的「只显示今天」）**：未完成待办**不做时间过滤**
> —— 今天 / 以后 / 已逾期 / 未排期都在「待办事项 · N」里；已完成只留**今天完成的**
> （已完成是逐日累积的历史，全量上百条会把 252px 面板占满，见 `lib/todoPanelLists.ts`）。
> 范围切分在 `lib/todoPanelLists.ts`，时间列文案在 `lib/todoTimeLabel.ts`，计数与空态都按新集合算。
> 右侧时间列因此按「与今天的关系」分级：逾期写「逾期」、未来写 `MM-DD`（跨年 `YY-MM-DD`）、
> 今天写 `HH:MM`、没设时间留白；完整时间（`YYYY-MM-DD HH:MM`）放在 `title` 里 hover 可查。

> **为什么当前行底从 45% alpha 降到 14%**：原来是 `rgba(accent, .45)` 叠在半透玻璃上 —— 三层 alpha 相乘，最终亮度不可控。改为固定 `--accent-wash` 后，「底 + 竖条 + 名字提亮」三处共同表达「这是当前行」，比单靠一块高亮底更稳、也更清楚（Timing §4.4 理由）。
> **待办行的时间列与计时行同格式（V0.3.11）**：用户口径「显示格式应该和计时一样，没指定时间就右侧空白，有开始时间的就按开始显示」。所以右列就是**一格等宽时刻**（`.todo-pend__time`，同 `.todo-row__time` 的字号/字形/`--ink-4`）：
> - `remind_at` 有值 → 显示它（开始时间优先）；
> - 只有 `planned_at` → 显示截止时刻；
> - 两者皆无 → **留白**（不再写「未设时间」）；
> - 粒度（ADR-034）：逾期 → `逾期`；不在今天 → `MM-DD`（跨年 `YY-MM-DD`）；在今天 → `HH:MM`；
>   完整时间 `YYYY-MM-DD HH:MM` 放 `title`；
> - 逾期时这一格与名字一起走 `--todo-overdue`。
> 胶囊、铃铛、「已逾期 / 未设时间」措辞都取消了 —— 铃铛只剩「今日计时」记录行还挂（那里表达的是 `items.remind_at`）。
> **时间怎么改**：只读态是读数，改要走底栏「编辑事项」（见 §3.4.2）；此前 `remind_at` 写进去后**没有任何地方显示**，用户据此报「待办时间写不进去」——现在它在右列可见。
> **可达性提示（AC-54 复验，V0.3.10 已解除）**：`planned_at` / `remind_at` 现在有两条录入入口（新增待办卡的开启 / 截止字段、行内改时间，见 §3.4.2），不再需要手工造数据。

### 3.4 键盘路径

`↑↓` 在记录/待办行间移动；待办行上：`Space` 完成/取消完成（= 点圆圈）、`R` 开关提醒（= 点整行）、`Enter` 改名、`Delete` 直接删除 + 底部撤销条（3s 可撤销，**不弹阻塞式确认对话框**）；编辑模式下的记录行：`Enter` 改名、`Delete` 走删除确认条；`Tab` 到底栏按钮；`Esc` 关窗。

**新增待办卡（`ComposeCard`）**：底栏「＋新增待办」就地展开一张卡（**不走悬浮框**，与「新增常用摸鱼 / 常用事项」同构），三个字段 —— 名称（必填）、开启时间、截止时间（后两项**可留空**；留空即不写 `remind_at` / `planned_at`），底部「取消 / 添加」+ 右上 `x` 关闭。卡内 `Enter` 提交、`Esc` 只收起卡片（不连窗一起关），`↑↓` 在卡内字段间移动不抢焦点。校验：提交时若截止早于开启，inline 报「截止时间不能早于开启时间」且不落库。

> **两次时间字段的映射**（易混）：**截止 → `todos.planned_at`**（逾期判定与中间时刻列的兜底值都用它）；**开启 → `todos.remind_at`**（到点提醒；也是待办行时刻列的**首选**，V0.3.11 起行上不再挂铃铛）。

#### 3.4.1 时间字段 = 自绘选择器（不是原生 `datetime-local`）

原生 `<input type="datetime-local">` 是 Chromium 的原生面板：既不能在面板里加「x 天后」，也无法把小时切成上午 / 下午（中文环境固定 24 小时制）。因此两个时间字段换成 `DateTimeField` + `DateTimePicker`：

| 项 | 规格 |
|---|---|
| 字段读数 | 有值：`今天 21:30` / `明天 09:00` / `10月22日 19:45` / 跨年 `2027年1月3日 07:00`（**24 小时制**，与「今日计时」行同一口径）；无值：灰字 `今天（未设）` |
| 默认值 | 打开时停在**今天** + 下一个 5 分钟档（`defaultPickerValue`），但**不落值** —— 没点过就仍是空 |
| 日历 | 周一起首、补齐前后整周（4~6 行）；「今天」一圈 `--line-3` 内描边；选中 = `--accent-wash` 底 + `--accent-line` 内描边 + `--accent-ink` 字（**不做实心蓝块**：白压蓝仅 2.45:1，见 app.css `.btn--primary` 注释）；‹ › 翻月只换视图、不改值 |
| 相对提示 | 日历**下方**一行「今天 / N 天后 / N 天前」（用户口径），右侧「清除」置空并收起 |
| 时间 | `上午 / 下午` 分段 + 小时（1–12）+ 分钟（**00/05/…/55 共 12 档**）；改任一项立即生效 |
| 位置 | `position: fixed` + `createPortal(body)`，宽 = 卡片宽（234），**横向右对齐卡片右沿**、纵向优先贴**卡片**上/下（贴字段会盖住标题输入框）；视口不够时翻边并夹取 |
| 收放 | 点字段开合；点浮层外 / `Esc` 只收起浮层（`Esc` 在 document 捕获阶段拦下，不再冒到卡片和窗口）；「清除」清值并收起 |
| 互斥 | 开「截止」时点「开启」会先收前一个（按**元素身份**判断，不是按 `.dt-field` 类） |

**纯逻辑在 `lib/datetime.ts`**：`ceilToStep` / `dayDiff` / `relativeDayLabel` / `formatFieldLabel` / `to12h` / `to24h` / `withTimeOfDay` / `monthGrid` / `shiftMonth`；浮层几何在 `lib/pickerBox.ts`（`pickerBox`）。两者都有单测（`datetime.test.ts` 16 条）。

#### 3.4.2 行内「点哪改哪」＝就地打字（V0.3.10 起，V0.3.13 改成打字）

底栏「编辑事项」= 行内编辑模式，**两节都进**（V0.3.11「编辑事项功能应也能修改计时的事项」）。
打开后再点一次「编辑事项」退出。编辑方式是**直接在该行原地打字**（V0.3.13 用户口径：
「点击一个事项名，随后可以删除、写下其他名字，点击某一事项的开始时间，输入新的时间即可」）：

| 点击面 | 行为 | 说明 |
|---|---|---|
| 名称 | 名字本身变成输入框（`InlineText`）：`Enter` 提交、`Esc` 取消、**失焦也算提交** | 不再弹「编辑条 + 确定 / 取消」；自动全选，点一下就能整段改写 |
| 开启时间位 | 名字右侧的等宽文字位变成输入框，改 `remind_at` | 预填 `09:00`（今天）/ `10-21 09:00`（跨天），未设时是虚线「+」 |
| 截止时间位 | 同上，改 `planned_at` | 逾期语气与圈色随之即时更新 |
| 行尾 `trash` | 待办：直接乐观删除（AC-32，撤销条兜底）；计时行：内联确认条 | 与 V0.3.11 一致 |

- **时间靠手打**（`lib/timeInput.ts`）：`09:00` / `明天 09:00` / `10-21 09:00` / `2026-10-21 09:00`；
  全角数字与全角冒号先归一。只给时刻时**按今天算**（面板本来就是今天的时间线）。
  解析不了就报错、**保持编辑态**，不吞掉用户打的字。
- **记录行同样可改起止时刻**（V0.3.12）：开始 / 结束各一枚定宽输入位，落库走 `update_record`；
  本地先挡「结束早于开始 / 开始晚于结束」，落库失败写进面板错误行。
- **清空即置空**：待办的两项时间都可以清空（`todo_update` 的 `double_option` → SQL `NULL`）；
  计时记录的时刻不可清空（浮层里清空 = 不改）。
- **校验与新增卡同一条**：提交时若 `planned_at < remind_at` → 报「截止时间不能早于开启时间」且不落库，
  输入框留在原地等改写。`lib/todoTimes.ts` 的 `todoTimePatch` 仍负责这条判定（7 条单测）。
- **键位全部 `stopPropagation`**：行上的 Space / Enter / R / Delete、面板的 Esc 关窗都不会在打字时误触发。
- **日历浮层只剩「新增待办卡」在用**（`DateTimeField` + `DateTimePicker`）：新增时挑时间仍比手打方便，
  编辑既有值时手打更快，两种入口分工明确。

### 3.5 便利贴预览（V0.3.9）

| 项 | 值 |
|---|---|
| 触发 | 鼠标悬停「今日计时」记录行（`TodosRecordRow.onHoverStart` 接 `useNotePreview.hoverStart`）；160ms 防抖 |
| 取哪张 | 该事项的所有便利贴中 `updated_at` 最新的一张（`useNotePreview.noteOf(itemId)`） |
| 空态 | 事项有便利贴但内容为空 → 卡内显示「（空白便利贴）」；**无便利贴 → 不弹卡** |
| 尺寸 | 宽 224（`NOTE_PREVIEW_W`），高自适应，最大 264（`NOTE_PREVIEW_MAX_H`，超出卡内滚动） |
| 位置 | 落在窗口左侧 240 透明预览区内，纵向跟随悬停行并夹在视口内；`position: fixed` + `createPortal(body)` |
| 关闭 | 移出 160ms 后收起；鼠标移入预览卡则保持（`keepOpen`）；窗口失焦立即收起（`closeNow`） |

### 3.6 提醒圆圈与「列对齐」（V0.3.11）

用户五条口径把这一页的行语义重排了一次：

| # | 口径 | 落地 |
|---|---|---|
| 1 | 待办时间显示在「开始时间」列 | 两节共用同一套三列网格 `minmax(0,1fr) auto minmax(0,1fr)`（名字 / 时间 / 右侧），时间列 `text-align: center`。因为两侧 1fr 等分，中列**必然**落在行的水平中线上 —— headless Chrome 实测两节时间列中心都是 `x=388`，与内容宽度无关 |
| 2 | 编辑事项也要能改计时的事项 | 打开「编辑事项」后，记录行名字变改名按钮（点它就地改名）、行尾出现删除（→ 内联确认条）。记录挂的是**事项**，删的是事项本身，所以保留二次确认，不像待办那样即时删除；编辑态隐藏「时长」列腾出名字宽度（四列时名字只剩 25px，实测） |
| 3 | 进行中的按时间排在计时最后 | `TodosRecords` 先渲染已保存分组（开始时间升序），再把进行中的会话放最末 —— 它是最后开始的那条，时间序上本就在末尾 |
| 4 | 今日计时与待办事项的统计格式统一 | 表头 `今日计时 · N`（去掉「条」），与 `待办事项 · N` 同格式；右侧总时长保留 |
| 5 | 单击待办 = 是否提醒；提醒放在总时间那列；黄圈=有、无色=无 | 行尾 12px 圆圈（`.todo-pend__mark`）落在第三列、贴右沿，正好在表头「X 小时 Y 分」下面（实测右沿同为 `497`）。`data-on` 只跟 `remind_at` 走 |

**点击语义（V0.3.11 起，注意与 V0.3.9～V0.3.10 不同）：**

| 点哪里 | 做什么 |
|---|---|
| 待办行（圆圈以外） | **开关提醒**：有 `remind_at` → 清空；没有但 `planned_at` 有值 → 借用它作为提醒时刻；两个时间都没有 → 当场弹 `DateTimePicker` 选一个（否则「打开提醒」没有时刻可依据） |
| 行尾圆圈 | **完成 / 未完成**（`role="checkbox"`）；`stopPropagation`，不会顺带改提醒 |
| 已完成的待办 | 点整行不再改提醒（提醒只管未完成的行），点圆圈仍可取消完成 |

> **提醒为什么借用 `planned_at`**：`remind_at` 是「到点提醒」这一个绝对时刻，用户点一下时没有别的输入，用这条待办自己的截止时刻是最不意外的选择；想改到别的时刻就走「编辑事项」里的时间位，或先清空 `planned_at` 让点击退回选择器。
> **圆圈同时承担完成开关这件事**（用户口径「完成改由圆圈承担」）意味着它的位置固定为「总时间列」，但**颜色只表达提醒**；完成态继续由名字删除线表达，避免一个标记又要表达两种状态。

### 3.7 提醒链路：T-15 轻提醒 / T-5 自动开始 / 到点自动开始（V0.3.12）

用户口径补齐了「黄圈到底提醒什么」：**不是**在开始那一刻响，而是**开始前 15 分钟**问问
「要不要改时间」——所以它叫**轻提醒**，专门给「时间只是大概」的待办用。两级提醒都以
`remind_at`（= 开始时间）为基准，黄圈 `data-on` 恒等于「有开始时间 ⇒ 这条链路是通的」。

| 时刻 | 弹什么 | 动作 |
|---|---|---|
| `remind_at − 15min` | 轻提醒卡：「15 分钟后开始 · HH:MM，要不要改时间？」 | **推迟 15 分钟 / 推迟 1 小时 / 推到明天此刻**（整体平移 `remind_at`）、**不用改** |
| `remind_at − 5min` | 自动开始卡：「HH:MM 开始 · 当前计时结束后自动开始？」 | **结束后自动开始**（写 `auto_start=1`）、**现在就开始**（`todo_start`） |
| `remind_at` 到点且当前空闲 | 不再弹 —— 直接开始计时 | 该待办**立即移出待办区**，计时区出现进行中的那行 |

- 弹卡复用既有的提醒浮出卡（同一位置、同一套玻璃样式，`mode: 'nudge'`），三张卡不会同时出现。
- 两级各自只弹一次（`todos.remind_stage` 0→1→2，只升不降）；**改开始时间会把阶段归零**，
  于是「推迟 15 分钟」之后还会按新时刻再问一次。
- **关机一夜不会补弹**：`remind_at + 10 分钟` 之后仍未处理的待办会被静默标成已处理
  （并撤回 `auto_start`）—— 不补弹、也不在启动瞬间自己起计时。
- 「结束后自动开始」写在 `todos.auto_start` 上，本次会话结束（`timer_stop`）时由后端顶上，
  长会话跑完也算；重启后未被处理的应允会被过期逻辑撤回。
- 待办不再进通用「到点提醒」：`reminder-fired` 只管事项，待办走 `todo-nudge`。

**编辑事项还能改计时行的时间（V0.3.12）**：计时行在编辑态下，两段时刻变成两枚可点的时间位
（同 `DateTimePicker`），落库走既有 `update_record`；改时刻后**时长跟着区间走**，
只改备注 / 事项名时保留原累计。合并行（同名多条）改的是**组内最早开始**与**最晚结束**那两条记录。

### 3.8 点记录行 = 开始计时 + 按连续性分行（V0.4.2）

用户口径三句话，落在这一页的两处：

1. **「在事项菜单点击事项可以直接开始计时」**——记录行（今日计时，`status="done"`）整行可点，
   `Enter` 等价点击。口径统一在 `useTimerActions.startOrSwitch`：
   空闲 → 开新会话；正在计**别的**事项 → 先暂停冻结累计再分段（`switch_item(end_and_start)`
   的后端守卫不接受运行中的会话，见契约 §4.2）；点的就是**当前这条** → 跑着不动、暂停着继续。
   行内命中按钮 / 输入框时不算点行；**编辑模式下整行不可点**（那里的点击是改名 / 输时间）。
   右键菜单同理：非当前会话的首项从「停止计时」（原来恒禁用）换成「开始计时 · {事项}」。
2. **「同一事项若时间不连续，则分行记录，若时间连续则合并记录」**——`lib/todayGroups.ts`
   在「按事项 id 分组」之上再按连续性切分：同事项按开始时间升序扫描，相邻两条间隔
   ≤ `CONTIGUOUS_GAP_MS`（60s）才并进同一行，否则另起一行。行 key 随之改成
   `grp-{itemId}-{firstId}`（旧的 `grp-{name}` 在拆分后必然撞 key）。上行「上一条没结束时间」
   无法判断连续，直接另起一行。
3. 时间口径不变：合并后仍是**时长求和 + 最晚结束**，不按区间长度反推（应用关着不计时）。

## 7. 与架构的交叉点（已裁定）

- **窗口**：独立窗口，**固定 label `todos`**（`open_todos_window`）；面板宽 252，窗口另含左侧 240 透明预览区（便利贴悬停预览，V0.3.9 起；原 336），高自适应（超出滚动）。
- **窗口定位**：`PanelPlacement::BelowMainInset(240)` —— 锚在主机窗正下方再左移 240，使可见的 252 面板仍与主窗左对齐（透明预览区探到主窗左侧）。
- **便利贴预览（§3.5）**：`useNotePreview` 状态机（`listNotes()` 一次缓存 → 按 `itemId` 取最近更新的一条；`hoverStart` / `hoverEnd` 带 160ms 延迟，鼠标可移入预览卡不消失；缓存未命中时按 `itemId` 补拉）；`NotePreview` 用 `createPortal` 挂 `body`、`position: fixed`，几何由 `lib/notePreview.ts` 的 `notePreviewBox(anchorTop, viewportH)` 算出（宽 224、高 ≤264，纵向夹在视口内）。悬停到**无便利贴的事项不弹**。
- **便利贴默认绑定事项**：`noteActions.currentItemId()` 取当前事项（`lastItemId`），空闲态点「写一张新的…」即直接落在当前事项上；只有显式传 `null` 才是「随记」（不绑事项）。
- **便利贴启动不自动重开**：`bootstrap` 第 ⑨ 步由原来的 `jobs::restore_notes::restore_open` 改为 `services::note::reset_open`（`UPDATE notes SET is_open = 0`）—— 上次退出时开着的便利贴**不再**在下次启动时被重新拉起（用户口径），`jobs/restore_notes.rs` 已删除。
- **几何持久化**：**不入库** —— 由 **`tauri-plugin-window-state` 按 label 自动维护**位置/尺寸。**本页无 `pos_x`/`monitor_id` 等 DB 几何字段**。
- **主题同步**：本窗**自订阅 `theme-changed`**。
