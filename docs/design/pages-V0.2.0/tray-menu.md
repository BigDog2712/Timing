# 页面：托盘菜单 TrayMenu（V0.2.0 · 改造）

> 覆盖对象：`DESIGN-V0.2.0.md` + `design-tokens-V0.2.0.{json,css}`
> 本文件只写**本页规格**与**差异字段**。
> 触发：系统托盘图标右键 | 主题：**由系统决定**（不随应用 `data-theme`）| 层：**OS 原生**
> 来源：对齐 Timing §4.5 `TrayApp` 托盘菜单的**信息架构**
> V0.2.0 改造：**保留系统原生 Win32 菜单（不自绘）** —— 只重排**信息架构**（分组 / 分隔线 / 启用·禁用 / 勾选 / 快捷键标注 / 项文案）；控制组**按状态裁剪（方案 Ⅰ 定案）**；顶部加**一条禁用文本项**承载状态（状态块降级取 B）。
> 注意 **实现路径见 §7（架构已裁定：原生，非方案 B）**
>
> **形态边界（本页最重要的一条）**：托盘菜单是 **Win32 `HMENU` + `TrackPopupMenu`**，外观（底、圆角、阴影、文字色、行高、玻璃、状态块）**全部由操作系统主题决定，我们无法控制一个字**。因此本页**只规定「有什么、怎么分组、何时可点、何时打勾」**，删去一切绘制规格。
> 需要玻璃外观的菜单 → 见 `context-menu.md`（应用内自绘）。

### 1.2 右侧信息位（原生 `accelerator` 槽）

原生菜单行右侧有一个**右对齐、系统灰字**的 accelerator 文本槽（默认显示快捷键）。本设计**借用该槽承载信息位**（条数 / 日期），这是原生菜单唯一可承载「辅助信息」的位置：

- `今日计时` → `4 条`（空态可不显示或显示 `0 条`）
- `排到别的日期…` → `10-13`（当前视图日期）

> 限制：该槽**字体、颜色、对齐全部系统决定**，不能换等宽字体、不能改色。仅作为「有/无信息」使用，不做视觉设计。

### 1.3 条件项（务必保留）

- **`Timer 窗口（只读大窗）`**：仅当 **`timer-window` 插件开启**时出现。V0.2.0 插件缓做 v0.3 → **本期恒不存在**。行模型须在**构建时**按 `pluginConfig.GetEnabled('timer-window')` 决定是否 `append`（不是打开后删除）。
- 原生菜单**宽度由系统按最长项自算**，无需（也无法）指定 272px。`--tray-w` 因此**退役**（见 §4）。

### 1.4 默认项（原生 `SetMenuDefaultItem`）

Win32 支持把某项设为**默认项**（渲染为**粗体**，回车/双击托盘执行）。可用于：

- **空闲态** → `开始正计时` 设为默认项；**计时中/暂停中** → `结束并写入事项计时` 设为默认项。

> 这是原生给出的、替代「状态块强调」的**可选**强调手段（配合 §3.3 的顶部状态行，二者可并存）。**非必需**，不强制启用。

### 1.5 原生菜单的**做不到清单**（设计必须让步的部分）

| 想要的效果（自绘版有） | 原生菜单 | 处理 |
|---|---|---|
| 玻璃底 / 圆角 / 阴影 | **无** | 交系统 |
| 行高 30 / 内边距 9 / 图标色 | **无** | 交系统 |
| **状态块**（`事项名 12:34` 顶栏） | **无**（不能画彩色圆点/等宽/SVG） | **降级取 B：顶部一条禁用文本项（纯文本）**（文案规范见 §3.3） |
| **危险色**（退出 / 放弃 红字） | **无**（系统不支持 per-item 前景色） | 语义改由**文案 + 分隔线 + 末位**承载；见 §3.4 |
| 分组**标题文字**（"视图"/"打开"） | **无** | 用分隔线代替 |
| 圆形强调 / 悬停高亮自定义 | **无**（系统 hover） | 交系统 |
| 应用主题（深/浅） | **无**（跟随 OS 明暗，不跟应用 `data-theme`） | 记为 **K-29**（架构 §9；见 §7） |
| 逐项 SVG 图标（lucide） | 仅支持**位图 `HICON`（约 16px）**，不支持 SVG | 默认**不带图标**（系统托盘菜单惯例）；若要图标须 Rust 侧预栅格化，见 §5 |

## 2. 构建模型（每次打开时构建）

原生菜单**不能常驻自绘组件**，改为**打开即构建**：

```
on_tray_icon_event(RightClick)
  └─ MenuBuilder::new()               // 每次右键重建
       ├─ read app_state (空闲 / 正计时 / 倒计时 / 暂停)
       ├─ read current_view (今日 / 其他日期)
       ├─ read plugin_config(timer-window)
       ├─ append 状态行（禁用文本项，§3.3）
       ├─ append separator
       └─ append 控制组项 ── 按状态裁剪（方案 Ⅰ，见 §3.1）
          append separator → 视图组
          append separator → 打开组
          append separator → 系统组
          append separator → 退出
       └─ set_enabled / set_checked / set_default 逐项
  └─ menu.popup_at_cursor()            // 系统接管弹出与关闭
```

- **状态实时性**：每次右键都重新读状态 → 不会再出现「菜单开着状态变了」的脏数据。
- **刷新策略（硬约束）**：菜单结构**仅在状态迁移时重建**；秒级时间用 `set_text` 原地更新、**不每 tick 重建**；状态文本 = **展开瞬间快照**（见 §3.3.2）。
- **无前端参与**：构建、弹出、定位、键盘（`↑↓ / Enter / Esc / ←→`）、失焦关闭**全部由 OS 完成**，前端**零代码**。
- 事件回传：各项点击走 Tauri `MenuEvent` → `invoke` handler（沿用 `src/services/ipc.ts`）。

## 3. 状态与启用语义

### 3.1 状态 → 控制组（**定案：方案 Ⅰ 按状态裁剪**）

托盘菜单原状为 16 项平铺 + 6 分隔线，空闲时「暂停/继续/结束/放弃」全灰。**V0.2.0 定案用方案 Ⅰ：按当前状态只 `append` 可用项**（不生成不可用项，而非生成后灰置）。

| 应用状态 | 状态行（§3.3） | 控制组**实际出现**的项 | 可点项数 |
|---|---|---|---|
| **空闲** | `空闲 · 点开始正计时` | `开始正计时` | 1 |
| **正计时中** | `摸鱼 · 12:34` | `暂停` · `结束并写入事项计时` · `放弃（不记录）` | 3 |
| **倒计时中** | `摸鱼 · 倒计时 剩 07:26` | `暂停` · `结束并写入事项计时` · `放弃（不记录）` | 3 |
| **暂停中** | `摸鱼 · 已暂停 12:34` | `继续` · `结束并写入事项计时` · `放弃（不记录）` | 3 |

**裁剪后的常态结构（不含顶部状态行与分隔线）**

| 分组 | 项 | 项数 |
|---|---|---|
| 状态行 | 1 条**禁用**文本项（§3.3） | 1 |
| 控制组 | 按上表（空闲 1 / 计时 3） | 1–3 |
| 视图组 | `今日计时` · `排到别的日期…` · `回到今天`（仅非今日）· `编辑固定任务…` | 3–4 |
| 打开组 | `今日日记` · `数据文件夹` · `配置文件` | 3 |
| 系统组 | `设置…` · `关于…`（+ `Timer 窗口…` 仅插件开启） | 2（+0–1） |
| 退出 | `退出` | 1 |
| **合计可点项** | | **空闲 ≈10 / 计时·暂停 ≈12** |

> **常态（空闲）≈10 项可点 + 1 条状态行 + 5 分隔线 ≈ 16 行菜单**；计时/暂停态 ≈12 项可点。已达成「约 8–10 项」的常态目标（空闲态），且**彻底摆脱「一半是灰的」**（因不可用项根本不生成）。
> **代价（已接受）**：项位置随状态变，**肌肉记忆失效** —— 属方案 Ⅰ 的固有取舍，用户已确认接受。
>
> **方案 Ⅱ（全量 16 项 + 原生自动灰置）—— 未采纳**：保留项位置恒定、肌肉记忆稳，但空闲时「一半是灰的」回归（Timing §6.5 视为反模式）。**本页停用，仅作备案记录。**

### 3.2 勾选（原生 `CheckMenuItem`）

- `今日计时`：当前视图 = 今日 → `set_checked(true)`（左侧系统勾）。
- 勾选语义仅用于**互斥的当前态**，不用于开关项（本菜单无开关项）。

### 3.3 状态块降级（**定案：取方案 B — 顶部一条禁用文本项 · 纯文本**）

自绘版的顶部状态块（`事项名 + SVG 圆点 + 12:34` / `倒计时 · 剩 07:26`）在原生菜单中**无对应物**。**兜底取方案 B：在菜单顶部插一条恒定存在、恒定禁用的文本项**承载同一信息。它**不可点**（`set_enabled(false)`），仅作只读状态显示。

> **P0 裁定（纯文本，无任何字符符号）**：原生菜单**无法携带我们锁定的 lucide SVG**，而 P0 要求功能图标必须是统一描边的 SVG 方案 → 状态项**一律不加圆点/符号前缀**（`●` U+25CF 等字符符号**全部不用**，从紧规避灰区）。状态语义改由**文字本身**承载（`已暂停` / `倒计时` 等）。**应用内** `MenuStatusBlock` 的 SVG/CSS 圆点**不受影响**（在 WebviewWindow 内绘制，合规），见本节末「范围澄清」。

#### 3.3.1 文案规范（纯文本；措辞沿用 `MenuStatusBlock`）

| 应用状态 | 状态行文案（禁用文本项 · **纯文本**） |
|---|---|
| **空闲** | `空闲 · 点开始正计时` |
| **正计时中** | `{事项名} · {MM:SS}`　例：`摸鱼 · 12:34` |
| **倒计时中** | `{事项名} · 倒计时 剩 {MM:SS}`　例：`摸鱼 · 倒计时 剩 07:26`；无事项名时 `倒计时 · 剩 {MM:SS}` |
| **暂停中** | `{事项名} · 已暂停 {MM:SS}`　例：`摸鱼 · 已暂停 12:34`（时长可省略为 `摸鱼 · 已暂停`） |
| **事项名缺失** | 以 `未命名` 占位：`未命名 · {MM:SS}` |

**口径细则**

- **无任何前缀符号**（无 `●`、无圆点、无图标）—— P0 裁定。
- 分隔符统一 **` · `（空格 + U+00B7 + 空格）**，与状态块同款；`已暂停` / `倒计时` 为**纯文本状态词**。
- 时长格式 **`MM:SS`**（两位补零）；**≥ 1 小时用 `H:MM:SS`**（如 `1:05:03`），与 `.timer-digits` 口径一致。

#### 3.3.2 刷新方式（硬约束 · 架构 ADR-013 / §6.e）

- **菜单结构只在「状态迁移」时重建**（空闲 ↔ 正计时 ↔ 倒计时 ↔ 暂停，以及视图 / 插件开关变化）—— 即重建原生 `HMENU`。
- **秒级时间（`剩 07:26` / `12:34`）用 `set_text` 原地更新该项文本**，**不每 tick 重建菜单**（重建会闪烁且成本高）。
- 原生菜单**打开期间不保证即时重绘** → 状态文本语义 = **「展开瞬间快照」**：菜单持续开着时不保证数字逐秒跳动。

#### 3.3.3 超长截断规则（硬约束 · 架构 K-30）

原生 Win32 菜单**按最宽项撑宽整个菜单、不自动省略**（架构 §9 **K-30**）→ 事项名过长会把整菜单拉宽。**必须在 Rust 侧 `append` / `set_text` 之前先截断字符串**：

| 规则 | 值 |
|---|---|
| 截断对象 | **仅「事项名」**（状态行及各项标签中的事项名一并适用） |
| 阈值 | 事项名 **≤ 约 20 显示宽** + 省略号（对齐 K-30；按半角宽度单位计，全角字 ≈ 2，故约 **10 个全角汉字**） |
| 省略号 | **单个 `…`（U+2026）**；**禁用三个英文点 `...`** |
| 永不截断 | ` · ` 分隔符 · 状态词（`倒计时` / `已暂停`）· 时长 `MM:SS` |
| 优先级 | 超长时**保时长完整 > 保状态词 > 截事项名**（数字 / 状态是扫读关键） |
| 极端兜底 | 截到仅剩 1 字仍超限 → 事项名整体显示 `…` |
| 整行参考上限 | 状态行整体 ≈ **28 个半角宽度单位**（≈10 全角事项名 + ` · ` + `12:34`），即菜单宽上限的驱动项 |

**示例（纯文本）**

| 输入事项名 | 状态行渲染 |
|---|---|
| `摸鱼` | `摸鱼 · 12:34` |
| `品牌视觉改版-首页与落地页联动设计` | `品牌视觉改版-首页与… · 12:34` |
| `写周报`（倒计时） | `写周报 · 倒计时 剩 07:26` |
| 极长名（超限极端） | `… · 12:34` |

> **范围澄清（重要）**：失去的只是**「状态块视觉（SVG 圆点 + 等宽数字）出现在托盘菜单里」**；`MenuStatusBlock` **组件本身完全不受影响** —— 它继续在**应用内悬浮菜单**（`context-menu.md` 小条右键 / 事项右键 / 便利贴右键 · `countdown-menu.md`）中**原样复用**，其 **SVG/CSS 圆点合规保留**（WebviewWindow 内绘制，不受 P0 字符符号禁令约束）。托盘退回原生只是**不再调用**该组件，不是删组件、也不改其规格。

### 3.4 危险语义（原生不可着色）

`退出` / `放弃（不记录）` 原为 `--danger` 红字。原生菜单**不支持 per-item 前景色**，改为：

- **位置**：置于各自分组**末位**（`放弃` 在控制组末、`退出` 在菜单最末）。
- **分隔线**：`退出` 前保留一条分隔线，形成「危险区」。
- **文案**：用明确动词（`放弃（不记录）` / `退出`）自带语义。
- 若 Phase 3 认为视觉强调不可缺 → **只能回退自绘（方案 B）**；但方案 B 已裁定为 **v0.3+ 备查**、**不在 V0.2.0 范围**（见 §7）。

## 4. 引用的 Token 名

> **重要**：原生托盘菜单**不吃任何应用 Token**——底/文字/间距/圆角/时长全部系统决定。以下处理为**退役**或**移交给应用内菜单**：

| Token | 处置 |
|---|---|
| `--tray-w` 272px | **退役**（原生宽度由系统按最长项自算） |
| `--menu-bg` / `--glass-panel-bg` / `--shadow-float` / `--line` / `--line-2` | **不用于托盘**；仍服务 `context-menu`（应用内自绘玻璃） |

## 5. 图标

| 对象 | 规格 | 说明 |
|---|---|---|
| **托盘图标**（系统通知区那枚） | Rust 侧 `.ico`，16/20/24/32 多尺寸 | **OS 原生资源**，前端不绘制（不违反「应用内图标必须 lucide」） |
| **菜单项图标** | **默认不带** | Windows 通知区菜单惯例为**无图标**；原生仅支持 16px 位图 `HICON`，不支持 SVG/lucide |
| （可选）**若必须带图标** | Rust 侧把 lucide SVG 预栅格化为 16px `HICON` 再挂到 `IconMenuItem` | **不在 V0.2.0 范围**；且会破坏「同一套矢量图标」一致性，**不推荐** |

> 结论：**托盘菜单项不带图标**。lucide 16/20/24px 规范**只约束应用内 UI**（小条、面板、便利贴、应用内菜单）。

## 7 · Tauri 实现路径（架构已裁定：**保留原生菜单**）

**背景**：Tauri v2 托盘菜单 = **原生 Win32 `HMENU` + `TrackPopupMenu`**，**无法自绘**。曾评估「方案 B：禁用原生、改在光标处弹透明 `WebviewWindow` 自绘玻璃菜单」，**架构最终裁定不采用方案 B，保留原生菜单**（成本与焦点竞态不值，且时序/多屏风险高）。**本页据此为终稿。**

架构侧约束与本页对应：

| 约束 | 设计侧对应 |
|---|---|
| **外观由系统决定** | 本页只控制**信息架构**（§1）：分组、分隔线、启用/禁用、勾选、快捷键标注 |
| **每次右键重建菜单** | §2 构建模型；状态实时读取 |
| **启用/禁用/勾选/默认项** 用原生 API | §3.2 勾选 · §1.4 默认项 · §3.1 按状态裁剪（不生成不可用项） |
| **主题不跟应用** | 记为 **K-29**（架构 §9 §6.e）：托盘菜单随 OS 明暗，与应用 `data-theme` 可能不一致，**已接受的局限**（原生菜单代价）；缓解=托盘只保信息架构、**不承诺与应用主题同色** |
| **应用内菜单仍自绘玻璃** | `context-menu.md`（小条右键 / 事项右键 / 便利贴右键）· `countdown-menu.md` · `common-items.md` **保持原样** |
| **条件项构建时判定** | §1.3 |

> **已核实**：`backdrop-filter` 只作用 WebView 内部层级、不穿透 OS 窗口管理器（架构 §6.g）。因此「应用内菜单玻璃」安全；而托盘菜单**根本走不到 WebView**，无玻璃一说。
>
> **方案 B 的去向**：因已选原生，**本期不落地方案 B**；但 ADR-013 将 **B 降级为 v0.3+ 备查（保留、不删除）** —— 若将来产品强制要求托盘菜单玻璃外观 + 状态块，再回到 B，届时不需从零重设计。
>
> **多窗口目录（架构 Q1）**：**不再含 `tray-menu` 窗**（该新窗是方案 B 才需要的）。窗口目录回到 `主窗 / note-* / todos / settings`；`App.tsx` 路由同步回到这四类，**不新增托盘菜单路由**。
