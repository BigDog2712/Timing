# AI 自动打标签（0.12.5）

> 一句话：**数据页 → 标签管理 → 「AI 自动打标签」**，把「应用」和「事项」一起交给 AI 判断
> 该挂哪些标签，先看预览，再一次性落库。

---

## 1. 在哪、怎么用

| 步骤 | 说明 |
|---|---|
| ① 打开 | 数据页 → 数据区域下方「标签管理」区块，标题右边的 **AI 自动打标签** |
| ② 等 | 按钮转圈：应用按 40 个一批顺序发，事项一批；应用多了会久一点 |
| ③ 看 | 弹窗列出每个对象一行：名称 + 标签 chip。**默认勾上的就是 AI 建议的** |
| ④ 改 | 点 chip 加/去；灰色标「（原有）」的是原本就有、AI 这轮没收的 |
| ⑤ 应用 | 底部「应用（N）」→ 写入 → 标签树、走量、应用排行上的 chip 一起刷新 |

前置：**设置 → AI** 里配好地址与密钥、打开总开关，再打开「应用标签 / 事项标签」（各管一侧）。

---

## 2. 三条口径

**① 先预览，AI 不直接动数据。**
写入是**全量覆盖**（应用 `override.tags`、事项 `items.tags` 都是整份替换），模型判错一次
就洗掉手填标签。所以 AI 只提议，清单里可摘可回。

**② 默认勾选 = 模型建议，不是「建议 ∪ 原有」。**
这一版是"重新判断"：没被建议的旧标签默认落选，但**灰着留在同一行**，点一下勾回来。
默认保留旧标签的话，AI 永远删不掉一个错标签，"重新判断"就退化成"只增不减"。
全摘掉时行内明示「将清空原有标签」——不静默。

**③ 两侧各自独立。**
应用侧失败不丢事项侧的结果（提示一句"这一侧先不写"）；总开关关着时提示指向总开关，
不是去翻两个子开关。

## 3. 写库边界（谁写、写什么）

| | 应用 | 事项 |
|---|---|---|
| 落点 | `__app_override::<exe>` 的 `tags` | `items.tags` |
| 谁写 | 分析窗自己（`cmd_commit_classification_settings`） | **药丸**（`set_item_tags`） |
| 怎么过去 | `ClassificationService.saveAppOverride` | `activity:host-intent` 的 `set_item_tags` 意图 |
| 只改什么 | **只换 `tags`**；`track` / `displayName` / `color` / `category` 不碰 | 整份 `tags`（空数组 = 清空） |

- **零新增 IPC 命令**：契约仍 109 / 114，ACL 未动。分析窗到现在也没有任何宿主写命令。
- **新标签补定义行**：`set_item_tags` 只改 `items.tags`，不建 `tag.def.*`。不补的话，
  AI 造的标签只跟着一条记录存在，那条记录一改就整条消失。
- **一条失败不拖累其余条**：这里没有事务，也不装作有；结果条写明成功与失败条数。

---

## 4. 已知限制（都不是 bug，是这一版的边界）

1. **没有撤销**。写错了只能再跑一次或手动改。全量覆盖 + 无撤销是有意的取舍：
   加撤销要留快照，而快照该存在哪张表、同步到哪一端，是另一个批次的事。
2. **范围是"全部"**：应用取分类页那份**应用目录**（见过的全部应用，按累计时长倒序），
   事项取全部非系统事项。没有"只挑这几个"的选择器 —— 先跑一遍、在预览里取消不需要的行，
   是当前最省事的路。
3. **耗时与规模成正比**：后端每 40 个目标一批，200 个应用约 5 批。没有进度条，
   只有按钮上的转圈。
4. **模型判定有随机性**：同一批对象隔几天再跑，标签可能不同。这是模型特性，
   所以预览才是必需品而不是可选项。
5. **系统项「未归类」不参与**（`isSystem`），给它打标签会污染标签树。

---

## 5. 后续可以做的（按价值排序）

1. **撤销上一次批量写入**：落一份"写前快照"（应用 tags + 事项 tags），支持一键回滚。
2. **范围选择**：`只看还没标签的` / `只看这段时间用过的`，减少误伤与等待。
3. **单应用入口**：应用排行行内直接「AI 猜标签」，复用同一套候选与预览。
4. **进度与分批呈现**：现在是整批返回才出预览，改成"每批回来就追加"，体感会好很多。
