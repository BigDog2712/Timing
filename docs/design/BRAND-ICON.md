# TickBar 品牌图标（ICON）

来源：`scripts/gen-icon.py`（唯一的真源）。`.png` / `.ico` 都是它的产物，
**不要手工改图**——改了下次重跑脚本就丢。

## 1. 这个记号是什么

小条左侧那枚**计时环**（`--ring-size`，16px 环 + 2.4px 描边）放大成图标：

| 部件 | 取值 | 出处 |
| --- | --- | --- |
| 底板形状 | 超椭圆 n = 4，满幅 | 同 `--ring-radius` 的超椭圆口径（n=3）再收紧一档，缩到小尺寸更像个「方」 |
| 底板渐变 | `#1B1F27` → `#0A0B0E` | 深色主题 `--bg-card` / `--bg-plate` 之间 |
| 左上提亮 | `#2C3444`，径向，alpha 按 0.5 叠 | 极淡，只为让 256px 不显死板 |
| 发丝描边 | 白 10% | `--line-2` |
| 环 | 开口 300°，圆头端帽，渐变 `#98CDF6` → `#3885C9` | `--accent-ink` → 压深一档的 `--accent` |
| 12 点刻度 | `#E8A33D`，直径 = 环粗 ×0.32 | `--warn`；旧图标唯一的记忆点 |
| 环身占比 | r_out = 边长 × 0.322，粗 = 边长 × 0.098 | 见 §2 |

纯平面：**没有任何投影/内阴影**（V0.2.10「去除整体阴影」口径）。

## 2. 逐尺寸分级（`GRADES`）

同一个比例缩到 16px 必然糊，所以按尺寸换一组参数：

| 尺寸 | r_out | 环粗 | 开口 | 刻度点 | 淡轨道 |
| --- | --- | --- | --- | --- | --- |
| ≥ 48 | 0.322 | 0.098 | 300° | 有 | 有 |
| 32 – 47 | 0.330 | 0.108 | 300° | 有 | 无（24px 以下是雾） |
| 16 – 31 | 0.360 | 0.140 | 310° | **无**（<1px，糊成脏点） | 无 |

`.ico` 因此是自己写的容器（`write_ico`）：16/20/24/32/40/48/64/128/256 九个条目，
每档用上面的参数**原生渲染**后再打包，不是从一张 1024 缩放。256 存 PNG，
其余存 32bpp BMP + AND mask（老 shell 对小尺寸 PNG 条目支持不稳）。

## 3. 托盘图标不是同一个文件

`src-tauri/icons/tray.png`（32×32，透明底，无底板，r_out 0.445 / 环粗 0.158 / 开口 316°）。

Windows 通知区只有 **16–24px**：带底板的版本在那里是一块深色方块，环被压成一条细线。
去掉底板、加粗环身之后，16px 下是一个干净的蓝色环 + 左上缺口 —— 缺口的朝向就是身份。

32 是刻意的：100% 缩放时 2:1 正好，150% 24px、200% 32px 也都落在整数比附近。

`app/tray.rs` 用 `include_bytes!("../../icons/tray.png")` 编译期内嵌（`image-png`
特性已在 `Cargo.toml` 打开），解码失败退回窗口图标。

## 4. 改图标怎么走

```bash
python scripts/gen-icon.py          # 重出 src-tauri/icons/ 下全部 png + ico + tray.png
python scripts/gen-icon.py --lab    # 只出对比图到 .workbuddy/icon-lab/（深/浅底色 × 各档）
```

改完 `.ico` 必须**重新编译**才进 exe（图标是 Windows 资源，`tauri-build` 在 build.rs 里嵌）。

依赖：Python 3 + Pillow（4× 超采样手绘，不引外部 SVG 渲染器，保证任何机器结果一致）。

## 5. 图标缓存

Windows 会缓存 `.lnk` / `.exe` 的图标，换图后仍显示旧图属于缓存问题，不是没生效：

```powershell
ie4uinit.exe -show            # 重建图标缓存（多数情况够）
taskkill /f /im explorer.exe && start explorer.exe   # 还不行再重启资源管理器
```
