# PLAN · 安卓端「应用使用时间统计」（0.13.0 候选）

> 目标：给 **Timing 安卓版**加上和 PC 版（Patina 分析窗）同级的「应用使用时间统计」——
> 哪个 App 用了多久、按分类怎么分、今天和昨天比什么样、几天的趋势怎么走。
> 状态：**方案，未动代码**。写于 2026-11-11。本文件不作实现依据，只作决策与判据的锚点。

## 0. 一句话结论

安卓上这件事**不是画界面**，是**拿系统数据**：Android 通过 `UsageStatsManager` 提供
「某应用在前台多久」，但这扇门要用户在系统设置里单独授权（`PACKAGE_USAGE_STATS`，
不是运行时弹窗能给的）。所以真正的工作量与风险都在：**授权引导、采集口径、落库、杀后台后的连续性**。
界面是最后一步。

参考对象（不是照抄，是各取一条）：

| 软件 | 值得抄的一条 | 不要抄的 |
|---|---|---|
| 数字健康（Digital Wellbeing） | 授权引导：先讲清「能看到什么、存在哪、不上传」，再跳系统页 | 只给「今天」，没有历史对照 |
| RescueTime | 「活动时长 ≠ 生产力」的分层：先给事实，再给趋势 | 用单一「效率分」代替事实 |
| ActivityWatch | 采集边界透明：采什么、存哪、怎么删 | 需要自建服务器才有完整体验 |
| 滴答清单/番茄类 | 分类可编辑、可按项目归 | 把「计划」和「实际」混成一张图 |

## 1. 现状（已核过的事实）

| 项 | 事实 |
|---|---|
| 安卓壳 | `src-tauri/gen/android/app/src/main/java/com/timing/app/`：`MainActivity.kt`、`TimingNativePlugin.kt`、`native/{Prefs,SafVault,SecretStore}.kt`、`overlay/`（悬浮条） |
| 原生桥 | `TimingNativePlugin.kt` 用 `@Command` 暴露能力（safStatus / mirrorIn / mirrorOut / overlaySet …），Rust 侧以字符串注册 `register_android_plugin("com.timing.app", "TimingNativePlugin")` |
| 清单权限 | 已有 INTERNET / POST_NOTIFICATIONS / SYSTEM_ALERT_WINDOW / FOREGROUND_SERVICE(+SPECIAL_USE)；**没有** `PACKAGE_USAGE_STATS` |
| 手机页签 | `MobileShell` 五页：计时 / 事项 / 记录 / 便利贴 / 设置（`TABS` 常量驱动） |
| 分析窗 | Patina 那套（应用排行 / 分类 / 趋势）是**桌面独占**：`src-tauri/src/services/insight/**` 在移动端不注册真实实现 |
| 契约 | 宿主命令 **81**（桌面另加 Patina 117）· 错误码 **17** · 事件 **11** · schema **v7** |

## 2. 三个必须先拍的口径

### ① 采集粒度：前台时长（推荐）还是「事件流水」

- **A 按包聚合（推荐）**：每 N 秒/每次切换问一次 `queryEvents`，把前台区间累加到 `(包名, 本地日)`。
  存储量小（一天几十行），足够画「排行 / 分类 / 趋势」。
- **B 存切换事件**：能算「几点到几点在干什么」的时间轴，但一天几百到几千行，还要自己折叠。
- 取舍：**先 A**。时间轴（PC 版那种「几点做了什么」）等 A 跑稳再上，两者共用同一张表也能扩展。

### ② 数据落点：新表 + 迁移，还是「现算不入库」

- **A 落库（推荐）**：新表 `app_usage(package_name, local_date, foreground_sec, first_seen_at, last_seen_at, updated_at)`，
  迁移 `0008`。好处：趋势、昨日对比、杀后台后补算都能做；坏处：**必须走迁移评审**。
- **B 现算不落库**：每次打开页面问系统要当天数据。省一张表，但**趋势图做不了**（系统只给窗口内的聚合），
  且每次进页面都要跨桥取数，慢且耗电。
- 取舍：**A**。这条会动 schema，需要主人点头。

### ③ 授权引导：什么时候问、被拒之后怎么办

- 入口只在「统计」页首屏：一段三行说明（看到什么 / 存在本机 / 可随时撤销）+ 一个「去授权」按钮。
- **不在启动时弹**：启动就跳系统设置是最招人烦的一种。
- 被拒之后：页面显示「未授权」的空态 + 授权入口，**不伪装成 0 分钟**（与 PC 版
  「空态与错误态必须长得不一样」同一条纪律）。

## 3. 技术路线

```
UsageStatsManager（系统）
   ↓ Kotlin：UsageStats.kt（新）
     · hasPermission(context) → PACKAGE_USAGE_STATS 是否已授
     · queryDay(packageFilter*): List<PackageUsage>  （begin/end = 本地日 00:00 → now）
     · openSettings()：Intent(Settings.ACTION_USAGE_ACCESS_SETTINGS)
   ↓ TimingNativePlugin：新增 3 个 @Command
     · usagePermission → { granted: boolean }
     · usageOpenSettings → ()
     · usageDay → JSON 数组（包名 / 前台秒 / 首末见时刻）
   ↓ Rust：`commands/insight/*`？不 —— 走 **mobile 侧宿主命令**
     · usage_stats_get（mobile-only，桌面回 stub）
     · 定时聚合任务：`jobs/usage_rollup`（mobile-only，15 分钟，落 app_usage）
   ↓ 前端：新页签「统计」（TABS 里插在「记录」之后）
     · 今日排行（Top N + 其他）
     · 分类分布（包名 → 分类映射，默认从系统 category 推）
     · 昨日对比 + 7 天趋势（读 app_usage）
```

### 3.1 包名 → 显示名 / 分类

- 显示名：`PackageManager.getApplicationLabel`（Kotlin 侧取，一次取完缓存到 settings KV）。
- 分类：`ApplicationInfo.category`（系统给的那套：游戏/影音/社交…）作为**默认值**；
  用户可在统计页改（写 KV，键前缀 `__pkg_category::<pkg>`，与 PC 版 `__app_item_bind::` 同一套思路）。
- 图标：先不取。取图标要做位图传输 + 缓存，属第二阶段。

### 3.2 采集的边界（必须先说清，否则以后天天被问）

- **只统计「在前台」的时间**：后台播放音乐、后台下载都不算（系统也只给这个口径）。
- **系统只保留最近几天**的明细事件，超过窗口就只能靠**我们自己落库的历史**——这也是选 ②-A 的理由。
- 息屏、锁屏不计时（`queryEvents` 里 `SCREEN_NON_INTERACTIVE` 要当切走处理）。
- 厂商 ROM 会杀后台：悬浮条已经有「退避重开 + 权限状态分开」的坑记录，
  采集任务要复用同一套（`enabled` 偏好 vs `permitted` 系统状态分开报）。

## 4. 契约影响（这是要拍的主要原因）

| 面 | 现状 | 加完之后 | 需要什么 |
|---|---|---|---|
| 宿主命令 | 81 | **+2**（`usage_stats_get` / `usage_stats_settings`）→ 83 | 契约文档四处 + `check:contract` |
| 错误码 | 17 | **+1** `USAGE_PERMISSION_DENIED` → 18 | `error.rs` + 前端两处镜像 + ADR |
| 事件 | 11 | 不变（采集完成后不广播，页面轮询/焦点重读） | — |
| schema | v7 | **v8**（`app_usage` 表） | 迁移 `0008` + 五表变六表 |
| 权限面 | — | `PACKAGE_USAGE_STATS`（特殊权限，需 `tools:ignore="ProtectedPermissions"`）+ capability 放行两条命令 | 清单 + capabilities |

> 如果不想动契约，可以退到「前端直接调原生插件」（`invoke('plugin:timing-native|usageDay')`）：
> 命令数不变，但**数据进不了 Rust**，趋势就必须前端自己算并另找地方存 —— 不建议。

## 5. 分期与判据

### P1 · 权限与「今天」（1 个 PR，可先出包）

| 验收 | 判据 |
|---|---|
| U1 授权可走通 | 未授权时统计页显示空态 + 「去授权」；点它跳到系统「使用情况访问」页；返回后 5 秒内页面自动变成有数据 |
| U2 数字对得上系统 | 同一时段（例如 30 分钟只用浏览器）本页「浏览器」时长与系统「数字健康」差 ≤ 60s |
| U3 未授权不伪装 | 未授权时**不显示任何 0 分钟排行**（空态与 0 数据必须长得不一样） |
| U4 息屏不计 | 锁屏 10 分钟后回来，时长不增加 |
| U5 不打启动流程 | 冷启动到主页 ≤ 现有基线 + 200ms（授权引导只在统计页首屏） |

### P2 · 落库与趋势

| 验收 | 判据 |
|---|---|
| U6 迁移安全 | 老库升到 v8 后，五张老表行数与升级前逐表相等 |
| U7 趋势可信 | 连续 3 天，`app_usage` 每日合计与当天「数字健康」差 ≤ 3% |
| U8 杀后台可补 | 采集任务被杀 → 下次启动补算中断区间（判据：中断 2 小时后打开，那 2 小时不计入任何应用） |

### P3 · 分类与编辑

| 验收 | 判据 |
|---|---|
| U9 分类可改 | 改一个包名的分类 → 排行按新分类着色；刷新后仍生效 |
| U10 设置不打架 | 统计页的分类编辑与 PC 版分类页互不覆盖（各有各的键前缀） |

## 6. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 授权率 | 特殊权限要跳系统设置，很多人到此为止 | 首屏讲清三条价值；拒绝后仍可用「手动计时」 |
| 厂商 ROM 杀后台 | 小米/华为/OPPO 默认限制后台 | 复用悬浮条的「退避重开 + 状态分报」；页面顶部提示「数据可能不完整」 |
| 口径争议 | 「我明明用了 2 小时」| 页面写明「只统计前台、息屏不计」，并给「按系统数字健康校准」的说明 |
| 隐私 | 应用使用记录是敏感数据 | 全部留在本机；不新增任何上报；导出走既有备份机制 |
| 包名不稳定 | 同一 App 换签名包名会变 | 以包名为键，显示名只做展示 |

## 7. 不做

- 不上传、不做云对比、不做「效率分」。
- 不采集**窗口标题/内容**（Android 也拿不到），只到「哪个应用 + 多久」。
- 不做「跨设备合并统计」（与 PC 版各自统计，避免口径混淆）。
