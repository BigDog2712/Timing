**原始需求复述（用户原话，语义不得改动）**

1. 界面分为**悬浮条**、**主界面**两个窗口；Timing 原**设置窗口移至主窗口界面**，对 UI 等进行融合。
2. 悬浮条窗口**右侧手柄**功能拓展：手柄支持拓展**三层形态**，左至右为**圆点、半手柄、手柄（原形态）**；可在设置菜单**开启不同的手柄**，并将手柄**绑定不同快捷功能**（如唤出主界面、同步等）。功能选择应**留好扩展空间**，便于新增不同功能。**每个手柄最多支持绑定五种动作**：左键单击、右键单击、中键单击、左键双击、右键双击。
3. 现在手柄**左侧的图标删除**，其功能**移入手柄功能**中。

**已拍板裁决**：A1 三手柄并排且各自可开关；A2 设置窗口逐页重排成主界面风格；A3 只做桌面。

## 2. 用户故事

| # | 作为… | 我想… | 以便… |
|---|---|---|---|
| US-1 | 长期用悬浮条计时的用户 | 在设置里勾掉不用的手柄 | 药丸只留我惯用的那一个，不被多出来的图标挤占事项名（当前名字已被压到 152px，不到 11 字） |

## 3. 需求池

优先级：**P0 = 必须（缺即返工）/ P1 = 应该 / P2 = 可选**。
每条需求都带**可验收口径**（怎么算做完、能怎么测）。凡判据涉及几何量，遵循 44 §乙-1 的"四问"：**对象对不对 → 盒子含不含 padding → 缩放反解 → 时刻对不对**。

### 3.1 三手柄并排与开关（H）

| ID | 优先级 | 需求 | 可验收口径 |
|---|---|---|---|
| H-01 | **P0** | 三手柄并排渲染在药丸**最右端**，左至右固定 `圆点 → 半手柄 → 手柄` | `.pill` 内 `[data-handle]` 三节点 `offsetLeft` 严格递增（dot<half<full）且 `offsetTop` 全等（同一行不换行）；`.pill` `offsetHeight === 32` |
| H-02 | **P0** | 每个手柄**独立开关**，设置里三个勾选 | 关掉某手柄后：① 该节点 `offsetWidth === 0`（`display:none`，**不是** `opacity:0`）② `elementFromPoint(该手柄原中心)` 不返回它（真正不占位、不吞点击）③ `.pill` 宽度相应减少 |
| H-03 | **P0** | 三手柄共用同一视觉语言，只有形状不同：圆点=实心点 / 半手柄=短括号 / 手柄=现行长括号 | 三者 `stroke-width === 2.5`、`viewBox` 高同为 22、`color === var(--pill-grip-ink)`；差异只在 path 几何（三个 `data-handle` 值不同） |
| H-04 | **P0** | **命名去重**：新手柄「圆点」与既有「收起态小圆点」（`floatForm='dot'` / `uiStore.collapsed`）不是一回事，代码里不得同名 | `data-handle` 取值只能是 `dot` / `half` / `full`；`floatForm` 相关标识不出现 `handle` 前缀，反之亦然（源码级断言） |
| H-05 | P1 | 每个手柄 hover 有 `title`，内容**由当前绑定动态生成**（「左键：记录面板 · 右键：今日摘要」，未绑定的槽不出现） | 改绑定后 title 文本随之变化；同一断言里同时断言"旧文案已不在"，防"文案没接上绑定" |
| H-06 | P1 | 键盘可达：Tab 依次到三个手柄，focus 显形 + 焦点环，`Enter`/`Space` 触发**左键槽** | Tab 顺序 = DOM 顺序；focus 时该手柄图标 `opacity===1`；`Enter` → 左键槽动作恰好 1 次 |
| H-07 | P2 | 设置里给每个手柄一个「恢复默认」小按钮 | 点击后该手柄 5 槽回到 §6.1 默认值，其余手柄不受影响 |

### 3.2 五动作槽与动作注册表（A）

| ID | 优先级 | 需求 | 可验收口径 |
|---|---|---|---|
| A-01 | **P0** | 槽位固定 5 个：`left` / `right` / `middle` / `leftDouble` / `rightDouble`；每手柄 × 每槽最多 1 个动作，可为「无」 | 持久化结构里每个手柄恰有 5 个 key；缺 key / 值为 `null` → 渲染为「无」 |
| A-02 | **P0** | **动作注册表是唯一数据源**：新增一个动作 = 只在注册表加 1 条（若需新底层能力，再加 1 个 `services/` 函数）；**不得**改设置页 UI、不得改手势分派 | ① 注册表条目数 N → 任一槽位选择器的 `option` 数 = N+1（含「无」）；② **反证型判据**：单测里临时向注册表注入一个只存在于此的假动作，不改任何 UI 代码，断言它出现在选择器里且能被派发。把注入删掉后该断言必须红 |
| A-03 | **P0** | 动作 **id 是持久化键**，UI 文案改名不影响已存配置 | 把某动作 label 改成另一个字符串 → 已存 id 仍解析成功并派发 |
| A-04 | **P0** | 未知 / 失效 id 一律回落「无」且不崩（老版本升级、手改 localStorage） | 注入 `{left:'not.exist'}` → 渲染不抛错、槽显示「无」、点击无动作、控制台无 error |
| A-05 | **P0** | 动作注册表**不进 `src/components`**（层门禁 L1：ADR-017） | `grep "ipc\." src/components/**` = 0；注册表与动作实现落 `src/services/` |
| A-06 | P1 | 选择器按组呈现：「界面入口」（主界面 / 记录面板 / 今日摘要 / 事项便利贴 / 便利贴清单 / 事项窗 / 设置）与「计时与同步」（开始 / 暂停 / 结束并保存 / Markdown 同步 / 倒计时菜单 / 摸鱼菜单） | 分组标题与目录数与注册表 `group` 字段一致 |
| A-07 | P1 | 每个动作自带 `canRun(ctx)` 护栏；不可用**不静默**：给一条 `setNotice`，不派发 | idle 下绑「结束并保存」→ `stop` 调用 0 次 **且**出现 notice；running 下 → 1 次 |
| A-08 | P2 | 同一动作允许绑到同手柄的多个槽（不拦），但给一行灰字提示「已在左键」 | 绑重复时提示出现；不阻止保存 |
| A-09 | P2 | 注册表每条带 `irreversible` 与 `lowFrequency` 两个标记，供选择器渲染角标与 §3.3 的延迟提示 | 「结束并保存」`irreversible===true`；「记录面板」`lowFrequency===true` |

### 3.3 手势判定：双击 / 中键 / 拖动 / hover（G）

| ID | 优先级 | 需求 | 可验收口径 |
|---|---|---|---|
| G-01 | **P0** | 双击判定窗 **250ms**，作为常量 `DBLCLICK_MS`（允许区间 **220–280**，落 `lib/constants.ts`） | 常量存在且 ∈[220,280]；改到 400 时 G-03 判据必须红（反证用例） |
| G-02 | **P0** | **双击不得触发两次单击**：双击的第一次单击必须被取消 | `click();click()+dblclick` 序列 → `left` 计数 = 0、`leftDouble` 计数 = 1；把分派错位（dblclick 派成 left）时该判据必须红 |
| G-03 | **P0** | **延迟只在必要时启用**：某手柄两个双击槽都为空 → 单击**立即**派发（0 延迟）；至少一个非空 → 单击延迟 250ms 等双击判定 | 双击槽全空：`click` 后同帧内派发；有双击绑定：`click` 后 250±50ms 派发，且 <200ms 内不派发 |
| G-04 | **P0** | 待定单击**可撤销**：拖动开始 / `pointercancel` / 组件卸载 / 窗口 blur 时清空 | `click` → 100ms 内 `pointerdown+move 20px` → 手柄动作 0 次，且窗口拖动触发 1 次 |
| G-05 | **P0** | 中键只认 **`auxclick`（`button===1`）**；`pointerdown` / `mousedown`(1) 只 `preventDefault`（抑制 WebView2 自动滚动与中键粘贴），**不派发** | `mousedown(1)` → 动作 0 次且 `defaultPrevented===true`；`auxclick(1)` → 动作 1 次；页面 `scrollTop` 变化 = 0 |
| G-06 | **P0** | 不得破坏「按住手柄拖窗口」：左键 `pointerdown` **必须继续冒泡**给 `.pill` 的拖动判定 | 手柄 `onPointerDown` 内不出现 `stopPropagation`（源码级断言）；拖 20px 后松手 → 手柄动作 0 次、`startCurrentWindowDrag` 1 次 |
| G-07 | **P0** | 右键沿用现机制：`pointerup(button 2)` 派发 + `contextmenu` 在 400ms 内去重（防开两次） | 一次物理右键 → 右键槽动作恰好 1 次（不是 2 次） |
| G-08 | **P0** | **hover 显形保留，但命中宽恒定**：hover 只改图标 `opacity`，不改宽度 | hover 前后该手柄 `offsetWidth` 相等、`.pill` `offsetWidth` 相等（否则 hover 会让药丸"鼓一下"、鼠标漂移） |
| G-09 | P1 | 中键若绑了动作，`auxclick` 后须再 `preventDefault`，并抑制 `paste` / `mouseup` 默认行为 | 事件对象 `defaultPrevented===true`；无粘贴副作用（合成事件下断言） |
| G-10 | P2 | 手柄上不响应滚轮（滚轮继续归药丸调倒计时） | 手柄元素 `onWheel` 不吞事件，滚轮仍改档位 |

### 3.7 几何与宽度（W）

**W-01（P0）宽度预算公式**——三项相加：

```
pill 宽 = padding(8+7) + border(2) + ring(16) + gap(8) + timer(53)
        + Σ(手柄命中宽 + 4)          ← 每个手柄净占「命中宽 + 4」
        + name(≤164)
```

| 项 | 值 | 来源 |
|---|---|---|
| 左右 padding | 8 + 7 = 15 | `--pill-pad-l` / `--pill-pad-r` |
| border | 2 | 1px × 2 |
| 环 | 16 | `--ring-size` |
| 环↔数字 gap | 8 | `--space-2` |
| 计时数字 | 53 | 定宽 + 右对齐 |
| 数字↔名 / 名↔手柄 / 手柄↔手柄 净间距 | 各 4 | `--space-2` − `--space-1` |
| 手柄命中宽 | **12**（原 10） | `.pill__handle { width: var(--grip-w) }`；`--grip-w` / `--grip-hit-w` 当前同为 10，**一并改 12** |
| 事项名上限 | 164 | `--task-w-max`（**不动**） |

## 6. 默认值与迁移

### 6.1 默认绑定（含理由）

| 手柄 | 默认开关 | 左键单击 | 右键单击 | 中键单击 | 左键双击 | 右键双击 |
|---|---|---|---|---|---|---|
| 圆点 `dot` | 关 | 记录面板 | 今日摘要 | 无 | 无 | 无 |
| 半手柄 `half` | 关 | 唤出主界面 | 事项窗 | 无 | 无 | 无 |
| 手柄 `full` | **开** | 当前事项便利贴 | 便利贴清单 | 无 | 记录面板 | 今日摘要 |

**四条理由**

1. **升级当天零学习成本**：`full` 的左/右键 = 原手柄左/右键（便利贴 / 清单），一字不差。
2. **功能不丢**：原「今天」图标左键=`记录面板`、右键=`今日摘要`，**逐字搬进 `full` 的左右双击**。之所以用双击而不是单击：单击槽必须留给老用户肌肉记忆里的便利贴；而"看数据"是一天几次的低频诉求，配得上一个刻意手势（`lowFrequency` 标记，A-09）。
3. **只开 `full`**：三个全开会让药丸从 278 变 310（+32）。老用户没要求过更宽，默认只开他本来就在用的那一个 —— 何况删掉今天图标后药丸反而**变窄 10px**（288→278），名字首次吃满 164。
4. **前两个手柄给"愿意配置的人"留位置**：开启即用（有预置绑定），不是开出来一个空壳。

### 6.2 持久化 schema（`localStorage`，键 `timing.appearance.v1` 内扩展）

```
appearance = {
  textOpacity: number,          // 既有
  bgOpacity: number,            // 既有
  floatForm: 'bar' | 'dot',     // 既有
  handles: {                    // 新增（可选；缺失 = 全默认）
    dot:  { enabled: boolean, slots: { left, right, middle, leftDouble, rightDouble } },  // 值为动作 id 或 null
    half: { … },
    full: { … }
  }
}
```

- `slots` 的 5 个 key **必须全存在**（A-01）；缺失的 key 按 `null` 补，写回时才补齐。
- 只存**动作 id**，不存文案（A-03）；未知 id 回落 `null`（A-04）。
- 键名统一走 `lib/storageKeys.ts`，不在代码里写字面量（既有纪律）。

### 6.3 升级迁移矩阵

| 场景 | localStorage | 用户看到 |
|---|---|---|
| 全新安装 | 无 `appearance` 键 | 与 §6.1 默认完全一致；只开「手柄」 |
| **老用户升级 0.12.0 → 0.12.1** | 有 `appearance`（3 个旧键），**无 `handles`** | 与全新安装**完全一致**。读到 `handles===undefined` → 直接取默认，**不写盘**（等用户真的改了才写），所以"没动过设置"的用户键值保持原样 |
| 手改坏 / JSON 解析失败 | 坏 JSON | 整体回落默认，不崩（X-02/X-03）；不覆盖原键 |
| 部分手柄被删（`handles.full` 缺） | — | 缺的那个手柄取默认（= 开，默认绑定），不是"关" |

### 6.4 「原功能不丢」逐条对照（这是本轮最容易返工的一张表）

| 旧入口 | 旧行为 | 新落点 | 是否一致 |
|---|---|---|---|
| 今天图标 · 左键 | `openTodayPanel()` → 记录面板 | `full` · **左键双击** · `today.panel` | 落点一致，手势不同（单击→双击） |
| 今天图标 · 右键 | `openDigestPanel()` → 今日摘要 | `full` · **右键双击** · `today.digest` | 落点一致，手势不同 |
| 手柄 · 左键 | `openOrCreateNoteForItem(currentItemId)` | `full` · 左键单击 · `note.current` | **完全一致**（含"无当前事项开空白便签"） |
| 手柄 · 右键 | `uiStore.openNotesList(pos)`（锚点取手柄左下） | `full` · 右键单击 · `note.list` | **完全一致**（锚点仍取该手柄 rect） |

| 3 | `--pill-w-max` 现在被**撤销条**共用（`overlays.css:150`），抬到 320 会让撤销条一起变宽 32px。 | 一个 token 两个消费方，改一个会顺带改另一个未授权的视觉。 | **拆 token**：`--pill-w-max: 320px` + 新增 `--undo-w-max: 288px`，撤销条改吃后者。不新增色源、不动别处。 |
| 4 | 「结束并保存」这类**不可逆**动作，允许绑到最易误触的单击槽吗？ | 允许 → 有误触丢一次计时的风险；禁止 → 用户少一个自由度，且和"5 个槽一视同仁"的说法矛盾。 | **允许绑**，但：① 注册表标 `irreversible`，选择器里给角标；② `canRun` 护栏（idle 下不派发 + notice）；③ 不做二次确认弹窗（单击弹确认会毁掉"快"这件事，护栏 + 角标已够）。 |
| 5 | 手柄命中宽从 10 提到 12，仍远低于 WCAG 2.5.8 的 24px。要不要顺手做大？ | 32px 高的条内做 24px 命中的唯一办法是让命中区**溢出条外**（`::before` 外扩，圆环就是这么做的），三连排时相邻命中区会重叠 → 点错手柄。 | **不做**，本轮只到 12，并**如实记债**（写进 CHANGELOG 的"已知限制"）：三连排 + 32px 高这个约束下，24px 不重叠在物理上做不到。要做就得减手柄数量或加高药丸 —— 两条都是更大的产品变更，另立议题。 |

## 8. 附录

### 8.1 动作注册表契约（S2 必须照此落地，UI 由它渲染）

```
interface HandleAction {
  id: string;                 // 持久化键，永不变（A-03）
  label: string;              // 中文文案，可改
  group: 'ui' | 'timer';      // 选择器分组（A-06）
  irreversible?: boolean;     // 不可逆角标（A-09 / §7-4）
  lowFrequency?: boolean;     // 低频动作标记（§6.1 理由 2 / 延迟提示）
  canRun(ctx: TimerCtx): boolean;     // 护栏（A-07）
  run(ctx: ActionCtx): void | Promise<void>;
}
```

**扩展性判据（这条是本轮最该被 review 的一条）**：新增一个动作时，需要改动的文件数 **≤2**（注册表 + 可选的 1 个 `services/` 函数）。改到第 3 个文件（尤其改到 `src/components/**`）即视为未留扩展空间。
