## 一、用户原话（需求正本，不得改写语义）

1. 界面分为**悬浮条**、**主界面**两个窗口；Timing 原**设置窗口移至主窗口界面**，对 UI 等进行融合。

   可在设置菜单**开启不同的手柄**，并将手柄**绑定不同快捷功能**（如唤出主界面、同步等）。
   功能选择应**留好扩展空间**，便于新增不同功能。**每个手柄最多支持绑定五种动作**的功能：
   左键单击、右键单击、中键单击、左键双击、右键双击。
3. 现在手柄**左侧的图标删除**，其功能**移入手柄功能**中。

## 四、硬约束（违反即返工，评审必查）

1. **单文件 ≤300 行**（`check:size` 逐文件棘轮 `scripts/size-allowlist.json` 152 条，只许减不许增；新文件必须 ≤300）。
2. **层门禁 L1–L9**（`check:layers`）：`src/components/**` 不许出现 `ipc.`（ADR-017，动作必须落 `src/services`）；窗口 API 只许 `src/lib/windowApi.ts` 引用；L9 双窗隔离（主窗 310 / 分析窗 411，唯一例外 `src/lib/windowApi.ts`）。
3. **契约门禁**（`check:contract`）：命令表 `#[cfg(desktop)]` 80+117 / `#[cfg(not(desktop))]` 80，事件 17，emit 点 11。**加 IPC 命令要改四处**（`lib.rs generate_handler!`、`src/services/ipc.ts`、`src/types/domain/ipc.ts`、`src/mocks/browserMockPlugins.ts`）+ 四处文档（`docs/phase2/IPC-CONTRACT-v2.md` 命令表/详解/变更记录/手机端行为表）。
   —— **优先不加命令**：手柄动作只用前端能力，落点复用 `open_patina_window` 的 `target`。
4. **品牌门禁**（`check:brand`）扫注释里的旧品牌名（`src-tauri` 改名前的那个）；`check:vendored --upstream` 要求未登记漂移 = 0（本轮若动 `src/{app,features,platform,shared}` 下 Patina 文件，必须登记）。
5. **`src-tauri/src/app/insight/bootstrap.rs` 正好 300 行，再加一行就红**。
6. **release 是 `panic = "abort"`**：用户可达路径禁止 `expect`/`unwrap`；构造失败回 `Result`，界面出红字。
7. **手势互不干扰**：手柄 pointerdown 必须继续冒泡给 `PillBar` 的拖动判定（拖动起来后 click 被 `drag.onClickCapture` 吞掉）；新增的单击/双击/中键判定不得破坏"按住手柄拖窗口"。
8. **中键在 WebView2**：`auxclick`（button===1）才可靠，`pointerdown` 的 button===1 可能伴随自动滚动，需 `preventDefault`。
9. **双击与单击冲突**：双击必须"延迟单击"（约 220–280ms 判定窗），且双击不得触发两次单击动作；同一手柄的 5 个槽位互斥。
10. **设置持久化**：外观偏好走 `localStorage`（`src/stores/appearanceStore.ts`，键 `timing.appearance.v1`）；参与业务判定的设置走 Rust `settings` 表 + `update_settings`。手柄绑定属显示/交互偏好 → 走 localStorage 扩展 `appearance`，**不进 Rust settings**（除非设计另有裁决并同步 schema）。
11. **文档同步清单**：`CHANGELOG.md`、`更新日志.md`（代码仓）、`docs/phase2/IPC-CONTRACT-v2.md`（若动契约）、`README.md`（结构树/命令数）、`scripts/size-allowlist.json`（若新增文件）。
