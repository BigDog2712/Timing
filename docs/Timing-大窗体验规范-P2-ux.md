# Timing 主窗口大窗 · 体验规范（Phase 2 / ux）

> 范围：分析窗（main）大窗，含首页(dashboard)、数据(data/history)、设置(settings)、映射(mapping)、关于(about)。
> **悬浮条 / 把手簇小窗本轮冻结**，本规范不涉及其形态与交互，仅在"入口整理"里继承 13 个 handleCatalog 持久化键的既有语义。
> 本规范只定义体验（信息层级 / 入口优先级 / 流程 / 状态机 / 无障碍），不写代码、不改视觉数值；视觉数值一律引用 Phase 1 结论。
> 优先级：P0=本轮必须落地且可验收；P1=本轮应做、可小步；P2=方向正确、排期可延。

## 0. 现状盘点（基于当前代码，作为重排依据）

大窗真实结构（来自 `AppShell.tsx` / `AppTopNav.tsx` / 各 feature）：

- **导航**：标题栏 `AppTitleBar`（品牌 114 + `TimingCapsule` 计时胶囊 + mini/最小化/最大化/关闭 152）+ 顶栏三区 `AppTopNav`（主界面 / 数据 / 设置，**仅图标**，`aria-current="page"`）。
- **View 枚举**：`dashboard | history | data | mapping | settings | about`，经 `TAB_BY_VIEW` 收敛到三个高亮区（history/data/mapping→数据，settings/about→设置）。
- **首页**：自由摆位画布（`DashboardBoard`），8 种卡 timer/apps/timeline/manage/notes/trend/heatmap/reminder，三列栅格 340/330/500、PAD24/GAP16，每卡 S/M/L 三档。
- **数据**：`DataHistoryFaces` 两副面孔（概览 data / 历史 history），概览含趋势 `DataTrendPanel`+热力 `DataHeatmapPanel`+目的地 `DataAppTrendPanel`（应用/分类/标签/网页四维）。
- **设置**：五组网格 + 左锚点导航 `SettingsGroupNav`，锚点表见 `settingsGroups.ts`（s-tracking / s-theme·s-highlight·s-display / s-pill-handles·s-pill-look / s-sync·s-backup / s-general·s-resident·s-plugins·s-ai）。

诊断（对应用户四痛点中我主攻的两条）：

- **信息层级混乱**：三页都已把视觉页头下线（只留 `sr-only` h1），层级完全依赖卡/面板内部，缺少"一眼先读到什么"的统一主次口径；首页自由摆位默认布局没有权重顺序约束；数据概览三块（趋势/热力/目的地）视觉权重接近，无主图表概念；设置五组内部卡高相近、无"高频先触达"的落点提示。
- **组件分布不均**：首页画布三列 340/330/500 本身是均衡基，但卡可自由摆、可留大空洞；数据页 `data-dashboard-grid` 概览块与目的地块高度/对齐无统一基线；设置网格单列顺排、长卡短卡交替产生节奏跳动。

## 1. 信息层级重排（P0）解决"信息层级混乱"

统一三级口径（对接视觉 Phase 1 的"字号差 + 字重 400/700 + 留白"，层级不靠灰阶、不靠强调色堆叠，一屏强调色面板 ≤2）：

| 级别 | 含义 | 体验承载手段（位置/大小/留白/首屏顺序） |
|---|---|---|
| **Primary（主）** | 进页面 1 秒内必须读到的那一个"答案" | 首屏第一行、最大字号档、字重 700、周围留白最大；每页**唯一** |
| **Secondary（次）** | 支撑主信息的分解/排行/走势 | 首屏可见、中字号、字重 400、常规 gap |
| **Tertiary（辅）** | 管理类、低频、设置性入口 | 下沉第二屏或收进菜单/弹层、最小字号、弱化留白 |

### 1.1 首页 dashboard 的三级（P0）
- **目标**：首屏权重落到 Phase 1 建议的 2:5:3 = 一行统计/计时 + 一个主图表 + 事项卡头。
- **做法**：
  - Primary = **今日已计时总量 + 计时分布环**（`timer` 卡）。放画布左上第一列顶部（x=24,y=PAD），M 档。
  - Secondary = **活动趋势 `trend`**（主图表，宽列 500/L 档）+ **应用排行 `apps`**。
  - Tertiary = `manage`（事项管理）、`notes`（便利贴）、`heatmap`、`reminder` 下沉到第二屏或非首列。
  - 自由摆位不强制锁位，但**出厂/重置默认布局**按上表排；用户自定义后不回拨。
- **影响范围**：`dashboard` 默认布局（前端层 `normalizeLayout`/出厂 layout 数据，不改卡实现）。
- **验收标准**：
  1. 出厂/重置后读取默认布局：`timer` 卡 `y` 为全画布最小且位于首列（x=24）。
  2. 首屏（BOARD_H=820 设计高内）可见卡集合包含且仅重点含 {timer, trend, apps}，其余卡 `y+h` 任一超过 820 或不在首屏首要位置。
  3. 每页 DOM 中 `h1`/主标题区域语义唯一（`sr-only` h1 仅 1 个）。

### 1.2 数据 data 概览的三级（P0）
- **目标**：概览从"三块等权"变成"一主图 + 两辅"。
- **做法**：Primary = 趋势 `DataTrendPanel`（主图表，占概览块首位、最大高度）；Secondary = 热力 `DataHeatmapPanel`；Tertiary = 目的地 `DataAppTrendPanel`（应用/分类/标签/网页，可滚动在下）。概览面与历史面切换沿用 `DataHistoryFaces` 面签，不新增导航路径。
- **影响范围**：`data-dashboard-grid` / `data-overview` 的布局顺序与高度分配（CSS 与结构顺序，不改读模型）。
- **验收标准**：概览首屏趋势图高度 ≥ 热力图高度；目的地面板起始 `offsetTop` 大于趋势与热力（即位于其后）。

### 1.3 设置 settings 的三级（P0）
- **目标**：高频组先触达，低频"设一次"项明确靠后，锚点导航承载层级可发现性。
- **做法**：沿用 `settingsGroups.ts` 既定五组顺序（计时行为→外观→悬浮条与把手→数据与同步→通用与启动），**不改 id、不改顺序**；在体验上明确：Primary=第 1 组"计时行为"（每次调时长都碰），Secondary=外观/数据与同步，Tertiary=悬浮条与把手、通用与启动（设一次）。锚点导航 `SettingsGroupNav` 常驻，组内任一项 ≤2 层深（既有硬约束）。
- **影响范围**：无结构改动，仅确认现状即达标 + 文档化口径。
- **验收标准**：`SETTINGS_GROUPS[0].id === "tracking"`；每个锚点 `id` 在 DOM 中存在且可 `scrollIntoView`（`settingsGroups.source.test` 的 DOM_ORDER 已覆盖）。

## 2. 组件分布均衡的体验规则（P1）解决"组件分布不均"

配合视觉 Phase 1 的 1:1 卡内距、密度两档（标准 padding16/gap16/行30，紧凑 padding12/gap12/行26，窗宽 1040 阈值自动切）。

### 2.1 区域划分（三页统一）
- 每页分三带：**头带**（工具条/面签，`flex-0-0-auto`）/ **主带**（滚动内容）/ **叠层**（toast、弹层，fixed 不占流）。现状 `AppShell` 已是此结构，本规则做口径固化。
- **验收**：每页根容器存在且仅存在一个滚动主带（`at-scroll-region` 或等价），头带不随主带滚动。

### 2.2 对齐基线
- **做法**：
  - 首页画布一切落点对齐三列栅格 COLUMNS（x=24/380/726）与 SNAP=8，`整理` 按钮把卡吸附回栅格，消除"卡悬空错位"。
  - 数据概览块与目的地块**左边界对齐**同一内容左缘；统计卡网格按 Phase 1 容器查询列数（≥1200→4 / 1040–1199→4紧凑 / 860–1039→3 / <860→2）。
  - 设置所有卡统一左右内边距与组间距（走密度档令牌），卡宽占满单列网格。
- **影响范围**：布局 CSS 与"整理"行为（不改卡实现）。
- **验收**：首页"整理"后任一卡 `x ∈ {24,380,726}` 或其叠放列、且 `(x,y,w,h) % 8 === 0`；数据概览块与目的地块 `offsetLeft` 相等；设置相邻卡间距差 ≤1px。

### 2.3 留白节奏
- **做法**：同层级元素用同一 gap（标准 16 / 紧凑 12），层级切换才换留白；禁止用"加一个空卡/空 div"占位制造间距。一屏强调色面板 ≤2（继承视觉口径）。
- **验收**：同一网格内相邻项 gap 恒定（单值）；页面内带强调背景的面板计数 ≤2。

## 3. 核心功能入口整理与优先级（P0）减少重复操作

### 3.1 入口盘点与优先级

| 入口 | 当前位置 | 频率/重要性 | 定级 | 处置 |
|---|---|---|---|---|
| 查看今日计时分布 | 首页 timer 卡 | 极高 | **P0** | 首屏常驻（§1.1 Primary） |
| 开始/暂停/切换事项计时 | 首页 manage/timeline 行点击起停 + 悬浮条把手(冻结) | 极高 | **P0** | 首屏常驻，大窗内保留行点击起停 |
| 看今日趋势/排行 | 首页 trend/apps + 数据概览 | 高 | **P1** | 首屏次级 |
| 进入数据/历史 | 顶栏"数据"→面签切历史 | 高 | **P1** | 顶栏一级 + 面签，保持单一路径 |
| 改计时规则（时长/合并间隔） | 设置→计时行为 | 中高 | **P1** | 设置第 1 组 |
| 分类映射管理 | 首页"全部分类…"→mapping / 数据页双击应用 | 中 | **P1** | 见 §3.2 合并 |
| 改外观/主题/语言 | 设置→外观 | 中 | **P2** | 设置第 2 组 |
| 悬浮条与把手绑定 | 设置→悬浮条与把手 | 低（设一次） | **P2** | 设置第 3 组 |
| 同步/备份/数据清理/导入导出 | 设置→数据与同步 | 低 | **P2** | 设置第 4 组 |
| 常驻/启动/插件/AI | 设置→通用与启动 | 低 | **P2** | 设置第 5 组 |
| 关于/反馈 | 设置区（about） | 低 | **P2** | 设置高亮区内 |

### 3.2 重复入口与合并建议（P0 识别 / P1 落地）
- **分类/标签入口分散**：首页 `onOpenMapping`（"全部分类…"）跳 mapping 视图；数据页双击应用行开"标签编辑"（`AppTagDialog`）；mapping 视图又有完整分类管理。
  - 建议：**统一"修改单个应用的分类/标签"走同一弹层**（数据页已是双击→标签弹层），首页/概览的"全部分类…"只作为"进入完整管理"的唯一入口指向 mapping，避免两套单项编辑 UI。
  - 验收：大窗内"单个应用改分类/标签"的触发点均打开同一组件（同一 `AppTagDialog`/标签弹层），不存在第二套单项分类编辑对话框。
- **历史入口**：当前历史只经"数据→面签历史"或"概览点某天柱子"进入，已在 `DataHistoryFaces` 收敛为单一路径，**保持**，不要再加第二条导航。
  - 验收：`history` 视图只由面签 `onSelect` 或 `onOpenHistoryDate` 两处进入，无独立顶栏项。

## 4. 关键交互流程简化（P0/P1）

取三条高频流程，给简化前后步骤对比。"步数"按用户可感知的点击/跳转计。

### 4.1 流程 A：看今日统计（P0）
- **简化前**：打开大窗 → 若落在"数据"或"设置" → 点顶栏"主界面" → 在画布里找 timer 卡（默认可能被摆在非首屏）。最坏 2 跳 + 1 次视觉搜索。
- **简化后**：大窗启动默认恢复到 `dashboard`，timer 卡固定首屏左上（§1.1）→ **0 跳直达**，落点即答案。
- **怎么减**：默认视图 + 默认布局首屏权重两件事保证"打开即见"，不依赖用户记卡位置。
- **验收**：冷启动（无上次视图记录）`currentView==="dashboard"`；默认布局 timer 在首屏首列顶部（复用 §1.1 验收 1/2）。

### 4.2 流程 B：新建 / 切换事项并开始计时（P0）
- **简化前**：首页 manage 卡 → 找到事项 → 点行起停；新建需进"新增·编辑"对话；切换当前计时事项需先停再在另一行起。
- **简化后**：
  - manage 卡行点击 = 一次点击一条意图（方向由 `useItemTimerToggle` 判，已实现），**切换事项不需手动先停**——点另一行即切。
  - 保证 manage 卡在首屏可达（Secondary/首屏可见，不必在第二屏）。
- **怎么减**：把"停当前 + 开目标"合成单次行点击语义；新建入口在卡头常驻一个按钮，避免进二级菜单找。
- **验收**：在 manage 卡点击非计时行，发出的意图只有一条（切换），无需用户额外点"停止"；新建入口在 manage 卡头一次点击可达。

### 4.3 流程 C：改一项设置（P1）
- **简化前**：顶栏"设置" → 在五组长页滚动找目标卡 → 改 → 保存。
- **简化后**：顶栏"设置" → 左锚点导航 `SettingsGroupNav` 一步跳到目标组（组内第一张卡即高频项）→ 改 → 工具条保存/取消常驻可见。
- **怎么减**：锚点导航把"滚动搜索"换成"一步定位"；任一项 ≤2 层深（硬约束）；保存/取消从页头搬到 `QuietPageToolbar` 常驻。
- **验收**：点任一锚点后目标卡滚入视口且 `aria-current` 落在对应组；"保存/取消"在设置页始终可见（不随滚动离场）。

## 5. 大窗内各面板/控件状态机（P0）

> 这是**大窗内面板与控件**的状态机，不是悬浮条状态机。状态取值与触发条件如下；每个状态给客观可判据的体验表现。全组件 default/hover/active/focus/disabled 的视觉语义令牌由 Phase 1 锁定，本节只定义**何时进入该状态 + 该状态下显示什么内容**。

### 5.1 数据读取型面板（timer/apps/trend/heatmap、数据概览、数据目的地）
统一七态（以 `readState.status` + 快照有无为准，现状 Dashboard/Data 已部分实现，这里固化口径）：

| 状态 | 触发条件 | 体验表现（可判据） |
|---|---|---|
| **加载 loading** | 首次拉取、无任何快照 | 面板 `aria-busy="true"`，显示骨架/占位，不显示旧数；不出现"空"文案 |
| **就绪 default** | 有数据且无刷新错误 | 正常渲染，`aria-busy` 去除 |
| **刷新中（有旧数）** | 有快照、后台刷新进行中 | 保留旧数可读，仅卡头轻提示；**不**整面覆盖 |
| **刷新失败（有旧数）E3** | `status==="error"` 且 `hasSnapshot` | 保留旧数 + 卡头小错误标 + 可"重试"；不清空 |
| **读取失败（无数据）E2** | `status==="error"` 且无快照 | 面板内一块错误 + "重试"按钮；仅该面板，不波及同页其它面板 |
| **整页失败 E5** | 全源失败**且**首屏零数据（`!hasAnyData`） | 整页 notice + 重试；有任一局部数据（待办/便利贴）时降级为"局部 E2 + 其余正常"，**禁止**整页覆盖 |
| **空态 empty** | 加载成功但无记录 | 解释性空文案；计时卡空态须用 `excludedToolTime` 解释"今天只有工具类应用(xh)"，不可只写"还没有记录" |
| **焦点恢复** | 重试后按钮消失、焦点落回 body | 焦点送回重试键/面板（`returnRetryFocusRef` 口径） |

- **验收**：
  1. E2 只影响触发面板：构造单面板 error + 其它面板有数据，其它面板仍 default。
  2. E5 需同时满足 error 且 `hasAnyData===false`；待办或便利贴非空时不得整页覆盖。
  3. 计时卡在"全工具类应用"日空态文案包含被排除时长数值。

### 5.2 面签 / 导航型控件（顶栏三区、数据面签、设置锚点）
| 状态 | 触发 | 表现（可判据） |
|---|---|---|
| default | 非当前 | 普通态 |
| **激活/选中** | 当前视图命中 | 顶栏三区用 `aria-current="page"`；数据面签用 tabs 语义选中；设置锚点 `aria-current` 落当前组 |
| hover/focus | 指针悬停/键盘聚焦 | 可见焦点环（不靠灰阶区分，走 Phase 1 focus 令牌）；预加载在 focus/mouseenter/pointerdown 触发，**不**在此改激活态 |
| 加载中（导航） | 目标 chunk 未就绪 | 保留旧视图直到就绪再切（现状口径），不显示白屏 |
- **验收**：顶栏三区恰有一个 `aria-current="page"`；键盘 Tab 可达每个 tab 且有可见焦点样式。

### 5.3 可编辑/动作型控件（设置项、保存/取消、不可逆动作）
| 状态 | 触发 | 表现（可判据） |
|---|---|---|
| default | 常态 | 可操作 |
| disabled | 条件不满足（如语言切换 pending、无未保存更改） | **深色禁用态不降文字透明度**（Phase 1 硬口径），改降背景对比 + `cursor:not-allowed`；保存按钮在无变更时禁用 |
| 处理中 pending | 异步进行（保存/语言预载） | `aria-busy`，期间保存被 gate 住返回 false，防重复提交 |
| **不可逆确认** | 结束并保存、数据清理、删除 | 必须二次确认（`useQuietDialogs` confirm）；不可逆动作不进任何"单击即执行"路径（继承 handleCatalog：`timer.stop` 不在出厂单击槽） |
| 脏态 dirty | 有未保存更改 | 保存/取消可用；离开视图前 `confirm` 拦截（`setSettingsDirty`/`setMappingDirty` 已有） |
- **验收**：
  1. 无未保存更改时保存按钮 disabled。
  2. 语言切换 pending 期间 save handler 返回 false（现状 `languageSelectionPendingRef` 已实现）。
  3. 数据清理/导入/结束保存均经 confirm 弹层，无直接执行路径。

## 6. 无障碍清单（a11y）

贯穿三页，继承现状已有口径并补齐：

- **可访问名**：顶栏三区图标按钮带 `aria-label`+`title`（现状已有）；每页保留 `sr-only` h1 作为页名。
- **语义正确**：顶栏三区是站点级目的地→`<nav>`+`aria-current="page"`，**不是** tablist；数据概览/历史是同上下文换面板→tabs 语义。两者不混（现状口径）。
- **键盘可操作**：所有入口（导航、面签、锚点、行点击起停、新建、保存/取消）可 Tab 到达并回车/空格触发；焦点顺序跟随 DOM 主次顺序（Primary→Secondary→Tertiary）。
- **焦点可见**：焦点环走 Phase 1 focus 令牌，深色不靠灰阶；重试后焦点回落到重试键/面板。
- **对比度**：禁用态深色不降文字透明度（纯白），靠背景对比区分（Phase 1 硬口径）；层级靠字号+字重+留白，不靠灰阶。
- **读屏反馈**：加载面板 `aria-busy`；错误/空态用 `role="status"`/`role="alert"`；toast 不抢焦点。
- **动效降级**：尊重 `quietMotionMode`（现状 `data-at-motion`），减少动画偏好时关装饰动效。

**验收（客观）**：
1. 键盘仅用 Tab/Shift+Tab/Enter/Space/方向键可完成 §4 三条流程，无鼠标依赖。
2. 顶栏三区恰一个 `aria-current="page"`；锚点导航恰一个 `aria-current`。
3. 每个可交互控件有可访问名（axe/脚本扫描无 "button has no accessible name" 违规）。
4. 开启"减少动态效果"后，`data-at-motion` 反映为降级值，装饰性过渡不触发。

## 7. 高风险交互与降级方案

| 高风险点 | 风险 | 降级方案 |
|---|---|---|
| 首页默认布局重排 | 改动默认布局数据可能影响老用户已存布局 | **只改出厂/重置默认**，归一化优先读用户已存布局；老用户升级不回拨（与 handleCatalog 同纪律） |
| E5 整页覆盖 | 判据写宽会把"局部失败"误判成整页失败，用户以为数据全丢 | E5 必须 `error && !hasAnyData`；待办/便利贴非空即降级为局部 E2 |
| 入口合并（分类/标签） | 合并单项编辑入口可能漏掉某条调用点 | 先只统一"单个应用改分类/标签"的弹层，不动 mapping 完整管理；分阶段灰度 |
| 数据概览三块重排 | 调高度/顺序可能破坏容器查询断档 | 断档列数沿用 Phase 1，不随本次重排改；只调顺序与相对高度 |
| 不可逆动作路径 | 新增入口时误把结束保存/清理挂到单击 | 所有不可逆动作强制经 confirm；CI/测试断言无"单击即不可逆" |
| 设置锚点漂移 | 挪卡未同步 `settingsGroups.ts` 导致点锚点跳空 | 锚点 id 与卡 id 同批改，`settingsGroups.source.test` DOM_ORDER 把关；id 不可改名 |

## 8. 与视觉 / 前端的对齐约定

- **对视觉**：三级层级落到你的"字号差 + 字重 400/700 + 留白"；本规范不出具体 px，强调色面板一屏 ≤2、禁用态口径均引用你的 Phase 1 令牌。若 timer/trend 需要"主图表"更大字号档，请在你的字阶里给一档可复用的 Primary 标题级。
