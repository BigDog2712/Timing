1. 标签是 **Obsidian 式**：可分级（`学习/考公`、`娱乐/视频`），**同一应用、同一事项可打多个标签**。
2. 「第二个界面」= 分析窗的 **「数据」与「历史」** 两页。
3. 直接在当前工作区改，不动 git。

## 1. 产品目标

1. **一套标签，处处一致**：应用、网站、事项共用同一个分级标签库；增删改（含重命名/删除）一次操作，所有关联对象与两个窗口同时生效。
2. **在看数据的地方就能打标签**：在「数据」「历史」里看到某个应用/事项时，两次点击内完成加标签，无需跳转映射页或主窗。
3. **AI 可用、可信、可理解**：AI 建议标签/今日汇总的成功率显著提升，失败时用户能看懂原因并知道下一步怎么做；任何情况下不写坏数据、不泄露密钥。

## 3. 核心口径与关键判断

### 3.1 标签的身份与存储（明确判断）

- **用户可见身份 = 标签路径**（`学习/考公`）。路径全局唯一，比较时忽略大小写、忽略首尾空白与前导 `#`、`\` 视同 `/`。
- **应用/网站侧继续引用分类键**（内置 `ai`…`utility`、自定义 `custom:…`），键的显示名（label override / 自定义定义）即标签路径。
  理由：统计、颜色、跨设备同步、导出包全部按键工作，改成存路径会让整条统计链路与历史数据回归；键稳定也让「重命名」只是改一条显示名。
- **事项侧继续存路径**（`items.tags` JSON 数组，0.12.3 半成品现状）。
  理由：事项行随全额数据包跨端，手机端没有分类目录（桩回空）也能直接显示可读标签；导出包自解释。
- 两侧通过「路径」对齐：同一路径在标签库中只对应一个键；事项打了一个标签库里不存在的路径时，**自动登记**为自定义标签（「输入即创建」）。
- 层级是**隐式**的（Obsidian 语义）：`学习/考公` 存在即意味着树上有「学习」节点；父节点本身可以被直接打在对象上，也可以只作为分组。
- 规格上限：路径 ≤ 64 字符、≤ 4 级、单段 ≤ 32 字符；单对象 ≤ 12 个标签（UI）/ 32（服务端兜底，沿用现值）。`other`/`system` 不是标签（「无标签」由空集合表达）。

### 3.2 统计口径（明确判断：**主标签沿用分类口径，多标签做增量**）

- **主标签 = 应用标签集合的首项 = 现有 `category` 字段**（`buildQuickAppOverride` 的不变式 `category == categories[0]` 保持）。数据页、看板、分类趋势、时间线、按小时活动等所有现有按「分类」聚合的地方，**一律按主标签聚合，口径与结果与改造前逐字节一致**。
- 理由：
  1. 现有图表（堆叠趋势、占比、看板）依赖「互斥且完备」的划分——一段时间只属于一个桶，合计 = 总时长。多标签直接聚合会重复计时，合计 > 总时长，所有占比失真；
  2. 现有 `dataCategoryTrendReadModel` / `activityTimelineCompiler` / `hourlyActivityCompiler` 与大量回归测试锚在单值口径上，保持主标签口径即零回归；
  3. 用户从单选分类迁移过来，原分类天然就是主标签，数据连续不断档。
- **多标签作为增量**（P1）：
  - **按标签筛选**：在数据/历史页选一个或多个标签过滤对象（命中任一即显示），图表仍按主标签分桶，只是对象范围变小；
  - **单标签视角**：选中某个标签时显示「该标签总时长」= 带此标签（含其子标签）的对象时长之和，并标注「与其他标签可能重叠，不参与合计」；
  - **父标签汇总**：父节点时长 = 子树内对象时长的**并集**（同一对象只算一次）。
- 事项：事项本身就是统计维度，标签不改变事项统计；事项上遗留的 `categoryKey` 字段继续保留且不在 UI 暴露，但分类传播时必须按 mapping 写入目标键，删除映射到 `NULL`。多标签仍只影响 `items.tags`，不把 `categoryKey` 派生为首个标签。

### 3.3 即时生效口径

- 同窗：保存后 ≤ 100 ms 乐观更新芯片；后端失败则回滚并提示。
- 跨窗：保存成功后由宿主广播变更事件，另一窗 ≤ 1 s 内刷新标签目录与芯片，**不需要重开窗口或卡片**（主窗管理卡当前「挂载时取一次」需改为订阅）。
- 统计视图：标签变更后当前页数据重新派生（只重算受影响部分，不整页闪烁/不重置滚动与选中状态）。

## 5. 数据迁移与兼容

### 5.1 旧分类 → 标签映射

| 旧数据 | 映射为 | 处理 |
|---|---|---|
| 内置分类键 `ai`…`utility` | 内置标签，路径 = 当前显示名（有 `__category_label_override::` 用覆盖名，否则用 `AI/开发/办公…`） | 键不变，无需改写 |
| 自定义分类 `__custom_category::custom:*` | 自定义标签，路径 = 显示名 | 键不变；显示名含 `/` 的**自此按层级解释**（发版说明写明） |
| 颜色 `__category_color_override::` | 标签颜色 | 原样沿用 |
| 已删除 `__deleted_category::` | 隐藏标签（不进候选/管理列表，内置可恢复） | 引用它的应用照旧按「无标签」显示，与现状一致 |
| 应用 `__app_override::` 的 `category` + `categories[]` | 应用标签集合，`category` = 主标签 | 原样沿用，无改写 |
| 网站 `__web_domain_override::` 的 `category` | 网站主标签（单值） | 原样沿用 |
| 事项 `items.tags`（路径数组，0.12.3 半成品） | 事项标签 | 原样沿用；库里没有的路径首次读取时自动登记 |
| 事项 `items.categoryKey`（旧单选） | 若该事项 `tags` 为空且 `categoryKey` 指向未删除的标签 ⇒ **一次性种入**该标签路径 | 幂等，用 settings 标记位只跑一次；字段继续保留；后续 rename/merge/delete 传播按 mapping 写入目标键或 `NULL` |

- **不改任何历史 `.sql`**。优先不改表（KV + 现有 JSON 列已够用）；若架构需要新表/列，业务库用 `0018_*`，活动库按其自身序号（当前到 `0030`）新增，并登记 schema registry。
- 迁移失败不得阻塞启动：失败记日志并在下次启动重试，界面按「未迁移」降级显示（事项仍显示原路径）。

### 5.2 跨设备同步 / 导出包

- KV 键前缀、`items.tags` JSON 格式、应用 override JSON 形状**不变**；旧版本客户端读新数据：标签显示为带 `/` 的扁平名，不崩、不丢字段。
- 新版本导入旧导出包：按 5.1 映射即可，不要求包版本升级。
- 重命名/删除传播产生的事项改写必须推进 `updated_at_ms`（`items.tags` 与 `category_key` 均须纳入实际触发器/写入口），保证跨设备合并取到新版本；应用侧 KV 改动走现有同步通道。
- `focus_blocks.category_key` 是 Activity 库中的投影快照，不是传播真源；业务库改写完成后由 projector 重建/更新，不由传播服务直接把它当第二个真源编辑。
- 两设备并发：同一事项标签以 `updated_at_ms` 新者为准（沿用现有整行合并策略，本期不做字段级合并，写入 Open Questions）。
- 业务 SQLite 与独立 Activity SQLite 无跨库事务原子性；传播通过可恢复 journal 分阶段提交。单库阶段可按单库批量指标验收，跨库失败需显示待恢复/失败状态，不宣称跨库原子。

### 5.3 手机端

- 分类目录桩回空：事项标签直接显示路径；不出现 `custom:category_ab12…` 这类原始键。
- 新增的宿主命令在手机端必须有桩，返回带错误码的「不支持」并有 `errorText()` 文案；AI 桩返回「手机端暂不支持 AI」类错误码，界面不崩、按钮置灰。
- 手机版号不变。

## 6. AI 对接非功能需求

> 范围：`services/ai/{client,config,prompt,suggest,daily}.rs` 与三个前端入口（主窗事项 AI 建议、分析窗应用 AI 建议、设置 → AI）+ 今日汇总。

| ID | 维度 | 要求 |
|---|---|---|
| A-01 | 错误分类 | 后端把失败归为**有限且稳定的错误码**（新增 ErrorCode，每个都有 `errorText()` 中文 case）：`AI_NOT_CONFIGURED`（未配置/总开关关）、`AI_DISABLED`（对应入口开关关）、`AI_AUTH`（401/403/密钥无效）、`AI_RATE_LIMITED`（429/配额）、`AI_NETWORK`（DNS/连接/TLS/代理）、`AI_TIMEOUT`、`AI_UPSTREAM`（5xx/供应商过载）、`AI_BAD_REQUEST`（400/模型不存在/上下文超长）、`AI_PARSE`（返回无法解析/空内容/拒答）、`AI_CANCELLED`。不再统一用 `IO_ERROR`。 |
| A-02 | 文案 | 每类给「原因 + 下一步」：如 `AI_AUTH` →「API 密钥无效或无权限，请到 设置 → AI 检查密钥与模型」。供应商原话作为「详情」可展开，**截断 ≤ 200 字并脱敏**。 |
| A-03 | 重试与退避 | 仅对 `AI_NETWORK` / `AI_TIMEOUT` / `AI_RATE_LIMITED` / `AI_UPSTREAM` 重试；最多重试 2 次（共 3 次尝试）；指数退避 1 s、2 s，±20% 抖动；有 `Retry-After` 时遵从但单次 ≤ 10 s；鉴权/400/解析失败**不重试**（A-20 的纠正重试除外）。 |
| A-04 | 超时分级 | 连接超时 10 s；测试连接 / 模型列表单次 15 s；标签建议单次 45 s；今日汇总单次 90 s；每次调用（含重试）设总预算：测试 30 s、建议 120 s、汇总 180 s，超预算即 `AI_TIMEOUT`。 |
| A-05 | 响应解析容错 | ① 剥离 ``` 围栏（含 `json` 语言标记）与 `<think>…</think>` 推理块；② 容忍前后缀杂文，提取第一个完整 JSON 对象/数组（括号配平，不是简单首 `{` 末 `}`）；③ 字段别名：根 `suggestions`/`results`/`data`/`items` 或根数组，条目 `id`/`targetId`/`target`，标签 `tags`/`labels`/`categories`；④ `tags` 为逗号/顿号分隔字符串时拆分；id 数字/字符串皆收；⑤ **部分合法**：逐条校验，合法条目保留，非法条目丢弃并计数；⑥ 未知标签丢弃、超上限截断、去重；⑦ 全部条目都非法 ⇒ `AI_PARSE`（不是静默返回空）；合法但 AI 认为无标签 ⇒ 正常返回空并提示「AI 没有把握，未给出建议」。 |
| A-06 | 解析结果可见 | 建议接口返回 `{suggestions, stats:{parsed, dropped, attempts}}`（或等价字段），前端在预览里显示「已解析 N 条，忽略 M 条」。 |
| A-07 | 并发与取消 | 每个入口同一时刻只允许 1 个在途请求（重复点击无效且按钮显示进行中）；全局 AI 并发 ≤ 2；用户可点「取消」，取消后丢弃迟到响应、不落任何写入，返回 `AI_CANCELLED` 且不弹错误；窗口关闭/卡片卸载即取消。超过 40 个对象自动分批顺序请求，部分批次失败时保留成功批次并提示失败数。 |
| A-08 | 密钥安全 | 密钥只进请求头；日志只记 `{入口, 模型, 错误码, HTTP 状态, 尝试次数, 耗时}`；所有对外文案与日志对 `sk-…`、`Bearer …`、`api_key=…` 及配置中的密钥原文做脱敏；单元测试覆盖「错误文案不含密钥」。 |
| A-09 | 写库纪律 | AI 结果**永远先进预览**，用户确认后才写；写入走与手动打标签同一条命令（同一归一、同一传播、同一事件）。 |
| A-10 | 可测试性 | `client` 层可注入模拟传输（不依赖真实网络）以测重试/超时/分类；`prompt` 解析层用固定文本用例覆盖 A-05 每一条。 |

## 7. 工程与非功能约束（硬约束）

- 单文件 ≤ 300 行（棘轮，只降不升）；超长文件借本次改造拆分（如 `quickClassification.ts`、`classificationStore.ts`、`Data.tsx`、`History.tsx` 中被触及的部分）。
- 分层只向下（前端各窗、后端六层 ADR-016）；**双窗互不 import**，标签归一 / 树构建 / 芯片样式等两窗共用逻辑放 `src/windows/shared/`（建议 `shared/tags/`），并与 Rust 归一规则做 parity 测试。
- 改表必须新增迁移、不改历史 `.sql`（业务库下一个 `0018`）。
- IPC 契约四处一致（`ipc_commands.rs`、前端 ipc 封装、mock、契约文档）；新增事件同步更新事件契约计数。
- 新增错误码必须有 `errorText()` case（两窗都要能显示）。
- 版本：桌面只递增末位；手机不动（见 Q-6）。写 `CHANGELOG.md`，`更新日志.md` 只追加。
- `npm run check` 与 `cargo test` 全绿；现有分类相关测试改名不改断言语义（统计结果必须一致）。
- 性能：500 个标签 + 1000 个应用 + 500 个事项下，标签管理面板首屏 ≤ 150 ms，标签选择浮层打开 ≤ 50 ms，单库批量阶段 ≤ 1 s；跨库传播采用 journal/outbox 可恢复流程，不承诺跨库原子或固定端到端耗时；数据/历史页加入芯片后首屏渲染耗时增幅 ≤ 10%。
- 风格：沿用 Quiet 组件（`QuietButton` / `QuietDialog`）与现有 token，不引入新 UI 库。

## 9. 验收标准

**标签基础**
1. 可创建 `学习/考公`，树上出现「学习」父节点且「考公」位于其下；输入 `#学习 / 考公 ` 与 `学习\考公` 归一为同一标签，不产生重复。
2. 给同一应用打 3 个标签、同一事项打 3 个标签，重启应用后仍在；两窗显示一致。
3. 超过 4 级 / 超过 64 字符 / 单对象超过 12 个时给出明确提示，不静默截断。

**传播**
4. 将 `学习` 重命名为 `教育`：所有 `学习/*` 变为 `教育/*`，受影响事项的 `items.category_key` 写入映射后的目标键；关联应用与事项的芯片、数据页、历史页、主窗管理卡均在传播完成并触发投影更新后刷新，无需重开。
5. 重命名到已存在路径时，preview 必须展示将触发的 `app_category(app_key, category_key)` 唯一键冲突明细（含占用方身份与字段快照）；存在任一此类冲突或 preview 指纹过期时整笔拒绝，不部分应用、不自动合并或覆盖；`block_segment_override(block_uid, app_key, seg_start)` 唯一键不含 `category_key`，不应作为该类冲突上报。解决冲突后重新 preview，确认无冲突才执行。
6. 删除有关联的标签前显示受影响数量与名称；确认后所有对象不再含该标签，受影响事项 `items.category_key` 写为 `NULL`；被删的是应用主标签时，下一个标签成为主标签，统计随之归入新主标签。跨库传播不承诺事务原子，失败进入可恢复状态并可重放。
7. 删除内置标签后可在管理面板恢复，恢复后原应用引用恢复显示。

**入口与即时生效**
8. 数据页应用趋势任一行、历史页应用/事项排行与记录任一行，悬停出现「＋」，≤ 2 次点击完成打标签。
9. 在分析窗给事项打标签后，主窗已打开的事项管理卡 1 s 内显示新标签（反之亦然）。
10. 后端写入失败时芯片回滚到原状态并显示错误文案。

**统计不回归**
11. 迁移前后，同一数据集上数据页、看板、标签趋势、时间线、按小时活动的数值**完全一致**（现有回归测试全部通过且断言不放宽）。
12. （P1）按标签筛选后合计 ≤ 未筛选合计；单标签视角显示「可能重叠」提示；父标签时长 = 子树对象并集（同一对象不重复计）。

**迁移兼容**
13. 旧库（含内置改名、自定义分类、颜色覆盖、已删除分类、应用多分类、事项 `categoryKey`）升级后：标签名称、颜色、应用归属、主标签全部保持；有 `categoryKey` 且无 `tags` 的事项被种入对应标签，仅一次。
14. 导入改造前的导出包成功且数据一致；旧版本客户端读取新数据不崩溃。
15. 手机端打开事项管理与 AI 入口不崩溃：标签显示为可读路径，AI 按钮置灰并有中文说明。

**AI**
16. 用模拟传输：网络错误/超时/429/5xx 前两次失败、第三次成功 ⇒ 用户拿到结果，无错误提示；连续失败 ⇒ 对应错误码与中文文案。
17. 401 ⇒ 不重试，显示「密钥无效」类文案并提供「去设置」。
18. 解析用例全部通过：带围栏、带前后缀杂文、带 `<think>` 块、字段别名、标签为逗号字符串、id 为数字、一半条目非法（保留合法的一半并显示忽略数）、全部非法（`AI_PARSE`）。
19. 进行中点「取消」⇒ 无任何写入、无错误弹出、迟到响应被丢弃；重复点击不会发出第二个请求。
20. 所有 AI 错误文案与日志中检索不到配置的密钥原文、`sk-` 前缀串或 `Bearer` 头。
21. AI 建议只包含已有标签；未经用户在预览中确认不落库。

**工程**
22. `npm run check` 与 `cargo test` 全绿；无文件超过 300 行；无跨窗 import；新增错误码均有 `errorText()` case；IPC 契约四处一致。
