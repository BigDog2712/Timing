# TickBar UIUX 设计文档 v1

> 阶段：Phase 1（设计调研 + 设计方向）
> 设计师：颜好看
> 日期：2026-10-16
> 产品：Windows 桌面悬浮轻量计时小工具（工作名 TickBar）
> 三轴刻度：**Variance = 7 / Motion = 5 / Density = 8**
> 设计寄存器：**Product Register（产品型）** — 设计服务产品，标杆是「赢得熟悉感」而非「独特性」。理由：这是一个常驻屏幕、每天被点击数十次的效率工具，任何需要"学习"的视觉都是负债。但常驻可见的特性又要求它具备可辨识的品牌个性，因此在「克制」的框架内保留一个高记忆度的品牌符号：**信号琥珀（Signal Amber）**。

## 0. 调研结论摘要（8 次联网调研）

### 0.1 同类工具的设计趋势（Timing / Toggl / Sunsama / Super Productivity / ShinyTimer / FloatingTimer）

| 观察 | 结论 | 对 TickBar 的指导 |
|---|---|---|
| Timing (macOS) 用**菜单栏小组件**显示时间，主体是"时间线"而非计时器 | 时间是"事后回看"的产物 | TickBar 反向切入：不做时间线，只做**当下这一刻的控制台** |
| Toggl Track 桌面版主操作是 `What are you doing?` 输入框 + 粉色播放按钮 | 输入框是核心资产，但完成一次记录需要 3 步以上 | TickBar 用**右键一键结束**把 3 步压成 1 步，这是产品唯一的护城河 |
| ShinyTimer / Timing 均强调 **No dock icon / 无窗口 / 始终一键可达** | 桌面计时工具的胜负手是"零窗口切换" | 悬浮条必须**永不抢焦点**，悬浮条就是全部 UI |
| Sunsama 的深色模式被评测反复称赞为「minimalist interface」，色彩用于**频道编码**而非装饰 | 深色工具色不能多，颜色必须携带语义 | TickBar 只允许**一个强调色系 + 两个状态色**，多一个都不加 |
| Super Productivity 深色主题：`border-t / divide-y` 分组，不用卡片盒 | 高信息密度的正确做法是"线"不是"盒子" | 药丸内部用 1px 分隔线，展开面板不用嵌套卡片 |
| FloatingTimer（macOS 开源）用 **200×100 浮动窗**，最后 60 秒放大到 240×120 并转红 | "尺寸变化 + 变色"是**被验证过的紧迫感语言** | 结束态用「环闪绿 + 撑大 4px」，但**不用红色**（红色留给危险操作） |
| 所有样本都**没有**用 emoji 作图标，全部是矢量描边图标 | emoji 会让工具瞬间掉档 | 锁定 Lucide（见 §8） |

### 0.2 Windows 平台悬浮窗的尺寸与交互习惯（Microsoft Learn + PowerToys 调研）

| 项 | 调研结论 | TickBar 采用 |
|---|---|---|
| 小组件边距 | Windows 官方小组件规范：容器四周边距 **16px**，元素间距 **4px** | 药丸距屏幕边缘 **16px**（可拖拽，吸附阈值 16px） |
| 圆角 | 官方小组件建议 **6–8px** | 药丸是胶囊形态（高 48 / 圆角 24），展开面板 **16px**，菜单 **12px** |
| 尺寸单位 | **必须用 DIP，响应 WM_DPICHANGED**；固定像素在高 DPI 下会崩 | 全部尺寸为 DIP；100% 下高 48px，150% 下渲染为 72 物理像素 |
| 点击穿透 | 常驻置顶覆盖层最致命的 bug 是"命中区过大，挡住底层应用" | 窗口固定 384×360 DIP 透明层，**只有可见药丸/面板区域可命中**，其余 click-through |
| 焦点 | 不允许抢焦点（用户可能在别的应用打字） | `WS_EX_NOACTIVATE`，仅显式点击才获得焦点 |
| 全屏应用 | 游戏/视频会被置顶窗激怒 | 检测全屏（`SHQueryUserNotificationState`）→ 自动隐入置顶之下 |
| 32px 悬浮条是否合理 | 可接受但偏紧；**44–48px** 才是移动端触摸目标的等价物，鼠标场景也更稳 | 采用 **48px**（原截图为紧凑版，保留 40px 紧凑档作为设置项） |
| 320×56 比例评估 | 高 56 偏大（视觉上更像"一个小窗口"而非"一条状态"）；宽 320 固定宽会在事项名长短变化时浪费空间 | **内容自适应宽度（min 256 / typ 288 / max 360）× 48 高**，比例约 **6:1**，更像"一条状态" |

### 0.3 对标品牌（选 1 主 3 辅）

**主对标：Raycast（macOS）**

| 为什么对标 Raycast | 说明 |
|---|---|
| 深色精密质感 | 近黑底 + 极低饱和的中性层次 + 单一强调色，没有一丝多余装饰 |
| **"一个输入条承载全部交互"** | 与 TickBar 的"一条药丸承载全部交互"是同一个设计命题 |
| 键盘优先但不排斥鼠标 | 契合我们"右键结束 / 空格暂停 / 全局热键"的三路径设计 |
| 组件密度极高但无压迫感 | 48px 高内塞 4 个功能区，靠 1px 分隔线和留白而不是卡片盒 |
| 图标与字体同源 | Raycast 用 Lucide 系描边 + 中性几何无衬线，正是我们要的线重语言 |

**辅助对标：**
- **Apple Dynamic Island**（形态语言）：药丸在「收起圆点 / 紧凑条 / 展开面板」三种形态间**连续变形**而非弹窗叠加，圆角随之从 24px 过渡到 16px。这是 TickBar 展开交互的骨架。
- **Linear**（排版纪律）：正文永远 13–14px、标题永远靠字重而非字号拉开层级、灰色只用三档。
- **Things 3**（克制哲学）：一个工具只回答一个问题。TickBar 只回答「现在这件事花了多久」。

**明确不对标：** Toggl Track（表单化、SaaS 化、步骤多）、Sunsama（规划型、信息过载）、Notion（内容型、无限嵌套）。它们都是"要打开的应用"，TickBar 是"一直在那里的状态"。

## 1. 设计方向：Floating Instrument（悬浮仪表）

**一句话定位：** 不是「一个计时器 App 的悬浮窗」，而是「桌面上的一个精密仪表」——像一支黄铜秒表的表盘，安静、精确、随时可用。

**三个声音词（Voice Words）：**
- **Brass-precise**（黄铜般精密）— 字距严谨、数字等宽、1px 线不含糊
- **Holdable**（可握持）— 药丸有实体感：实色底 + 内描边 + 外阴影，像一枚可以拿起来的物件
- **Unneurotic**（不焦虑）— 无红外闪烁、无进度条逼迫、无弹跳动效。计时是陪伴，不是监工

**氛围描述：** 近黑仪表底 + 等宽数字 + 一枚琥珀色信号环。静止时像关机，运行时像心跳。在同屏的 Slack / 浏览器 / IDE 之上，它应当是**最安静但最容易被眼睛找到**的那 3 平方厘米。

## 2. 配色基调

### 2.1 主视觉决策：Signal Amber（信号琥珀）——不用紫，不用粉

**品牌强调色 = `#E9A23B`（Signal Amber，信号琥珀）**

选它的理由（同时解释为什么不用其他方案）：
1. **语义正确**：琥珀是仪表盘、黄铜秒表、真空管指示灯的颜色。"时间在走"这件事在人类集体记忆里就是暖橙色的。
2. **避开 AI 套路**：`#6366F1` 靛蓝、`#7C3AED` 紫、`#EC4899` 粉是训练数据的默认值，一眼即知是 AI 生成。琥珀在深色效率工具里极罕见（Raycast 用红、Linear 用紫蓝、Toggl 用粉红）。
3. **在近黑底上对比度 7.88:1**，既是有效状态色，也能安全承载小号文字。
4. **不做渐变**。全文档禁止任何 `linear-gradient` 用于主视觉。唯一允许的"渐变"是状态光晕：`radial-gradient(circle, rgba(233,162,59,0.10), transparent 70%)`，**不透明度上限 0.12**。

### 2.2 深色中性色阶（自建，非 Tailwind slate/zinc 默认值）

深色层次的表达方式是**亮度递进**，而不是阴影。

| 层级 | 色值 | 用途 |
|---|---|---|
| L0 深渊 | `#0E0F12` | 阴影基色、拖拽时的投影、撤销条底 |
| L1 药丸底 | `#1A1C20` | 药丸默认背景（96% 不透明） |
| L2 抬升 | `#22242A` | 药丸 hover、展开面板底 |
| L3 高亮面 | `#2B2E35` | 按下态、chips 底、菜单 hover |
| L4 顶层 | `#343841` | 菜单按下、输入框底 |

文字与线条：

| Token | 色值 | 对比度（对 `#1A1C20`，实测） | 用途 |
|---|---|---|---|
| `--fg` | `#F2F4F7` | **15.5 : 1** | 主文本（计时数字、菜单主项） |
| `--fg-2` | `#C3C8D0` | **10.1 : 1** | 次级文本（事项名、暂停态数字） |
| `--muted` | `#8B919C` | **5.38 : 1** | 三级文本（辅助说明、「新建事项」默认态） |
| `--meta` | `#6E7480` | **3.63 : 1** | 仅限：图标、分隔线、禁用态文字（**禁止用于可读文案**） |
| `--border` | `#33373F` | 装饰性 | 面板外描边、静态分隔线 |
| `--border-soft` | `#26292F` | 装饰性 | 药丸内部 1px 分隔线 |
| `--border-strong` | `#454B55` | 装饰性 | hover 时描边加强 |
| `--edge-inner` | `rgba(255,255,255,0.08)` | — | 药丸顶部 1px 内高光（模拟物理边缘，非毛玻璃） |

### 2.3 状态色（核心：三态三色，绝不混用）

| 状态 | Token | 色值 | 对比度 | 语义 |
|---|---|---|---|---|
| **idle 待机** | `--state-idle` | `#8B919C` | 5.38 : 1 | 中性、待命、"我在等你的指令" |
| **running 计时中** | `--state-running` | `#E9A23B` | **7.88 : 1** | 暖、活、"时间正在燃烧" |
| **paused 已暂停** | `--state-paused` | `#7C93AC` | 5.39 : 1 | 冷、静、"手停住了但没结束" |
| **ended 已保存** | `--state-success` | `#3FB950` | 6.72 : 1 | 记录已落盘（仅闪 900ms） |

三色的设计逻辑：**琥珀（暖·活）→ 钢蓝（冷·止）→ 中性灰（无）**。这是一条"能量轴"，不是彩虹。用户不需要看图标，扫一眼颜色就知道现在的状态。

### 2.4 语义色

| Token | 色值 | 对比度 | 用途 |
|---|---|---|---|
| `--success` | `#3FB950` | 6.72 : 1 | 保存成功、撤销条确认 |
| `--warn` | `#D29922` | 6.76 : 1 | 计时超过 4 小时提醒、休眠期间有计时 |
| `--danger` | `#F2555A` | 5.05 : 1 | 「丢弃本次记录」、错误态 |
| `--danger-on` | `#1A0505` | — | 危险色背景上的前景 |

**注意：** 结束后不使用红色。红色只属于"销毁数据"这一类动作。让"完成"变成绿色是正向强化的正确做法。

### 2.5 交互效果色

| Token | 值 |
|---|---|
| `--accent` | `#E9A23B` |
| `--accent-hover` | `#F2B157` |
| `--accent-active` | `#D18F2C` |
| `--accent-on` | `#201603`（琥珀底上的前景，对比度 8.23:1） |
| `--accent-halo` | `radial-gradient(circle at 50% 50%, rgba(233,162,59,0.10) 0%, rgba(233,162,59,0) 70%)` |
| `--focus-ring` | `0 0 0 2px #1A1C20, 0 0 0 4px #E9A23B` （2px 间隙 + 2px 琥珀环，视觉 7.88:1） |

**每屏强调色使用量（Density=8 下的硬约束）：** 药丸内**最多 1 处**（状态环 + 其光晕算 1 处）；展开面板内**最多 2 处**（输入框焦点环 + 主按钮）。其余全部中性色。这一条是防"AI 彩虹屁设计"的核心闸门。

### 2.6 悬浮条与背景的对比安全策略

药丸要浮在任意壁纸上，因此**拒绝依赖壁纸**：

- 药丸底 = **96% 不透明** `#1A1C20` + 顶部 `rgba(255,255,255,0.08)` 1px 内描边 + 外部投影 `0 8px 24px rgba(0,0,0,0.44)` + `0 2px 6px rgba(0,0,0,0.32)`
- **不用 Mica / Acrylic / backdrop-filter 模糊**。理由（这是刻意的设计决策，不是偷懒）：
  1. 48px 高的小面积上做模糊，视觉收益趋近于 0，但 GPU 采样成本固定存在（Win11 Mica 是实时色调映射着色器）；
  2. 模糊会让文字对比度随壁纸**不可预测**，违反本项目"深色底 + 高对比浅色文字"的 P0 要求；
  3. 三位一体的"渐变 + 发光边框 + 毛玻璃"是 AI 模板的标志性套路，主动规避。
- 提供设置项：检测到浅色壁纸 / 高对比度模式 / 字体放大 → 药丸切为 **100% 不透明** 并把描边提升到 `rgba(255,255,255,0.14)`。

## 3. 字体方案

### 3.1 选择过程（按 Typography 选择流程，含"反射拒绝"步骤）

- 三个声音词：**brass-precise / holdable / unneurotic**
- 直觉首选：Inter、DM Sans、JetBrains Mono → **Inter 与 DM Sans 均命中反射拒绝列表**（训练数据默认值，制造 monoculture），**全部拒绝**
- 重新出发的物理对象参照：**德国博朗 1970 年代电子计时器的丝印面板** + **黄铜秒表的刻度盘**
- 交叉检查：精密感**不一定要等宽字体**，所以计时数字用等宽是对的，但界面正文用几何中性无衬线更合适；反过来，我也检查了"是否只是把 Inter 换了个名字" —— Geist 的 `a / g / t / r` 字形与 Inter 有明确差异（更方、终端更平切、更接近瑞士工程制图），不是换皮

### 3.2 锁定字体

| 角色 | 字体 | 授权 | 说明 |
|---|---|---|---|
| **界面主字体（Latin）** | **Geist Sans** | OFL 1.1 | 几何中性、终端平切、小字号下比 Inter 更"硬"，符合仪表气质。Windows 上小字渲染清晰 |
| **界面字体（中文）** | **Noto Sans SC** | OFL 1.1 | 中文字形骨架与 Geist 的方形终端相容；`font-weight` 与 Geist 的 400/500/600 三档对齐 |
| **计时数字（核心）** | **Geist Mono** | OFL 1.1 | 等宽 + 居中冒号 + 目的明确的技术感。**必须开启 `tabular-nums` + `zero`（斜杠零）**，避免 1/7、0/O 混淆 |
| 等宽回退链 | `JetBrains Mono → Cascadia Mono → Consolas → monospace` | OFL / Microsoft | Cascadia Mono 随 Windows Terminal 分发，Windows 上的最终保底 |
| 完整回退链 | `-apple-system, "Segoe UI Variable Text", "Microsoft YaHei UI", sans-serif` | — | Windows 无字体文件时的系统兜底 |

```css
--font-ui:   "Geist Sans", "Noto Sans SC", -apple-system, "Segoe UI Variable Text", "Microsoft YaHei UI", sans-serif;
--font-mono: "Geist Mono", "JetBrains Mono", "Cascadia Mono", Consolas, monospace;
```

### 3.3 字号阶梯（48px 药丸专用的紧凑寄存器，非 Web 尺度）

| Token | 字号 / 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `--text-2xs` | 10px / 12px | 500 | `+0.06em` | 极小徽标（如 "4h+" 超时角标） |
| `--text-xs` | 11px / 16px | 500 | `+0.02em` | 快捷键提示（`Space`、`Esc`）、撤销条 |
| `--text-sm` | 12px / 18px | 500 | `+0.01em` | 「新建事项」、chips、辅助说明 |
| `--text-base` | 13px / 20px | 500 | `0` | 事项名、菜单项 |
| `--text-md` | 14px / 22px | 510 | `0` | 展开面板输入框、菜单主项 |
| `--text-lg` | 16px / 24px | 590 | `-0.01em` | 展开面板标题 |
| `--text-timer` | **20px / 24px** | 510 | `0` | **药丸内计时数字（默认）** |
| `--text-timer-lg` | 28px / 32px | 510 | `-0.01em` | 展开面板中的大计时 |
| `--text-timer-xl` | 40px / 44px | 510 | `-0.02em` | 仅"专注模式全展开"（v2，本期不实现，预留给 token） |

**计时数字硬规范（工程级）：**
```css
.timer-digits {
  font-family: var(--font-mono);
  font-size: var(--text-timer);
  font-weight: 510;               /* 等宽数字不要 600+，会糊 */
  font-variant-numeric: tabular-nums;
  font-feature-settings: "tnum" 1, "zero" 1;
  letter-spacing: 0;
  min-width: 5ch;                 /* "00:00" —— 防止 0→1 跳字时药丸宽度抖动 */
  text-align: right;              /* 右对齐 + 定宽 = 数字永远原地变化 */
  font-variant-ligatures: none;
}
.timer-digits[data-hours="true"] { min-width: 8ch; }   /* "1:23:45" */
```
**这是全文档最重要的一条排版规则**：计时数字必须在**不换行、不宽度跳动**的前提下每秒变化。任何宽度抖动都会让这个产品显得廉价。

### 3.4 字重三档体系

| 级别 | 字重 | 用途 | 禁止 |
|---|---|---|---|
| Read | 400 | 说明文字、撤销条正文 | 不用于数字 |
| Emphasize | **510** | 计时数字、菜单项、事项名、按钮 | — |
| Announce | 590 | 展开面板标题、大计时 | 不用于 14px 以下 |

**规则：48px 高度内只用 2 档字重（510 / 590），第 3 档（400）只在展开面板里出现。** 在极小尺寸上堆字重层级是新手错误。

### 3.5 大写与字距

- 快捷键盘标签（`SPACE` / `ESC` / `ENTER`）**统一大写 + `letter-spacing: 0.06em`**，11px，色 `--meta`
- 中文**永不**加字距（中文字距一加立刻显得廉价）
- 标题负字距只对 ≥16px 的拉丁文生效

## 4. 视觉规格（药丸几何标注）

### 4.1 形态 A：紧凑条（默认态，含活跃事项）

```
   ┌─────────────────────────────────────────────────────────┐
   │  ← 2px                          ↑ 48px 胶囊高            │
   │  ┌────┐                                                 │
   │  │ ◯  │  00:00   │ 品牌视觉改版第一轮        │  ⌄  │     │
   │  └────┘                                                 │
   └─────────────────────────────────────────────────────────┘
    44×44    min 5ch   1px 分隔   1fr, max 11 中文字符   44×44
     热区    数字区      线        事项名区（截断）      手柄热区
```

| 规格项 | 值 | 说明 |
|---|---|---|
| 药丸高度 | **48px**（紧凑档 40px，设置可切） | DIP；150% DPI 下渲染 72 物理像素 |

### 4.2 形态 B：收起圆点（Collapsed）

| 规格项 | 值 |
|---|---|
| 可见直径 | **28px** |
| 命中区 | **36×36**（详见下方说明） |
| 内容 | 只剩状态环（描边 2.5px + 状态色），运行中带 halo |
| 位置 | 保持收起前药丸左边缘的锚点位置，形态向左上收拢 |

**关于 44×44 触摸目标的偏差说明（必须在 spec 中标注）：**
收起态命中区 **36×36**，主动小于 44px。理由：TickBar 是**常驻置顶覆盖层**，一个 44px 的隐形命中区会遮挡底层应用 44×44 范围的点击——这在 Windows 上是比"目标略小"严重得多的可用性事故（Microsoft PowerToys 顶部菜单栏调研中列为头号坑）。补偿措施：
1. 桌面鼠标场景下 36px 已是舒适目标（Windows 官方小组件规范建议最小触控目标为 32px 量级）；
2. 提供**全局热键**路径（`Ctrl+Alt+Space` 开始/暂停）覆盖键盘用户与运动障碍用户；
3. 悬停即出 tooltip，不依赖精确点击。

### 5.1 状态机总览

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
        ┌───────────┴──────────┐  左键点击环   ┌───────────────┴──┐
        │  IDLE 待机            │ ───────────→ │  RUNNING 计时中   │
        │  环: 2px --state-idle │               │  环: 2px 琥珀     │

        └───────────┬──────────┘  右键结束     └───────┬──────────┘
                    │                                   │ 左键点击环
                    │ 点击「新建事项」                    ↓
        ┌───────────┴──────────┐               ┌──────────────────┐
        │  COMPOSING 新建事项   │               │  PAUSED 已暂停    │
        │  面板展开 + 输入框聚焦 │               │  环: 2px 钢蓝     │

                    ┌──────────────────────────────────────────────┐
                    │  ENDED 结束态（瞬时，900ms）                   │

                    └──────────────────────────────────────────────┘
```

### 5.2 主状态 × 视觉规格矩阵

| 属性 | IDLE | RUNNING | PAUSED | ENDED |
|---|---|---|---|---|
| 药丸底 | `--surface` `#1A1C20` | `--surface` | `--surface` | `--surface` |
| 环描边色 | `--state-idle` `#8B919C` | `--state-running` `#E9A23B` | `--state-paused` `#7C93AC` | `--success` `#3FB950`（→ 900ms 后回 idle） |
| 环描边宽 | 2px | 2px | 2px | 2px → 3px（强调） |
| 环内图标 | 无（hover 出 16px `play`） | 无（hover 出 16px `pause`） | 常显 16px `pause`，色 `--state-paused` | 16px `check`，色 `--success` |
| 计时数字色 | `--fg` `#F2F4F7` | `--fg` `#F2F4F7`（**保持高对比**） | `--fg-2` `#C3C8D0` | `--fg-2` |
| 数字内容 | `00:00` | 秒级递增 | 冻结在当前值 | 冻结 900ms |
| 事项名区 | 「新建事项」+ `plus`（`--muted`） | 事项名（`--fg-2`）+ 右侧 12px 迷你计时微标 | 同 running，但 `--muted` | 事项名 + 绿色 `check` |
| 光晕 | 无 | `--accent-halo` 呼吸 2.4s | 无 | 绿光晕 300ms 淡出 |
| 动效 | 无 | 1Hz tick + 呼吸 | **完全静止** | 绿色收束 |
| 光标 | `pointer`（环/手柄）、`grab`（条身） | 同左 | 同左 | 同左 |

**关键决策：计时数字在 RUNNING 时保持 `--fg`（15.5:1）而不是变琥珀。** 理由：琥珀色数字在 20px 等宽下会略微降低长时阅读舒适度，且用户的注意力应该落在"数字本身"而不是"颜色"。状态由环和光晕承载，数字只负责可读性。这是 P0-6「深色底 + 高对比浅色文字」的直接落实。

### 5.3 通用交互态（每个可交互元素都必须覆盖）

| 状态 | 药丸本体 | 环形按钮 | 「新建事项」/ 手柄 |

| **Active / Pressed**（100ms） | 底 `#2B2E35`，`transform: scale(0.985)` | 环 `transform: scale(0.92)`，光晕不透明度 +0.04 | 底 `#343841`，`scale(0.97)` |

| **Empty** | 无活跃事项 → 事项名区显示「新建事项」 | hover 出 `play` | 不适用 |

### 5.4 三态核心操作路径（零学习成本验证）

| 用户目标 | 操作 | 步数 | 反馈 |
|---|---|---|---|
| 开始计时（已有事项） | 左键点环 | 1 | 环变琥珀 + 1Hz tick + 光晕呼吸 |
| 开始计时（新事项） | 点「新建事项」→ 输入 → `Enter` | 1 击 + 输入 + 1 键 | 面板收起为药丸，环变琥珀 |
| 暂停 | 左键点环 | 1 | 环变钢蓝，动效全停，数字转 `--fg-2` |
| 恢复 | 左键点环 | 1 | 环回琥珀 |
| **结束当前记录** | **右键单击** | **1** | 环闪绿 + `check` + 撤销条 3s |
| 撤销刚才的结束 | 点撤销条「撤销」 | 1 | 恢复 RUNNING，累计时长接续 |
| 收起 | 左键点手柄 `chevron-right` | 1 | 280ms 变形为 28px 圆点 |
| 展开 | 左键点圆点 | 1 | 280ms 变形回药丸 |

**结论：全部主路径 ≤ 1 次点击。** 这就是"轻量"的全部含义。

### 5.5 右键交互的冲突解决方案（重要设计仲裁）

**问题：** 团队要求「右键结束当前记录」同时也要「右键菜单」。这两个语义直接冲突。

**方案：单击 / 长按分层 + 键盘替代路径**

| 输入 | 行为 | 理由 |
|---|---|---|
| 右键**单击**（按下→抬起 < 400ms） | **立即结束并保存当前记录**（不动画打断，环闪绿） | 核心闭环必须零摩擦。这是产品唯一的差异化动作，绝不能藏在菜单里 |
| 右键**长按 ≥ 500ms** | 弹出上下文菜单，并给出 120ms 的触觉式视觉反馈（环外圈轻微放大 1.06 后回弹到 1.0，非弹性缓动） | 长按是"我想做点别的"的自然表达 |
| `Menu` 键 / `Shift+F10` | 弹出上下文菜单（键盘可达路径） | 无障碍强制要求 |
| 收起态右键单击 | 弹出上下文菜单（无记录可结束） | 语境自适应 |
| **不确定态**（按住 400–500ms 区间） | 若在此期间抬起，视为单击（结束）；菜单不弹出 | 阈值单一，无歧义 |

**发现成本补偿：** 首次运行的第 3 次计时结束后，撤销条旁边出现一次性的提示「右键长按可以打开更多操作」（12px `--muted`，出现 4 秒后永久不再出现）。不做 onboarding 弹窗。

### 5.6 边界与异常态（Riley 压力测试者视角）

| 场景 | 设计 |
|---|---|
| 计时 < 60 秒时结束 | 不静默保存。撤销条文案：「只记了 47 秒，要留下吗？」+ 主按钮「保存」+ ghost「丢弃」 |
| 计时 ≥ 4 小时 | 药丸右侧出现 10px `--warn` 圆点 + tooltip「已连续计时 4 小时 12 分」；不弹窗、不变红、不中断计时 |
| 事项名超长 | 截断到 11 中文字符 + `…`；悬停 400ms 后 tooltip 显示完整名（tooltip 最宽 240px，2 行折行） |
| 计时跨过 24:00:00 | 数字区 `min-width` 切到 8ch，格式 `25:14:03`；上限显示 `99:59:59` |
| 系统休眠 / 睡眠期间计时 | 唤醒后用药丸右侧 `--warn` 提示「休眠期间 1 小时 12 分未计」；计时基于 `Stopwatch.GetTimestamp()` 单调时钟 + 挂起检测，不基于墙钟累加 |
| 已有记录在跑时新建事项 | 先自动保存旧记录（走正常结束流程），再进入 COMPOSING；撤销条文案「已保存 上一条 · 22:08」+ 撤销 |
| 用户连点环 3 次 | 200ms 去抖窗口，忽略重复触发（防止误双击产生"开始→暂停→开始"的瞬时抖动） |
| 双击药丸条身 | 无绑定动作（防误操作）；条身只用于拖拽 |
| 保存失败（磁盘满 / 权限） | 环闪 `--danger`，记录保留在内存并重试 3 次，撤销条换红底提示；**绝不丢数据** |
| 全屏应用运行中 | 自动降到置顶之下（不隐藏，避免用户以为"工具挂了"）；仅保留 3px 的屏幕边缘细条暗示存在。此行为可在设置关闭 |
| 多显示器 | 记住所在显示器 + 相对该显示器右下角的偏移（默认距右 16px、距下 16px）；显示器拔掉后回落到主屏 |
| 高对比度模式 / 系统动画关闭 | 关闭呼吸光晕与 1Hz tick，只用状态色 + 图标表达；描边不透明度提至 0.14；尺寸整体 ×1.15 |

### 5.7 键盘可达性（Sam 无障碍依赖视角）

| 按键 | 行为 |
|---|---|
| `Tab` / `Shift+Tab` | 在「环 → 事项名区 → 新建事项 → 手柄」四个焦点站之间循环 |
| `Space` | 开始 / 暂停（等价左键点环） |
| `Enter` | 结束并保存（等价右键单击）；在 COMPOSING 态为"开始计时" |
| `Esc` | 取消当前面板 / 关闭菜单；RUNNING 态下**不**结束计时（防误触丢数据） |
| `Menu` / `Shift+F10` | 打开上下文菜单 |
| `Ctrl+Alt+Space`（全局热键） | 从任意应用开始 / 暂停，**不需要药丸获得焦点** |
| `Ctrl+Alt+N`（全局热键） | 新建事项（药丸直接进入 COMPOSING 并聚焦输入框） |
| 方向键 | 在菜单项 / chips 之间移动，不使用鼠标悬停依赖 |

**硬要求：** 药丸的每一个功能都必须有键盘路径；`focus-visible` 在深色底上必须可见（用 2px 琥珀环 + 2px 间隙，对比度 7.88:1）；所有 `focus` 样式禁止用 `outline: none` 清除。

## 6. 动效规范

### 6.1 缓动曲线（3 条，仅此 3 条）

| Token | 曲线 | 用途 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 一切颜色 / 阴影 / 透明度过渡（"快出慢入"的 UI 标准曲线） |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 元素离场（淡出、撤销条消失） |
| `--ease-morph` | `cubic-bezier(0.32, 0.72, 0, 1)` | 药丸形态变形（Dynamic Island 式的"先快后极慢"收尾） |

**明令禁止：**
- 任何弹跳 / 弹性缓动，包括 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`、`cubic-bezier(0.34,1.56,0.64,1)`、`ease-back`、`spring` 系
- `linear` 用于非"持续旋转/进度"以外的场景
- 任何时长 > 400ms 的 UI 动效

### 6.2 时长阶梯

| Token | 值 | 场景 |
|---|---|---|
| `--dur-instant` | **100ms** | 按下反馈、图标淡入、`scale` 微缩 |
| `--dur-quick` | **150ms** | hover 变色、描边变化、阴影变化（**跨系统收敛值**，本项目最常用） |
| `--dur-base` | **200ms** | 状态切换（idle → running → paused）、菜单出场 |
| `--dur-morph` | **280ms** | 药丸 ↔ 圆点 ↔ 面板的形态变形 |
| `--dur-exit` | **180ms** | 撤销条淡出、菜单关闭 |
| `--dur-confirm` | **900ms** | 结束态绿色保持时间（之后回 idle） |
| `--dur-undo` | **3000ms** | 撤销条生命周期 |

### 6.3 状态动效语言（每个动效必须携带信息）

| 动效 | 规格 | **传达的信息**（若无信息则删掉） |
|---|---|---|
| **1Hz tick** | 每秒整点，环描边不透明度 1.0 → 快速增亮 `--accent-hover`（120ms）→ 在 500ms 内 `ease-out` 衰减回 1.0 | "秒针走了一下"。这是 RUNNING 的主心跳，**不用旋转 spinner**（旋转代表"加载中"，语义错误） |
| **光晕呼吸** | 56×56 halo，`opacity 0.06 → 0.10 → 0.06`，周期 **2400ms**，`ease-in-out`，无限 | "它活着"。极低对比的持续微动，在余光里可见，直视时不干扰 |
| **暂停冻结** | 所有动效在 **120ms 内**（`--ease-standard`）全部停止；环色琥珀→钢蓝 `--dur-base` | "时间凝固了"。**瞬时硬停 + 短暂渐变**的组合强化"冻结"感 |
| **恢复** | 环色钢蓝→琥珀 `--dur-base`；光晕从 opacity 0 淡入 300ms 后才开始呼吸 | "重新点火"，不是"瞬间炸开" |
| **结束收束** | 环色 → `--success`（150ms）→ 环描边 2px→3px 并 `scale(1.06)`（120ms）→ `check` 图标 200ms 缩放入场 → 保持 900ms → 全部回 idle（200ms） | "记录落盘了"。用绿色 + 对勾这一对人类共同符号，不需要读文字 |
| **撤销条入场** | 从药丸下方 8px 位置，`translateY(-6px) + opacity 0` → `translateY(0) + opacity 1`，280ms `--ease-morph` | "有个东西可以撤销"。**不做从屏幕外滑入**（会抢注意力） |
| **撤销条退场** | `opacity 1 → 0`，180ms `--ease-exit`，无位移 | 静默离场 |
| **形态变形** | 药丸 ↔ 圆点 ↔ 面板：几何（宽/高/圆角）+ 位置 280ms `--ease-morph`；内容 `opacity` 延迟 80ms 后 200ms 淡入 | "同一个东西换了形状"。**不做两个窗口的交叉淡入**（那会暴露"这是两个图层"） |
| **hover 反馈** | 150ms `--ease-standard`，仅颜色与阴影 | 指针可交互 |
| **拖拽吸附** | 松手时距屏幕边缘 < 16px → 吸到 16px；位移用 180ms `--ease-morph` | "它属于这条边" |

**动效预算硬约束：** 同一时刻动画中的元素**不超过 3 个**；RUNNING 稳态下**只有 2 个**（1Hz tick + 光晕呼吸），且都不产生布局重排。

### 6.4 性能实现约束（Windows 特化，写给前端）

```css
/* 允许动画的属性（白名单） */
opacity, transform, background-color, border-color, color, box-shadow, border-radius

/* 禁止动画的属性（黑名单） */
width, height, margin, padding, top/left/right/bottom, font-size,
filter: blur(), backdrop-filter
```

**形态变形的实现方案（避免 Win32 逐帧 resize 抖动）：**

窗口本身**固定为 384×360 DIP 的透明置顶层，尺寸永不变**。药丸、圆点、面板都是这个固定窗口内部用 `transform` + `border-radius` 绘制的元素。这样：
- 窗口不需要响应 `WM_SIZE`，避免拖动时的重绘闪烁与撕裂；
- 形态变形全部在 CSS/合成层完成（GPU 加速），无布局抖动；
- 命中测试由应用层按"当前可见元素的矩形"动态定义（其余区域 click-through）。

> **文档化例外：** 本项目的形态变形需要过渡 `width / height / border-radius`（药丸高 48 → 面板高 auto）。这是产品形态语言的**核心表达**，且仅发生在用户主动触发的单次变形中（≤280ms），不是稳态动画。除此之外，`width/height` 一律禁止动画。此例外已在 §6.4 立项并需在 Code Review 中核对。

### 6.5 prefers-reduced-motion

```css
@media (prefers-reduced-motion: reduce) {
  /* 关闭所有持续性动效 */
  .halo-breath, .ring-tick { animation: none !important; }
  /* 保留状态切换的即时可见性（去掉过渡而非去掉状态） */
  * { transition-duration: 0.01ms !important; }
  /* 用静态表达替代动效表达 */
  .ring[data-state="running"] { stroke-width: 3px; }  /* 加粗代替跳动 */
  .ring[data-state="paused"]  { stroke-dasharray: 4 3; } /* 虚线代替颜色独占 */
}
```
**关键原则：减少动效 ≠ 减少信息。** 关闭动效后，RUNNING 用 3px 粗环表达、PAUSED 用虚线环表达——状态仍然百分百可辨（也让色觉障碍用户多一条通道）。

## 8. 图标库锁定（P0-1）

### 8.1 锁定结论

> **全项目唯一图标库：Lucide（lucide.dev），版本锁定 ≥ 0.460，许可证 ISC。**

**为什么锁定 Lucide：**

| 判据 | Lucide 的表现 |
|---|---|
| 描边一致性 | 统一 24×24 网格、**2px 描边**、圆角端点（`stroke-linecap: round`）。这与本设计的「2px 环描边 + 2px 焦点环」形成同一条"线重语言"，是整个视觉系统能成立的技术前提 |
| 风格匹配 | 纯 outline、几何中性、克制。TickBar 是"仪表"，不是"品牌 App"，不需要 Phosphor 那种圆润多字重或 duotone 的表现欲 |
| 与字体相容 | Geist 的方形终端 + 平切笔画，与 Lucide 的几何直线高度同源；换成圆润图标库会立刻产生"拼贴感" |
| 覆盖率 | 1600+ 图标，本产品全部所需图标（见 §8.2）100% 覆盖，无需混入第二套库 |
| 工程性 | 提供无依赖纯 SVG，可**离线内联**进桌面应用（关键：悬浮工具不应依赖 CDN）；tree-shakable，全部用到的图标 < 8KB |
| 许可证 | ISC（比 MIT 更宽松），商用、修改、再分发无限制 |
| 尺寸体系 | 原生 24px 网格，等比缩放到 20px / 16px 无失真（顶点对齐像素网格） |

**明确排除的其他库及理由：**
- **Phosphor** — 6 种字重的表现力对 48px 高、只用 5–6 个图标的产品是纯负担，且 duotone 会与"每屏 ≤2 处强调色"冲突
- **Tabler** — 6000+ 图标覆盖对我们过剩；其描边在缩到 16px 时一致性弱于 Lucide
- **Heroicons** — 仅约 292 个图标，会撞到 `undo-2` / `settings-2` 这类缺口；且 Solid 变体本设计完全用不到
- **Material Symbols** — 平台味太重（Google 审美），与 Windows + Geist 的组合不搭；字体文件 4–6MB 不可接受
- **Fluent UI System Icons** — 虽然"最 Windows"，但其细描边风格（1.5px）会与我们 2px 环/焦点环的线重语言冲突，且会让产品看起来像系统自带组件而不是一个有品牌个性的工具。**这是一个刻意的差异化选择。**

### 8.2 图标清单与尺寸规范（全项目统一，不得混用）

| 尺寸 | 用途 | stroke-width | 图标清单 |
|---|---|---|---|
| **16px** | 行内（按钮内文字旁、菜单项内、chips 内、撤销条内） | **2.5** | `play` `pause` `check` `plus` `undo-2` `pencil` `trash-2` `settings-2` `pin` `pin-off` `keyboard` `circle-alert` `clock` |
| **20px** | 按钮内（收起手柄、独立动作按钮） | **2** | `chevron-right`（收起） `chevron-left`（展开） `grip-vertical`（拖拽暗示，可选） |
| **24px** | 独立图标（展开面板标题、空状态、错误态） | **2** | `circle-dot`（空状态） `inbox`（无历史） `keyboard`（快捷键引导） |

**描边宽度的技术细节（必须写进代码）：** Lucide 的 `stroke-width` 是相对 `viewBox="0 0 24 24"` 的。图标缩放到 16px 时若保持 `stroke-width: 2`，视觉线重会细 33%，与 20px 图标不一致。**规范：16px 下设 `stroke-width: 2.5`，20px / 24px 下设 `2`**，保证三种尺寸的**视觉**线重一致。

```html
<!-- 正确示例 -->
<svg width="16" height="16" viewBox="0 0 24 24" fill="none"
     stroke="currentColor" stroke-width="2.5"
     stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
  <path d="M5 3l14 9-14 9V3z"/>   <!-- lucide: play -->
</svg>
```

### 8.3 emoji 禁令执行

- 全项目**零 emoji 作为功能图标**。UI 内出现的所有图形符号必须来自 Lucide。
- 校验正则（提交前自查）：`[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]`
- **重要陷阱**：禁用区间同时覆盖了一批"看起来不像 emoji 的字符符号"，例如 `U+2713`（对勾）、`U+26A0`（警告三角）、`U+2714`（重对勾）、`U+274C`（叉）。这四类符号在设计稿和代码里极常见，**一律禁止**。状态符号必须使用 Lucide 的 `check` 与 `circle-alert` 图标，不得使用任何 Unicode 字符符号。
- 例外：只有用户自己输入的事项名（UGC）可以含 emoji，UI 不得渲染为图标。

## 9. Windows 平台专项规范与已知坑（交付给架构师/前端）

| # | 事项 | 规范 |
|---|---|---|
| 1 | 窗口样式 | `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`（无 `WS_EX_APPWINDOW`，不占任务栏）；`WS_POPUP` 无边框 |
| 2 | 窗口尺寸 | 固定 **384×360 DIP**，永不 resize（见 §6.4）；DPI 变化时按新 DPI 重新计算内部 DIP 布局 |
| 3 | DPI | 全量 DIP。响应 `WM_DPICHANGED`；**禁止**任何硬编码物理像素。150% 缩放下 48 DIP → 72 物理像素 |
| 4 | 圆角 | **不要依赖 DWM 的自动圆角**（Win11 对顶层窗口强制 8px 圆角、且圆角是几何而非样式，无法通过样式覆盖）。用分层窗口 + 透明底 + 自绘 24px 圆角。参考做法：`DwmExtendFrameIntoClientArea(hwnd, &{ -1,-1,-1,-1 })` |
| 5 | 点击穿透 | 用 `SetWindowRgn` 或 `WM_NCHITTEST` 返回 `HTTRANSPARENT`，**把命中区严格限定在当前可见的药丸/面板矩形**。这是本产品最容易出致命 bug 的地方（一块透明的 384×360 会挡住整个桌面） |
| 6 | 焦点 | `WS_EX_NOACTIVATE` + 仅显式点击时 `SetForegroundWindow`。**绝不在计时开始/结束时抢焦点**（用户正在 IDE 里打字） |
| 7 | 拖拽 | 拖拽起始阈值为 **4 DIP**（小于此视为点击，避免手抖变成拖动）；吸附阈值 **16 DIP**；吸附后固定边距 **16 DIP** |
| 8 | 拖动实现 | 不要用 `WM_NCLBUTTONDOWN + HTCAPTION`（会触发系统拖动循环与 DWM 动画，产生拖影/半透明预览）。手动追踪 `WM_MOUSEMOVE` + `SetWindowPos(SWP_NOSENDCHANGING)` |
| 9 | 全屏检测 | `SHQueryUserNotificationState()` 返回 `QUNS_RUNNING_D3D_FULL_SCREEN` / `QUNS_PRESENTATION_MODE` 时降层 |
| 10 | 计时精度 | 用 `QueryPerformanceCounter` / `Stopwatch.GetTimestamp()`（单调时钟），**不用墙钟差值**；配合 `WM_POWERBROADCAST` 检测休眠/唤醒并记录 gap |
| 11 | 主题 | 本产品**恒为深色**，不跟随系统亮色主题（这是品牌决策：琥珀 + 近黑是识别符号）。但必须响应：高对比度模式、`SPI_GETCLIENTAREAANIMATION`（动画开关）、字体缩放（`SPI_GETNONCLIENTMETRICS`） |
| 12 | 性能预算 | 空闲态 CPU 占用 **< 0.1%**；RUNNING 稳态 **< 0.3%**（每秒 1 次 repaint，只重绘环所在的 56×56 区域，不做整窗 repaint）；GPU 显存 < 20MB；内存 < 60MB |
| 13 | 无网络依赖 | 字体与图标全部**本地内联**，不请求 Google Fonts CDN。悬浮工具在断网时必须是完整体验 |
| 14 | 启动 | 无 splash、无 onboarding 弹窗。首次启动即显示药丸本身（Loading 态见 §5.3），3 秒内进入可用 |

## 11. 交付给下游的约束摘要

**给架构师（Phase 1 协同）：**
1. 窗口必须支持**固定尺寸透明置顶层 + 动态命中区**，否则 §6.4 的零抖动形态变形无法实现；
2. 字体（Geist Sans / Geist Mono / Noto Sans SC）与 Lucide SVG 必须**本地内联**，不依赖网络；
3. 计时精度必须用单调时钟 + 休眠检测，不能用墙钟累加；
4. 全局热键 `Ctrl+Alt+Space`（开始/暂停）、`Ctrl+Alt+N`（新建事项）需要在 Phase 2 的 Spec 中确认；
5. 右键"单击结束 / 长按 500ms 菜单"的分层输入需要在窗口消息层实现（区分 `WM_RBUTTONUP` 与长按定时器）。

**给前端（Phase 3）：**
1. 所有颜色/间距/圆角/时长必须 `import` 自 `design-tokens.json`（Phase 2 产出），**零裸值**；
2. 计时数字必须 `tabular-nums` + `min-width: 5ch` + `text-align: right`，这是不可协商项；
3. 形态变形只允许 280ms + `--ease-morph`，且同时动画元素 ≤3 个；
4. `focus-visible` 样式不允许被清除；`prefers-reduced-motion` 分支必须实现且**保留状态可辨性**；
5. 图标只用 Lucide，尺寸 16/20/24px 三档，16px 时 `stroke-width: 2.5`；
6. 提交前用 emoji 正则自查：`[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]`。

**Phase 2 待产出（不在本期范围）：** `DESIGN.md`（9 节标准格式）、`design-system/MASTER.md`、`design-tokens.json`、`design-tokens.css`、`pages/` 页面级 Override（药丸主视图 / 展开面板 / 菜单 / 撤销条 / 设置页）。
