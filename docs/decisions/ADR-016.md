# ADR-016：后端分层与解环——新增 `platform` 叶子层与 `jobs` 调度层

## Status

Accepted（2026-10-18，架构评估 P0「后端存在 `infra ↔ services` 依赖环」项；对应任务 T07 / T23）

## Background

V0.2.10 的后端目录是四层：`commands -> services -> repositories -> models`，外加一个 `infra`。评估时实测到两处结构性问题：

1. **`infra` 反向依赖 `services`**。6 个文件 `infra/{runtime,monitor,reminder,countdown,clock,note_windows,events,tray}.rs` 里出现 `use crate::services::...`。其中 `clock` 最要命：`services` 需要当前时间（`now_ms`）来算时长，`infra::clock` 又处在「infra 是 services 的下游」这一约定里 —— 一个纯读取系统时间的函数，把整个依赖图变成了有环图。
2. **`infra` 里混着三种东西**：真正的平台适配（窗口、托盘菜单、通知、快捷键、几何）、长驻调度（监控、周期落盘、提醒轮询、倒计时轮询）、以及装配动作（`setup`、事件发射）。后两类不是「平台能力」，却因为「要拿 AppHandle」被塞进 `infra`，于是 `infra` 必然要读业务状态，必然反向依赖 `services`。

有环的现实代价不是「编译不过」（Rust 允许同 crate 内互相引用），而是：**任何试图单独测试或替换 `infra` 的想法都不成立**，以及后面每加一个后台任务，环都会更紧一点。

## Decision

**把依赖图重新排成一条线，并把「环」从结构上拆掉，而不是用 allowlist 遮住。**

目标层级（依赖只能向下列走）：

```
platform  （叶子：只依赖 std + chrono，无 Tauri）
   ↓
infra     （平台适配：窗口 / 托盘菜单 / 通知 / 快捷键 / 几何 / 迁移）
   ↓
services  （业务：计时 / 事项 / 待办 / 便利贴 / 设置 / 主题 / 日记 / 倒计时 / 提醒）
   ↓
app       （装配：events 发射 / tray / bootstrap / diagnostics）
jobs      （调度：monitor / flusher / reminder / countdown）
   ↓
commands  （IPC 入口，62 个函数）
```

要点：

1. **新建 `platform`**：`clock`（单调时钟锚点表）、`log`（分级滚动日志 + panic hook）、`boot_timing`（冷启动埋点）。三者都「不需要任何 Tauri 能力」，因此可以待在依赖图最底部，被 `services` 直接使用而不会形成环。
2. **`infra` 瘦身**：只剩 `autostart, db, geometry, migrate, notify, shortcuts, tray_menu, window, window_spec`。原来的 `infra/setup.rs`、`infra/runtime.rs`（以及 `monitor`/`reminder`/`countdown`/`note_windows`/`events`/`tray`）全部迁出。
3. **新建 `app` 装配层**：`events.rs`（读业务状态再广播——这一步天然属于装配，不属于平台）、`tray.rs`、`bootstrap.rs`（composition root，声明启动顺序）、`diagnostics.rs`。
4. **新建 `jobs` 调度层**：每个常驻任务一个文件，只负责「定时 → 调服务 → 发事件」，不写业务规则。
5. **单调时钟替代墙钟算时长**（T23）：落库字段（`started_at`/`ended_at`/`running_since`）仍用**墙钟**（跨进程重启必须能对齐）；「这次跑了多久」改用 `std::time::Instant` 锚点（`platform/clock.rs` 的锚点表），每次折账后重新锚定。这样 NTP 校时 / 手动改时不会让时长跳变；锚点缺失（进程重启）时自动退回纯墙钟差值，行为与 v0.2 一致。
6. **门禁化**：`scripts/check-layers.mjs` 用 6 条 grep 规则把上述约束变成 CI 可执行项：
   - L1 `src/components/**` 不得出现 `ipc.` / `invoke(`
   - L2 `src/stores/**` 不得出现 `ipc.`
   - L3 只有 `src/lib/window.ts` 可以 `import ... from '@tauri-apps/api/window'`
   - L4 `src-tauri/src/infra/**` 不得出现 `use crate::services`
   - L5 `src-tauri/src/commands/**` 不得出现 `use crate::repositories`（禁止跳层）
   - L6 全库不得出现 `eprintln!`（统一走 `log_*`）

## Consequences

正面：

- **环结构性消失**：`infra → services` 的 grep 结果为 0，且是「没有这个依赖」而不是「被白名单放行」。
- `platform` 可被单测直接覆盖（`tests/timer_clock.rs` 6 条、`tests/boot_timing.rs` 9 条），不需要构造 Tauri App。
- 调度与装配分开后，「后台任务什么时候跑」与「启动顺序是什么」各自有唯一归属文件，改一个不会牵动另一个。
- 时间口径有了明确的双时钟约定，`tests/timer_clock.rs` 能模拟墙钟前后跳 ±1h 并断言时长误差 ≤1s。

负面 / 已接受的代价：

- **目录数增加**（`platform` / `app` / `jobs` 三个新目录、约 15 个新文件）。对单人项目来说，这是拿「文件数」换「依赖方向唯一」。
- 分层是**约定 + grep**，不是编译器强制。Rust 同 crate 内没有可见性级别的模块系统能禁止 `use crate::services`，所以只能靠门禁。门禁能拦「新写的代码」，拦不住「用 `#[path]` 或宏绕过」——后者属于人为规避，不在防线范围内。
- `platform::log` 是宏 + 全局 `OnceLock` 方案，不做结构化查询。真需要检索时替换 `log()` 的下游即可，调用点不用动。
- 原计划 ADR-016 留给「自动更新」（评估任务 T19）。因 T19 依赖证书与外网托管，尚未落地，编号先给本次分层改造；自动更新落地时取 ADR-018。
