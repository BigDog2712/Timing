# ADR-011: 倒计时作为计时状态机的「模式扩展」，到点判定归 Rust

## Status

Proposed (2026-10-16) — 待 V0.2.0-1 用户确认后转 Accepted

## Background

V0.2.0 新增「倒计时」：与现有正计时共存的双模式，带时长菜单。任务要求：现有 `active|saved` 两态加倒计时语义（`target_sec` + 到点行为：自动结束 / 铃声 / 通知），并**复用单调时钟逻辑**。

候选实现：

- **A**：在 `time_records` 上**扩展模式**（`mode` + `target_sec`），**不新增状态**；到点由 Rust 后台判定。
- **B**：新增独立「倒计时」实体 / 独立状态机。
- **C**：到点由前端 tick 判定后调 `stop_timer`。

约束：计时状态机是**单一事实来源且归 Rust**（ADR 不变量，ARCHITECTURE-v1 §3.2）；必须与 `uq_records_open` 单 active 约束兼容；崩溃恢复 / 15s 落盘口径不变。

## Decision

**采用方案 A：`time_records` 加 `mode('countup'|'countdown')` + `target_sec`，状态机仍是 `idle|running|paused` 三态；到点判定归 Rust 的 1s 后台 watcher，结束时把时长钳制到 `target_sec`。**

具体锁定项：

1. **数据**：`time_records.mode TEXT NOT NULL DEFAULT 'countup'`、`target_sec INTEGER`（仅 countdown 非空，应用层保证 `>0`）。`TimeRecord` 与 `TimerState` 各加 `mode`；`TimerState` 另加 `remainingSec = max(0, target_sec - live)`（服务端快照，与 `liveDurationSec` 同源，避免同步跳变）。
2. **命令**：`start_countdown({ itemId?, targetSec })`；非法 `targetSec`（≤0 或 >24h）→ `INVALID_TARGET_SEC`。手动提前结束复用 `stop_timer`。
3. **状态机（不新增状态）**：
   ```
   idle ──start_countdown──▶ running(countdown) ⇄ paused(countdown)
                                   │
             [Rust watcher: live >= target_sec]  ─▶ saved（accumulated = target_sec）
             stop_timer（手动提前）              ─▶ saved（accumulated = live）
   ```
4. **到点判定归 Rust**：`infra/countdown.rs::spawn_countdown_watcher`，`tokio::interval(1s)`，若存在 `mode='countdown'` 的 active 会话且 `live_duration >= target_sec` → 结束（K-20）。**不由前端发起**，避免窗口隐藏 / WebView 挂起时漏触发（与「状态机归 Rust」一致）。
5. **钳制**：结束时 `accumulated_sec = target_sec`（精确落点，不受 tick 抖动）；`ended_at = started_at + target_sec*1000`（时长口径自洽，便于统计）。
6. **到点行为**：发系统通知（复用 ADR-010 的通知通道）+ `timer:state-changed`（idle）+ `countdown-finished` + 应用内视觉（`useAppBootstrap` `setNotice` + `flashEnded`）。
   > **V0.2.0 落地口径修订（2026-10-16，批2 回归 QA 后）**：到点行为本批实现为「**系统通知（随 OS 自带提示音）+ 应用内视觉**」，满足 AC-47「至少通知 + 视觉提示」。原设想的 **Web Audio API 铃声本批不实现**（K-22 自动播放策略有不确定性，且 OS 通知已带提示音），降级留待后续；**不影响 AC-47 达成**。见 `OPEN-DECISIONS.md` #9。
7. **单调时钟复用**：沿用同一 `live_duration(record, now_ms())` 公式（墙钟毫秒 + tokio 单调调度）；墙钟跳变只会导致「到点提前/延后一次」，不污染已落盘时长。

## Consequences

正面：
- 正/倒计时共用一条会话生命周期、索引、崩溃恢复与落盘逻辑，改动集中在 TimerService 分支。
- 到点判定归 Rust：窗口隐藏 / 挂起 / 休眠唤醒后仍能正确到点。
- `target_sec` 钳制保证倒计时记录时长精确等于目标，统计口径干净。
- 零新增依赖（到点用后台任务、铃声用 Web Audio）。

负面 / 需处理：
- 新增一个 1s 后台任务（无倒计时时每秒一次单行查询、早退）；开销可忽略，必要时可改为「仅 countdown 活跃时启用」。
- `ADD COLUMN` 不能带 `CHECK`（K-13），`mode` / `target_sec` 约束落在应用层。
- 墙钟跳变对到点时刻有一次性影响（已用钳制兜底）。
- 铃声受 WebView 自动播放策略限制（K-22）。
