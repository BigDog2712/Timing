# ADR-038：插件目录改为程序同级，不再写 `%APPDATA%`

## Status

Accepted（2026-11-04，0.1.1）。取代 `infra/plugin_fs.rs` 里「用户插件目录 = app_data/plugins」的旧口径。

## Background

插件目录原先落在 `%APPDATA%\com.tickbar.app\plugins`。这条规则是从「用户目录一定可写」推出来的，
在安装版上没毛病，但和本产品的实际用法相冲：

1. **TickBar 是绿色优先的工具。** 主推形态是解压即用的 portable exe，用户对它的预期是
   「整个文件夹拷走就能换机器」。程序旁边的插件跟着走，`%APPDATA%` 里的不跟——拷到新机器上
   插件就凭空消失了，而屏幕上没有任何线索指向 C 盘深处。
2. **同一条路径两套语义。** 原先同时扫 `<exe>/plugins`（标 `exe`，注释写着「随包分发，通常只读」）
   和 `app_data/plugins`（标 `user`）。用户看到两个 plugins 目录，只能靠猜哪个生效。
3. **删除不干净。** 「我不想要插件功能了」在便携语境下应该是「删掉插件目录」，
   而不是去 `%APPDATA%` 里翻。

## Decision

1. **用户插件目录 = exe 同级 `plugins/`**：`plugin_fs::user_plugin_dir` 由 `current_exe()` 的父目录推出。
2. **不再扫 `%APPDATA%\com.tickbar.app\plugins`**。该目录当前为空，无迁移负担；
   以后若发现历史插件，不做自动搬迁（搬用户文件比丢配置更危险）。
3. **`PluginSource::Exe` 只在两目录不同时才单独扫**。正常情况下它和 `user` 是同一个目录，
   再扫一遍会让同一批 `plugin.json` 以「同 id 被跳过」的红色错误条目重复出现。
4. **安卓 / iOS 例外**：APK 是只读包，`current_exe()` 指向系统进程，那里放不了可写目录，
   仍用应用私有目录。移动端本来也没有插件入口。
5. **受保护目录的代价如实暴露**：装到 `C:\Program Files` 这类位置时目录不可写，
   「打开目录」会报 IO 错误，设置页的路径也就点不开。不静默退回 `%APPDATA%`——
   退回去等于把这条 ADR 又推翻一次，用户还不知道自己的插件跑哪去了。

## Consequences

- 便利：绿色版「拷走即带上插件」成立；设置页显示的就是用户能直接打开的那个目录。
- 代价：**卸载会连 `plugins/` 一起删**（NSIS 里 `RMDir /r "$INSTDIR\plugins"`）。
  README 与发布说明已注明「自己写的插件先备份」。
- 代价：`scan()` / `scan_roots()` 的入参从 `app_data_dir` 改成**已解析好的用户目录**，
  免得函数内部既算路径又扫盘；测试因此可以把用户目录指到临时目录，
  不会去翻程序旁边的真实 `plugins/`。
- 插件目录不再是「程序数据」，不再受 `%APPDATA%` 备份/清理策略保护。
