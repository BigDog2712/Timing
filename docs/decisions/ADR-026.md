# ADR-026：常用摸鱼改为应用内置；摸鱼菜单瘦身；常用事项框回归

## Status

Accepted（2026-10-19，V0.3.9）

## Background

V0.3.2 的摸鱼菜单内容全部来自插件 `<插件目录>/plugin.json` 的 `quickTimers`，
暂停态右键数字 / 点事项名唤出；V0.3.8 又补了「暂停即自动弹出」。用户这一轮提了五条：

1. 「其他事项」行右侧的说明文字（`滚轮定长`）多余，去掉；
2. 菜单最下面三条会话操作（继续 / 结束并保存 / 放弃）**用鼠标都能做**，留着是噪音；
3. 常用摸鱼要能**自己管**：名称、时间、正计时还是倒计时，并能**排序**；
4. 左键事项名应弹出**常用事项框**（置顶 + 最近编辑 5 条 + 右下角「事项管理」小圆点）；
5. 悬浮面板唤出时，鼠标还没移到面板上就消失了——应先移入、再移出，约 1s 后才收。

其中第 3 条与 V0.3.2 的数据源直接冲突：用户明确「都是应用内置功能，非插件，不要写在插件里」。

## Decision

### 1. 常用摸鱼落 `settings` KV，不进插件、不加表

- 新键 `moyu.presets`，值为 JSON 数组 `[{ id, item, minutes, mode }]`，**顺序即展示顺序**；
- 与 `countdown.presets` 同一口径（JSON in KV），因此**不需要迁移**，也不新增命令
  ——读写走既有 `get_settings` / `update_settings`；
- 出厂三条（上厕所 10 / 摸鱼 25 / 吃饭 60，均倒计时）作为默认值：
  **键缺失或 JSON 损坏**才回落默认；**空数组是合法状态**（用户可以把条目删光）；
- 归一化在两端各一份（Rust `models::moyu::normalize_presets` + 前端 `normalizeMoyuPresets`）：
  空名丢弃、名称截断 40 字符、分钟钳 1..1440、id 补齐去重、总条数上限 20。
- `mode = countup` 时 `minutes` 只是占位，不参与开始计时（用户口径：时间仅对倒计时生效）。

### 2. 插件 `quickTimers` 不再驱动摸鱼菜单

按用户口径「非插件」，菜单只读 `Settings.moyuPresets`。插件系统本身（扫描 / 校验 /
设置页列表）保持不动，`quickTimers` 仍会在设置 → 插件里展示，但**不再注入菜单**。
这是本轮唯一的能力收缩，后续若要把插件贡献点接回来，需要先定义「内置 vs 插件」的展示边界。

### 3. 摸鱼菜单删掉三条会话操作

`继续计时` / `结束并保存` / `放弃这次` 全部下线：

- 继续：点圆环（或数字 / Space）；
- 结束并保存：右键圆环；
- 放弃：记录 / 事项窗口里的删除入口。

菜单只剩「常用摸鱼 + 其他事项 + 管理常用摸鱼」，高度也随之收紧。

### 4. 常用事项框回归（V0.3.1 删掉的那个浮层，重做版）

- 入口：**计时中 / 暂停态左键事项名**（暂停态的摸鱼菜单仍由右键数字 + 暂停自动弹出承担）。
  空闲态「新建事项」**保持直达内联命名**——用户口径「原来可以直接添加的功能要留着，
  同时也能通过悬浮框直接添加」，两条路并存，不是互相取代；
- 内容：置顶事项（`items.is_pinned`，后端 `is_pinned DESC, sort_order ASC, id ASC`）
  + 最近编辑（`updated_at` 倒序前 N 条，排除系统事项与已置顶项）。两组**不写标题文字**
  （用户口径：删掉「置顶常用事项 / 最近编辑」这类说明），只用一条分隔线区分；
- **框底常驻输入框**：「添加常用事项…」，回车 = 新建事项 + 置顶 + 排到置顶组末尾，
  **框不关、焦点回输入框**，方便连续添加。这是「通过悬浮框直接添加」的唯一入口
  （V0.3.9 早期曾用「新建事项…」一行，用户要求删掉那行换成输入框）；
- 点一行 = 切事项：该事项在管理卡里设了**默认倒计时**就按该时长起倒计时（计时中先
  `end_and_start` 再起倒计时）；没设则空闲直接开始（已用滚轮设过档位则起该档位倒计时）、
  计时中走 `switch_item(end_and_start)`（分段）；
- 右下角小圆点 → **管理卡**（形态对齐摸鱼管理，见下）；
- 固定任务不再有「托盘 → 编辑固定任务…」入口（该入口 V0.3.1 已删），置顶只在管理卡里改。

### 4.1 管理卡 = 摸鱼管理同款清单（排序 / 新增 / 默认倒计时）

- 列表**只列已置顶的常用事项**（不是全部事项的开关列表）：行 = 拖柄 + 名称 + 默认时长 + 移出；
- **排序靠拖拽**（拖柄 `draggable`，聚焦后 ↑ / ↓ 同样可调），落库把 `sort_order` 重写成 0..n-1；
  V0.3.9 早期摆过 ↑↓ 两个按钮，卡宽受小条窗口限制，两个按钮一占名称只剩「品牌视…」，已删；
- **新增 / 编辑共用一张表单**：名称 + 分钟（**留空 = 正计时**）。新增 = 建事项 + 置顶，
  编辑 = 改名 + 改时长；删除 = **移出常用**（取消置顶），事项本身保留；
- 默认时长存 `settings.itemsTimers`（settings KV `items.timers`，JSON `{ "<itemId>": 分钟 }`）：
  它只是「这个事项点下去多长」的偏好，与 `is_pinned` / `sort_order` 同层级，**不建表、不动表结构**；
- 「显示最近事项」：**开 = 高亮色、关 = 常规色**，不再画图标与对勾；条数从 3/5/8/10 档位按钮
  改为**开关行右侧的数字输入框**（默认 5，钳 1..10），落 `items.recent_count`。

### 5. 悬停收起改为「先移入、再移出 + 1s」

`useHoverClose` 新增 `requireEnter`：指针必须先进入过浮层（`.menu` / `.panel` / …），
离开后才开始计时；宽限由 420ms 提到 1000ms。自动弹出的摸鱼菜单与常用事项框启用该模式。
其余浮层保持 V0.2.7 行为（它们本来就是「在指针位置展开」，不存在「还没移过去就消失」）。
指针直接移出窗口（桌面）仍然立即计时收起。

### 6. 入口：点事项组件 = 新建输入框 + 常用事项框**一起出**；框内不提供新建

**最终口径（用户第三次纠正后定稿）**：空闲态小条上的事项组件（`.pill__empty`）左键一次，
同时出现两样东西：

1. 条上就地长出的**新建输入框**（`InlineNameEntry`，焦点在此，回车建好即开始）；
2. 条下方的**常用事项框**（置顶 + 最近编辑 + 右下角「事项管理」小圆点），可挑已有事项。

实现要点：uiStore 新增合成 action `openCommonItemsNew(pos)`，一次写入
`commonItemsPos` 与 `inlineEdit`。**不能分两次调**——`open*` 系列都先铺 `CLOSED`，后一步会把
前一步开的浮层顶掉，这就是「几次要么输入框在、要么常用框在」的根因。
`GlassMenu` 增加 `autoFocus`（默认 true），常用框与输入框同弹时传 false，焦点留给条上的输入框。

悬浮框里**仍然不提供新建**：早先的「新建事项…」行与常驻输入框都已删除。
落地后两者一起收：回车提交在 `usePillInlineEdit` 的 `finally` 里收；点行挑事项在
`CommonItems.choose` 里收（先 `closeInlineEdit` 再起计时）。

### 7. 打字时浮层不被「假离开」误收

`useHoverClose` 增加打字豁免：焦点落在浮层内的文本输入控件（`input` / `textarea` /
`contenteditable`）且窗口仍有焦点时，`documentElement` 上的 `leave` 一律不当作离开。
WebView2 在窗口尺寸/焦点变化、IME 候选窗弹出时会补派这种假 leave，表现为「打字打着框没了」。
真正的指针移出一定会先经过 `pointermove`（`handleMove` 里照旧起算），所以不会漏收。

### 8. 最近事项用框底小胶囊，不再占整行

用户口径：「最近事项形态改为最初版的小胶囊状，尽可能小巧显示」。

置顶事项是「要点开的那几条」，值得整行（图标 + 名称 + 默认倒计时 + 当前项勾选）；
最近编辑只是「刚才用过、顺手切回去」的候选，条数最多 10 条，全用整行会把框拉得很高
（208×145，其中大半是最近项）。因此改成：

- **18px 高的小胶囊**：`--text-cap` 字号、左右 6px、`--radius-full`、自然宽度横排、
  放不下自动换行；当前项 `--accent-wash` + accent 文字，其余 `--bg-field`；名字过长单行省略。
- **位置**：与右下角「事项管理」小圆点同一行（贴底对齐），省掉原本的一整行高度；
  有置顶项时保留一条分隔线，没有置顶时菜单就只剩这一行（实测 36px 高）。
- **实现位置**：`GlassMenu` 的 entries 只保留置顶行，胶囊走 `footer` 插槽 →
  不改 `GlassMenu` 的行协议（它已到 300 行上限），样式单独放
  `styles/common-items-chips.css`。代价是胶囊不在 `GlassMenu` 的键盘 ↑↓ 序列里，
  点击后要自己 `close()` 收框。
- **置顶行不带图标**（用户口径：去掉行首那个图钉）：`MenuItemEntry.icon` 改为可选，
  `GlassMenu` 只在传了的时候渲染。行首留白与文字左缩进沿用 `--menu-item-pad-x`，
  当前项的高亮竖线 / 右侧勾选不受影响；其他菜单仍照常传图标。

### 9. 事项窗口宽度 336 → 252（右键事项组件唤出的那个）

> **已被 ADR-027 §6 部分取代**：252 只是**面板**宽度；窗口为了左侧便利贴预览区扩到 **492**
> （= 252 面板 + 240 透明预览区）。本节对「面板从 336 收到 252」的结论仍然有效。

用户口径：「事项菜单栏宽度缩小四分之一 …… 是在事项组件右键点击唤出的菜单」。

小条上右键事项名（`ItemName.onMenu`）打开的是**事项窗口** `todos`（V0.2.6 起取代旧的
`ItemMenu` 直弹），所以缩的是窗口本身：

- `infra/window_spec.rs` 的 `TODOS`：`width` / `min_width` / `max_width` 336 → **252**
  （252 = 336 × 3/4），仍 `resizable: false`，高度区间 [360, 560] 不动。
- `todos-panel.css` 的 `.todos` 改用 `width: 100vw`：面板跟着窗口走，不再绑 `--todos-w`
  （那个变量留给主窗里的今日摘要面板，两者宽度解耦）。
- 窄窗副作用：底栏「编辑事项」会折行 → 两个按钮加 `white-space: nowrap; min-width: 0`。
- 窗口尺寸归 Rust 常量管，前端所有浮层（菜单 / 卡片）不在这次范围内。

## Consequences

- **契约不变**：60 命令 / 15 错误码 / 9 事件；版本号仍 0.3.0；无迁移
  （仅 `Settings` DTO 增加 `itemsTimers` 字段，走既有 `update_settings`）。
- 现有用户升级后菜单不空：`moyu.presets` 缺失 → 出厂三条。
- 插件 `quickTimers` 进入「声明保留、菜单不消费」状态（见 Decision 2）。
- 常用事项框与摸鱼菜单共用 `GlassMenu`，但顶部状态块只有摸鱼菜单传（常用事项框不需要再报一次当前会话）。
