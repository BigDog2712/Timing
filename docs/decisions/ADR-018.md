# ADR-018：错误码集从 16 扩到 17（`ITEM_NAME_TOO_LONG`）

## Status

Accepted（2026-10-18；关闭 `OPEN-DECISIONS` #6「待办 title 超长无专属错误码」，对应架构评估遗留的契约项）

## Background

`ErrorCode` 是一个**闭合** union，V0.2.0 起锁死 16 个，规则写在多处文档里：

> 「Spec §5 只授权新增 5 个，不得越权加第 17 码」

于是「文本超长」这件事一直没有合法表达方式。实际实现只能借用 `ITEM_NAME_EMPTY`：

```rust
// services/todo.rs（V0.2.0）
if trimmed.chars().count() > TODO_TITLE_MAX_LEN {
    return Err(AppError::new(
        ErrorCode::ItemNameEmpty,          // ← 语义是「为空」
        format!("待办标题长度不能超过 {TODO_TITLE_MAX_LEN} 字"),
    ));
}
```

代价不在后端，而在**前端**：`errorText()` 按 code 分派，于是「标题超长」被渲染成
「事项名称不能为空」。用户看到一句自相矛盾的提示——既没告诉他超了多少，也没指对字段。
更糟的是表单高亮：`ItemPicker` 里 `ITEM_NAME_EMPTY` 会走「空名称」分支，
而真正需要的「输入过长」分支不存在。

`messsage` 字段本来承载了正确的长句，但它**不是契约**：`check:contract` 只校验 code，
message 随时可能被改写，前端也不该按 message 文本做判断。

V0.2.0 期间把这条登记为 OPEN #6，结论是「可接受的技术债」，理由写得很诚实：
「错误码闭集契约硬约束 + 复用同码明确 message + 前端 maxLength 双保险」。
但双保险里有一环是假的 —— 后端根本没校验「事项名」长度，只有前端 `maxLength=60`。

## Decision

**加第 17 码 `ITEM_NAME_TOO_LONG`，同时把「闭集」的定义从「数量固定」改为「变更须评审」。**

1. 新增变体 `ErrorCode::ItemNameTooLong` → `"ITEM_NAME_TOO_LONG"`；
   构造器收敛成一个 `AppError::text_too_long(field, max)`，避免三个调用点各拼一遍文案。
2. 三个「超长」检查点全部改用它：
   - 事项名 `> 60`（`create_item` / `update_item`）
   - 待办标题 `> 200`（`todo_create` / `todo_update`）
   - 便利贴正文 `> 4000`（`note_create` / `note_update`）
3. **补上后端缺失的事项名长度校验**（`ITEM_NAME_MAX_LEN = 60`）。
   前端两处输入框限 60（`ItemPicker` / `InlineNameEntry`），后端此前不校验，
   绕过 UI 调 IPC 能存进任意长名称；而托盘菜单按显示宽度截断，数据与展示会不一致。
   前端常量 `ITEM_NAME_MAX_CHARS` 与后端同值，改动须两侧同步。
4. 「闭合」规则改写为：**基数可增，但每次增码必须同时满足**
   - `error.rs::as_str` 与前端 `ErrorCode` 联合类型同步（`check:contract` 强制）；
   - 契约文档 §2 补一行「触发条件 / 前端处理 / 可重试」；
   - 有一份 ADR 说明「为什么现有码表达不了」。

## Alternatives considered

- **维持复用 `ITEM_NAME_EMPTY`**：省一次契约变更，但前端永远分不清「空」与「超长」，
  提示文案与表单高亮都只能是错的。这项技术债的利息由**每一次用户输入**支付。
- **把 code 改名为 `TEXT_INVALID`、连「为空」一起合并**：会破坏 v0.1.0 起就存在的
  `ITEM_NAME_EMPTY` 语义，前端所有分支都要改，收益（少一个码）远小于破坏面。
- **前端按 message 文本判断**：把人类可读文案变成隐式契约，改一个字就静默失效，
  比技术债更糟。

## Consequences

- 前端 `errorText()` 新增一支「输入内容过长，请精简后再试」；具体字数由后端的
  message 承载，前端不必重复常量。
- `check:contract` 输出从 `错误码：16 / 16` 变为 `17 / 17`，这行就是本 ADR 的机械凭据。
- 旧库里的长名称不会被追溯清理（未提供迁移），只在**写入路径**拒绝新超长值。
  这条是刻意的：静默截断用户数据比留下一条超长记录更危险。
- 契约文档 §2 从「共 11 个，锁定」修正为「共 17 个」——它此前从未回写 v0.2.0 的 5 个码，
  属于**文档已与代码不符**，本次一并修复。
