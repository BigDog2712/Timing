# ADR-049：小圆点放大到 33px + 外环改「增长弧」+ 双击高亮与主窗重申置顶

## Status

Accepted（2026-11-06，V0.11.5；用户口径「圆点太小，放大一倍」+「外环不应该长度固定地绕圈」）

**部分取代 ADR-046**：尺寸与外环语义由本文取代，ADR-046 的其余口径（小圆点形态点开是临时条、移开收回）仍有效。

## Background

V0.11.1 把圆点从「76px 环 + 时分」改成 44px 纯图形秒表；V0.11.4（ADR-046）再缩到 22px，
并把外环定成「60 秒转一圈」的钟表口径。落地后用户实测有两处不对：

1. **太小。** 22px 是按「1x 屏上还看得清指针」定的，真机桌面上占地方到可以忽略，
   但它同时也是唯一的常驻状态指示——用户要的是「扫一眼就知道在计时」，22px 做不到。
2. **外环读不懂在演什么。** 实现是「90° 固定短弧 + 整组 `<g>` CSS 旋转，60s/圈」。
   指针在转，弧也在转，但弧**长度恒定**——视觉语言是「一段固定长度的东西绕着圆心跑」，
   而用户要的是「环从起始位置延伸出去，满一圈后重来」。两者不是同一件事，
   前者读不出「这一分钟走到哪了」。

同一批还暴露了两个独立问题，与尺寸无关但同属悬浮形态的可用性：

- **托盘双击高亮在圆点形态完全无效。** 高亮逻辑只挂在 `.pill` 上，圆点形态收不到反馈，
  用户双击托盘后不知道该看哪里。
- **几何变动后主窗会被盖住。** `tauri.conf.json` 的 `alwaysOnTop: true` 只在建窗那一刻生效；
  收起成圆点时前端会 `set_position` + `set_size`（`useWindowAutoFit`），
  实测几何变动后主窗会失去置顶、被别的窗口压住。

## Decision

### 1. 尺寸 22 → 33px，几何常量 ×1.5，描边不跟着等比

`--dot-size` 22px → **33px**，`CollapsedDot` 的半径 / 长度常量按 ×1.5 放。

但三处描边**不**等比：

| 常量 | 等比应为 | 实际 | 理由 |
|---|---|---|---|
| `RIM_STROKE` | 1.125 | **1.1** | 表盘线只做视觉分隔，1.125 与 1.1 在渲染上无差别，取整避免半像素 |
| `ARC_STROKE` | 2.7 | **2.4** | 弧是最粗的一笔，2.7 在 33px 圆内会挤掉内圈留白 |
| `NEEDLE_STROKE` | 1.65 | **1.5** | 针需要与弧拉开粗细层次，等比会让针看起来"变胖了" |

等比放大会得到 1.125 / 2.7 / 1.65，在 1x 屏上细描边会糊成一团灰——ADR-046 已经踩过一次
（44→22 时描边没有跟着减半，才保住了读数），这次同理，只是方向相反。

### 2. 外环改「增长弧」，删除整套旋转

- `frac = (displaySec % 60) / 60`，`march = false`：弧从 12 点开始**按时间比例变长**，
  60 秒长满一圈后回到起点重来。
- 删掉 `.dot__ring` 的 `animation: dot-turn`、`@keyframes dot-turn`、`.dot[data-turn]`、
  `<button data-turn>`。整组旋转不再存在，结构上外环那组 `<g>` 不带 `transform`。
- **暂停不做 270° 静弧**：已经没有动画可冻，`useTimerTick` 暂停后不再递新值，
  `displaySec` 停住 → 弧长自然冻在当前长度；暂停靠 `--color-warn`（底色/描边）区分，
  不靠一个假的「停表角度」。
- 适用范围是**正计时**（`running` / `paused`）。倒计时、待命、结束、空闲沿用
  `arcSpec` 给的静态弧——它们的"进度"语义本来就不同，不该被这条改掉。

### 3. 不复用 `arcSpec` 的 running 分支，而是在圆点内覆盖

`arcSpec` 的 running 分支是给**悬浮条色环**的「进行中」语言：90° 行进弧 + `march`。
圆点只有一枚环，它演的是「这一分钟走到哪」，与"有东西在跑"不是同一个语义。

所以做法是在 `CollapsedDot` 内用 `growth` 覆盖 `frac` / `march` / `thick`：

```ts
const growth = !isCountdown && (visual === 'running' || visual === 'paused');
const frac = growth ? (displaySec % 60) / 60 : arc.frac;
const march = growth ? false : arc.march;
```

`arcSpec` 与 `ringGeometry` **一字未改**，悬浮条行为不变。改共享几何函数来满足一个调用方，
是让另一个调用方承担语义漂移的代价。

### 4. 已知代价：每分钟空 1 个 tick

`displaySec % 60 === 0` 那一秒 `frac = 0`，命中 `isArcVisible` 的阈值
（`ARC_MIN_FRAC = 0.001`）→ **该秒不画弧**。

这是「60 秒循环」的必然结果，**刻意保留**：不改成 `+1/60`。
改成 `+1/60` 会让整分钟那一下从满圈直接跳成 1/60，视觉上比空一秒更跳；
而 `isArcVisible` 这条阈值本身是为了避免 `round` linecap 在零长度处留下一个描边宽的亮点
（同 `MainButton` / `TimerRing`），不是为了这个场景临时加的，不该为它开口子。

### 5. 托盘双击高亮扩展到圆点

- 圆点订阅 `highlightSeq`（与 `PillBar` 同一个 ui store 信号）、挂 `data-highlight`。
- 高亮用 `--highlight-color` 画**内侧**环（`box-shadow: inset`）+ 22% 底色：
  圆点窗口 `pad = 0`，外发光会被窗口边界裁掉，只有内阴影能完整看见。
- 节奏与悬浮条一致：`0.8s × 3`。
- `HIGHLIGHT_MS = 2500` 从 `PillBar` 的本地常量收进 `lib/constants.ts`，两处共用——
  两个形态闪的总时长不一致，用户会以为是"有时灵有时不灵"。
- 与 `data-warn` 的 opacity 动画**并列不抢属性**：高亮只动 `box-shadow` 与
  `background`，不碰 `color`，否则会顶掉状态色（暂停的黄、倒计时末段的红）。
  两者同时成立时用多动画叠加（`.dot[data-warn][data-highlight]`）。

### 6. 主窗重申置顶，不新增 IPC 命令

- `infra::window::show_main()` 在 `show()` 之后重申 `set_always_on_top(true)`。
- `on_window_event` 里，主窗的 `Resized` / `Moved` 之后重申一次；失败只 `log_warn`，
  不 panic（置顶失败不该让计时停下来）。
- **不新增 `set_topmost` 之类的命令**：命令 **67** 是契约（ADR-022 之后置顶是恒定行为，
  没有用户可切换的开关），为内部维护动作加一条命令等于让契约面变宽而没有新能力。
- 不会自激：置顶本身不改尺寸/位置，不会再次触发 `Resized` / `Moved`。

## Alternatives

| 方案 | 否决原因 |
|---|---|
| 只改形态（增长弧）、不改尺寸 | 用户的第一诉求就是"太小"，22px 下增长弧更难看清；只改形态等于只解决了半个问题 |
| 保留整组旋转，只把 90° 短弧换成更长的弧 | 长度仍在「60 秒内恒定」，还是"固定长度的东西绕着转"；用户否的正是这个语言 |
| 复用 `arcSpec` 的 running 分支（改 `arcSpec` 让圆点也走 90° 行进弧） | `arcSpec` 是悬浮条色环的共享几何，为一枚环改它会改变悬浮条；共享函数只应被调用方适配，不该被调用方改写 |
| 新增 `set_topmost` IPC 命令解决被盖住 | 命令 67 是契约面；这是"宿主对自己的窗口做维护"，不是一项用户或插件可调用的能力（ADR-048 的白名单原则同款判断） |
| 用外发光（`box-shadow` 外阴影）做高亮 | 圆点窗口 `pad = 0`，外阴影会被窗口边界裁掉，画了也看不见 |
| 整分钟补 `+1/60` 消除空窗 | 会让整分钟那一下从满圈跳成 1/60，比空 1 秒更跳；且要给 `isArcVisible` 的阈值开口子 |
| 暂停时画一个 270° 的"停表"静弧 | 弧长已经是"这一分钟走到哪"，再叠一个角度信息会两个读数打架；颜色（`--color-warn`）足够区分 |

## Consequences

- **每分钟空 1 个 tick**（`displaySec % 60 === 0` 那一秒不画弧），用户可感知但不可操作，
  属显式取舍。`CollapsedDot.test.tsx` 有断言锁住 `frac` 的算法与「零值不画」。
- **暂停靠颜色，不靠角度**：`data-warn` 负责"停住了"，弧长负责"走到哪"，两个信号不重叠。
- **每次 `Moved` 都会打一次 Win32 `SetWindowPos(HWND_TOPMOST)`**：原生拖拽期间
  这个回调会按帧频率触发，等于每帧一次系统调用。**真机需确认拖动是否有卡顿 / 抖动**
  —— 这条**未验证**（本轮只验证了"拖动后不再被盖住"，没有逐帧测过拖拽流畅度）。
  若真机出现卡顿，退路是**改成拖动停止后再重申**（`Moved` 静默一小段时间后补一次，
  拖动期间一次都不打），而不是去掉重申。
- **`arcSpec` 与悬浮条零影响**：`ringGeometry` / `arcSpec` 未改动，
  既有色环用例全绿，悬浮条的进行中弧行为与 V0.11.4 完全一致。
- **`--dot-size` 仍只有一处定义**：`src/styles/design-tokens-compat.css:70 = 33px`。
  几何常量仍只在 `CollapsedDot.tsx` 顶部一处（`SIZE = 33` 与三个描边常量），
  样式从令牌读尺寸、组件从常量算半径——两处都不许出现第二份 33。
- **`HIGHLIGHT_MS` 成为两个形态的共用真值**：改它 = 同时改悬浮条与圆点的闪烁时长，
  这是刻意的（两个形态是同一个应用的两种外观）。
- **ADR-046 只被部分取代**：尺寸链（44 → 22 → 33）与外环语义（旋转 → 增长）由本文接管；
  「点开圆点是临时条、鼠标移开 300ms 收回」那条口径仍有效，未变。
