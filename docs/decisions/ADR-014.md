# ADR-014：主窗改「内容自适应尺寸」——用窗口收缩代替透明区点击穿透

## Status

Accepted（2026-10-17，用户反馈驱动：`悬浮面板下有占用，无法正常点击其他应用，应修复`）

> **部分被 ADR-020 取代（2026-10-18）**：本文「画布仍是 384×360、只收缩 OS 窗口」的前提已不成立
> ——画布被删除，坐标上界改为「显示器工作区」，`--window-w/--window-h` → `--fit-w/--fit-h`，
> `canvas.ts::canvasViewport()` → `fitBounds.ts::fitBounds()`。
> 仍然有效的是核心机制：「量内容包围盒 → `setSize` / `setPosition`」与
> 「遮罩不算内容但要下钻」两条。文中的 384×360 上限、`maxWidth/maxHeight = 384/360`
> 与 `.menu-scrim` 铺满画布的表述请以 ADR-020 为准。

## Background

主窗 `main` 自 V0.1.0 起是**固定 384×360 的透明置层**（`tauri.conf.json` 里 `minWidth/maxWidth` 双双钉死在 384×360，`app.css` 的 `html/body/#root/.layer` 也按 `--window-w/--window-h` 排版）。小条本体只占 ~300×32，其余是视觉透明区。

问题：`.layer { pointer-events: none }` **只是 CSS 层语义**，对 **OS 窗口矩形无效**。WebView2 窗口覆盖多大地盘，鼠标事件就被吃掉多大一片——透明区里的点击既不给小条、也不给桌面，用户点不到下面的应用（P1 缺陷）。

Windows 侧能「让透明像素穿透」的经典做法是 `WS_EX_LAYERED` + `UpdateLayeredWindow` 做逐像素 alpha 命中测试，但那是**原生绘制栈**的做法，**不能用在 WebView2 上**（WebView2 没有 `UpdateLayeredWindow` 渲染路径）。候选：

- **A**：`WS_EX_TRANSPARENT` + 全局低级鼠标钩子，按光标位置动态开关穿透。可行但需要 `SetWindowsHookEx(WH_MOUSE_LL)` 全局钩子（安全敏感、跨进程事件风暴、装杀软口径差），成本与风险都高。
- **B**：**把真实 OS 窗口收缩到可见内容包围盒**，画布仍是 384×360。零原生代码、零新依赖。
- **C**：放弃 WebView2 改原生绘制（layered window）。不可接受。

## Decision

**采用方案 B**：主窗 `main` 的 OS 窗口尺寸 = 可见内容包围盒（上限仍是 384×360 画布），由前端驱动。

要点：

1. **画布与窗口解耦**：CSS 侧画布仍是 `--window-w/--window-h`（384×360），**所有浮层坐标、视觉位置零改动**；`src/hooks/useWindowAutoFit.ts` 每帧（MutationObserver + 250ms 兜底轮询）量可见内容的**四条边**并集，算出画布内偏移 `(L, T)` 与尺寸 `(W, H)`，差值 <2px（尺寸）/ <1px（位置）不动，避免抽搐。
2. **原点补偿，内容零位移**：只缩 `right/bottom` 会在窗口左上角留下 `.layer__stack` 的 `--snap-margin`（16px）与 `--pill-inset`（6px）两条看不见的挡片亲测仍在吃点击。所以窗口尺寸改为 `W×H`、位置同步 `+(L, T)`：裁掉的正好是四周留白，**屏幕上的内容一个像素都不动**。偏移量写 `localStorage['timing:fit-offset']`，首帧先按它还原（`window-state` 恢复的位置是「上一轮补偿后」的，不还原就会跳 16px）。权限需 `core:window:allow-outer-position`。
3. **贴边钳制改读画布**：凡是「按视口算」的坐标都换成画布尺寸 —— 否则窗口一收缩，`window.innerWidth` 变成小条宽度，菜单会被硬挤到小条上。新增 `src/lib/canvas.ts::canvasViewport()`（主窗读 CSS 变量，其余窗口回落真实视口），`GlassMenu` / `CountdownCustom` / `ReminderPopover` 已切换；`menu.css` 的 `100vh` 限高与 `today-digest.css` 的 `80vh` 限高在主窗改为 `--window-h` 口径（`html[data-window="main"]` 作用域）。
4. **放开尺寸夹钳**：`tauri.conf.json` 主窗 `minWidth/minHeight` 由 384/360 改为 **1/1**（`maxWidth/maxHeight` 保持 384/360）。不放开的话，Windows 的 `WM_GETMINMAXINFO` 会把 `setSize` 夹回 384×360，收缩完全无效。`resizable:false` 不变（程序化 `set_inner_size` 不受该标志限制）。
5. **权限**：capability 增加 `core:window:allow-set-size`（`src-tauri/capabilities/default.json`）。
6. **浮层开合 = 窗口长大/缩回**：菜单/面板/撤销条/提示/倒计时卡出现在包围盒里，窗口自动长大到能装下（实测：只有小条时 178×64、右键菜单展开 230×356、今日日记面板 368×346、恢复对话框 342×302，关闭后逐级缩回）。
7. **遮罩不算内容、但要下钻**：`.menu-scrim` / `.dialog-scrim` 自己永远铺满 384×360 画布，直接量它们会把窗口重新撑回整张画布（等于 bug 没修）；但 `.dialog-scrim` 里装着真正的对话框，所以量它的**孩子**、跳过遮罩本身。窗口外的点击本来就不进窗口，「点外收起」由 `src/main.tsx` 的窗口失焦（blur）兜底。
8. **排版容器要展开**：`.layer__stack` 自己（以及任何带内边距的容器）的矩形含留白，量它等于把透明带原样留在窗口里 —— 首轮实测窗口 198×64、而小条只有 175×32，差的就是 6px/16px 边。`pushExpanded()` 把 `.layer__stack` 递归展开成元素孩子，只量画出来的那块；展开后实测窗口 = 小条矩形，`(0,0)` 起。新增浮层若再套一层容器，同样会被展开，无需额外登记。
8. **`.layer` 必须是 `position: fixed`**：窗口比画布小以后，视口只有 64px 高，若 `.layer` 还在流内，`focus()` / `scrollIntoView` 会把根滚动条推起来，画布坐标整体平移 —— 实测菜单打开时小条被推到 `y=-100` 直接飞出窗口。固定到视口原点后，程序化滚动再也搬不动它；`useWindowAutoFit` 另加 `scrollX/scrollY` 补偿双保险。

## Consequences

正面：

- **透明区不再吞点击**：平时窗口只有小条（或折叠点）那么大，其余桌面完全可用。
- 零原生改动、零新依赖；画布坐标与视觉**零漂移**，面板/菜单布局一行没动。
- 与 `window-state` 兼容：持久化的尺寸会被 `maxWidth/maxHeight` 夹到 ≤384×360，首帧 `useWindowAutoFit` 再纠正到实际内容尺寸。

负面 / 已接受的代价：

- **窗口尺寸不再恒等于画布尺寸**。任何「窗口尺寸 = 画布尺寸」的隐含假设都是雷（本次已清扫 `window.innerWidth/Height` 与 `vh` 用法）；后续新增浮层定位必须走 `canvasViewport()`。
- **投影被窗口边缘切掉**：浮层收起依赖窗口失焦（`main.tsx` 的 blur），若为投影留出 `box-shadow` 的墨水范围，浮层四周就会多一圈「点了没反应」的死区，第一下点不关菜单。取舍是**保留即时收起**，放弃外投影（试过外扩，已撤回）。
- 每次浮层开合会触发 1–2 次 `setSize`（rAF 去抖 + 飞行中互斥），有极小的尺寸抖动可能。
- `reclamp`（AC-23）仍以物理像素比较矩形，窗口变小后「越界回主屏中心」的位置会更贴内容，无功能影响。
- **便利贴窗不采用此模型**（仍是固定几何 + 右下角缩放手柄，见 ADR-009）；它的「整面板可拖动」是另一条修复（`useWindowDragAnywhere`）。
- **发布构建必须带 `custom-protocol`**：`cargo build --release` 单独跑出来的二进制仍连 `devUrl`（`http://localhost:1420`），脱离 dev server 就是白窗 —— 本次排障在这上面绕了一圈（白窗里 `.layer` 不存在，`useWindowAutoFit` 直接早退，看起来像「修复无效」）。正路是 `scripts\build-release.cmd`（`cargo clean --release -p timing` + `cargo build --release --features custom-protocol`）。
