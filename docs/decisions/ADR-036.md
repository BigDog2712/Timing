# ADR-036：撤回 `mdSync` 插件贡献点，Markdown 同步回归宿主内建

## Status

Accepted（2026-11-04，V0.4.x / Unreleased）。取代 ADR-033 里「`mdSync` 作为插件贡献点」部分；
ADR-033 的其余结论（声明式插件、`MD_SYNC_CONFIG_INVALID`）继续有效。

## Background

ADR-033 把 Markdown 同步做成了插件：`plugins/md-sync/plugin.json` 声明三个落点，
宿主 `services/md_sync/` 执行读写。方向是对的——**插件不该能跑任意代码**——但落地后留下
两个说不通的地方：

1. **卸载不是卸载。** 删掉 `plugins/md-sync` 目录，设置页「同步」页签还在（`SettingsPanel`
   里硬编码在 `TABS`），后台定时任务还在跑（`bootstrap` 无条件 spawn），DB 表照建，
   只是落点为空。真正的插件应该是「目录不在 = 功能不在」，而同步代码（Rust 八个文件、
   `MdSyncTab`、`mdSyncStore`）一直编在主包里，删不掉。
2. **插件只能改参数，加不了功能。** 贡献点只有 `quickTimers` 和 `mdSync.bindings`，
   本质都是往已有功能里填数据。`EntryKind::Script` 是明确拒载的预留位。所以
   「创建插件给应用增加功能」这件事，当时的架构做不到。

而且 `config.rs` 里把 `id == "md-sync"` 写死了，等于全局只能有一个同步提供者——
第三方想提供另一种导出方向也插不进来。

用户的口径：「md 同步功能不做成插件了，支持落点的修改，插件功能继续开发。」

## Decision

1. **`mdSync` 贡献点移除**：`PluginContributes` 只剩 `quick_timers`；`PluginInfo` 不再回传
   `mdSync`；`MdSyncView` 删掉 `installed` / `pluginId` / `pluginName` / `pluginVersion`。
   老清单里多写的 `mdSync` 被静默忽略（解析策略本就是「字段不认识就忽略」），不会拒载。
2. **出厂落点收进宿主**：原 `plugin.json` 的三条落点搬到 `services::md_sync::config::default_bindings()`。
   保存过的配置仍然优先，`merge_bindings` 的「按 kind 补新种类」逻辑原样保留。
3. **`app_data_dir` 从同步模块移除**：`load` / `run` / `tick` / `open` / `save_config` 都不再
   接收目录参数——同步不再需要扫插件目录。命令层因此少一次路径解析。
4. **插件页与同步页解耦**：`PluginsTab` 的「配置 →」按钮和 `onOpenMdSync` 回调删除；
   同步页自己就在设置里，不需要从插件列表绕过去。
5. `plugins/md-sync/` 目录删除（git 历史可追）。

**为什么不干脆把同步整段搬进插件？** 它要读写任意路径、后台定时、写数据库——这些能力
无论由谁声明，都必须由宿主实现成接口，插件只是调用方。搬出去之后 `infra/md_file.rs`、
定时任务、DB 仍然在主包里，真正挪走的只有业务逻辑，代价却是给两端引入脚本运行时
（桌面 Boa/QuickJS，安卓另找一套 JVM 侧引擎）。用高成本换「目录可删」的观感，不划算。

## Consequences

- 删掉 `plugins/md-sync` 不再影响同步：落点来自 `default_bindings()`，保存值在 `settings`
  表的 `plugin.md-sync.config`（键名保留 `plugin.` 前缀，避免为改前缀写数据迁移）。
- 想改落点：设置 → 同步，直接改根目录 / 文件模板 / 标题，保存即同步一次。
- 插件系统少了一个贡献点，但**边界更干净了**：插件只做「声明数据」，不做「配置携带者」。
  下一步若要支持「插件加功能」，需要的是 UI 落点 + 受限动作目录（见 NEXT-STEPS），
  而不是让每个内置功能都伪装成插件。
- 测试跟着改：删掉两个只覆盖 md-sync 清单的用例（`md_sync_requires_api_v2…`、
  `repo_md_sync_plugin_manifest_is_valid`）与 `tests/plugin_dev.rs`（它唯一的断言就是
  「仓库 md-sync 被 dev 扫到」），新增 `factory_bindings_cover_every_kind`。
  测试夹具 `env()` 不再写测试插件，但「三种 kind 都锁到临时目录」的安全底线保留——
  它现在防的是 `default_bindings()` 里那条作者本机的 OneDrive 路径。

## Alternatives considered

| 方案 | 为什么没选 |
|---|---|
| 保留插件，只把 UI 改成「没插件就隐藏页签」 | 卸载仍然是假的：任务照跑、表照建、代码照在包里 |
| 双向兼容：插件声明落点 + 宿主内置默认 | 两套来源会打架，`merge_bindings` 要处理「插件写的 vs 代码写的」，排查成本翻倍 |
| 用 `#[cfg(feature)]` 编译期裁掉同步 | 能减包体，但用户运行时仍卸不掉；只在分发给别人且在意体积时才有意义 |
| 同步整段搬进插件（脚本化） | 见 Decision 末段：主要成本是两端各一套脚本运行时，收益只是目录观感 |
