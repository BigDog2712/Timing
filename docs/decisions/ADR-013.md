# ADR-013: 托盘菜单保留原生菜单（不自绘）

## Status

Accepted (2026-10-16，用户裁决) — 否决自绘方案（方案 B）

## Background

V0.2.0 产品前提之一是「**对标 Timing v1.7.0**」。Timing 的托盘菜单为自绘玻璃面板（`docs/design/pages-V0.2.0/tray-menu.md` 定义 272px 玻璃 + 状态块 + 按状态裁剪）。架构初稿据此评估了自绘路径。

**技术约束（已联网核实）**：Tauri v2 的托盘菜单由 `tray-icon` + `muda` 构造，Windows 平台上就是原生 Win32 `HMENU` + `TrackPopupMenu`（macOS 为 `NSMenu`）。**原生菜单无法用 CSS / 令牌控制外观**——不存在「给原生菜单换皮」的路径。

候选：

- **A**：保留 Tauri 原生托盘菜单。零成本；外观跟随系统（与主 UI 两套语言，**与 Timing 不一致**）。
- **B**：禁用原生菜单；`on_tray_icon_event` 收到点击后在**光标坐标**弹出一个**透明置顶 `WebviewWindow`**，内含自绘 `GlassMenu`。外观对齐 Timing，但约 **2–3 人日**成本，且需自管焦点/关闭/键盘/多屏/层级。

## Decision

**采用方案 A：保留 Tauri 原生托盘菜单，不做自绘。**

依据：**用户裁决**——方案 B 的成本（约 2–3 人日）相对收益不划算，**用户明确接受「托盘菜单外观与 Timing 不一致」**。架构推荐（B）被否决，记录在案。

具体：

1. 托盘图标继续 `TrayIconBuilder` + 原生菜单（`muda`）；不变更 V0.1.0 的托盘机制。
2. **内容组织（方案 Ⅰ，定案）——按状态裁剪**：**状态迁移时重建原生菜单**——空闲仅「开始正计时」等可用项；计时中「暂停 / 结束并写入事项计时 / 放弃」；暂停中「继续 / 结束 / 放弃」；常态约 **8–10 项**；「视图 / 打开 / 系统 / 退出」组**常显**。
3. **状态块降级（取 B）**：顶部加一条 `enabled=false` 文本项，文案与 `MenuStatusBlock` 同口径（空闲 `空闲 · 点开始正计时`；计时中 `任务名 · 12:34`；倒计时 `任务名 · 倒计时 · 剩 07:26`）。**纯文本、无圆点/无富样式**；任务名先截断（≤ ~20 显示宽）——原生菜单按最宽项撑宽、不省略（K-30）；秒级文本用 `MenuItem::set_text` 更新，**不每 tick 重建**。
4. **外观特性**：原生菜单**自动跟随系统深色模式**（但**不跟随应用 `data-theme`**，K-29）；**失去玻璃外观**。
5. **应用内菜单不受影响**：小条右键 / 事项右键 / 便利贴右键均在 WebviewWindow 内绘制，**仍走自绘玻璃 `GlassMenu`**。
6. **IPC 不新增**（服务端契约仍 52 条）。

## Consequences

正面：
- **零成本**、零新增依赖、零新窗口；开发与维护最省。
- 键盘导航、无障碍（读屏）、失焦/点外部关闭、多显示器定位、任务栏层级行为**全部由系统保证**，无需自管。
- 信息架构（分组 / 分隔 / 启用禁用 / **按状态裁剪**）**完整保留**；状态可经顶部禁用文本项呈现。

负面 / 已接受：
- **外观不达标**：托盘菜单与主 UI / 应用内悬浮菜单两套语言，**与 Timing 不一致**（用户已接受此代价）。
- **能力降级**：① **玻璃外观失去**；② **状态块降级为顶部一条禁用文本项**——不再是富样式可视块（原生菜单无法渲染我们锁定的 lucide SVG）。
  - **依赖核查结论**：**无别处依赖**被破坏——`MenuStatusBlock` **组件**在**应用内悬浮菜单**中仍原样复用（`tray-menu.md §1` 的「与悬浮菜单共用」正是此意），仅**托盘不再调用**它；玻璃外观同理，仅托盘退回系统外观，其余弹层/面板不受影响。
  - **P0（已裁定，从紧）**：状态项**一律纯文本**，不加任何圆点 / 字符符号充当图标（原设计前缀 U+25CF 已弃用；原生菜单无法用 SVG）。

升级路径：若未来（v0.3+）要求托盘对齐 Timing 玻璃外观，再回到方案 B（见下）。

## 未来可选增强（v0.3+，方案 B 备查 — 保留不删）

若后续版本决定提升托盘观感，可切换方案 B：

- 禁用原生菜单（`TrayIconBuilder` 不设 menu、`show_menu_on_left_click(false)`）；`on_tray_icon_event` 收到 `Click{ position }` 后在光标处弹出预建的**透明置顶 `WebviewWindow`**（`label = tray-menu`），内含自绘 `GlassMenu`（与应用内菜单同一组件）。
- 关键约束（届时复用）：
  1. 窗口：`transparent:true`、`decorations:false`、`shadow:false`、`skipTaskbar:true`、`alwaysOnTop:true`、`resizable:false`；**启动预建隐藏窗**消除首次 ~100–200ms 延迟。
  2. 关闭：`WindowEvent::Focused(false)` → `hide()`；`Esc` → `hide()`；失焦后 150ms 校验前台窗兜底。
  3. 键盘/无障碍：`GlassMenu` 自管 ↑↓/Home/End/Enter/Esc/Tab-out + `role="menu"`。
  4. 多屏：`TrayIconEvent` 坐标 × `scaleFactor` → 目标屏 `work_area` 钳制 + 右下翻转。
  5. 成本约 2–3 人日；风险见 ARCHITECTURE K-25。
- 届时**信息架构（状态块 + 按状态裁剪）可在自绘方案中完整还原**。
