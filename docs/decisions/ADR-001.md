# ADR-001: 使用 Tauri 2 作为桌面应用框架

## Status

Accepted (2026-10-16)

## Background

TickBar 是常驻 Windows 的轻量悬浮计时工具，核心诉求是**低内存、低占用、小安装包、快速冷启动**，同时需要 5 项系统集成能力：无边框置顶悬浮窗、全局快捷键、系统托盘、开机自启、本地持久化。候选框架：Tauri 2、Electron、.NET 8（WPF/WinUI 3）、Flutter Desktop。

关键约束：团队为 Web 技术栈；MVP 需快速迭代；无后端、纯本地。

## Decision

选择 **Tauri 2（`tauri` crate 2.12.4，Rust ≥1.90）**，前端使用系统 WebView2 渲染。

理由：
1. 体积/内存/冷启动全面优于 Electron（约 3.8MB / 45-90MB / 120-150ms，对比 Electron 约 130MB / 210-310MB / 400-890ms），与「轻量常驻」定位直接对齐。
2. 五项系统集成**全部有官方插件一等支持**（`tauri::tray`、`tauri-plugin-global-shortcut`、`tauri-plugin-autostart`、`tauri-plugin-window-state`、`tauri-plugin-sql`），无需手写 Win32 P/Invoke。
3. 无边框+置顶+`skipTaskbar`+透明为窗口配置一等能力。
4. Web 技术栈团队上手快、UI 还原成本低。
5. 不选 .NET：XAML 迭代慢、自定义窗口与热键需手写 Win32，MVP 速度与团队熟悉度不利。不选 Electron：体积/内存与产品定位冲突。不选 Flutter：桌面托盘/热键生态仍需第三方兜底。

## Consequences

正面：
- 安装包与内存占用显著优于 Electron，符合产品定位。
- 全局快捷键、托盘、自启、窗口状态、SQLite 均官方支持，集成成本低。
- 前端可用成熟 Web 生态与 HMR，迭代快。

负面：
- 依赖系统 WebView2 运行时（Win10 老版本需内嵌 bootstrapper，见 W-1）。
- Rust 侧需维护领域逻辑与 IPC 命令，对纯前端团队有学习曲线。
- 需注意 Windows 透明窗口白闪、DPI 换算等平台细节（见 ARCHITECTURE §9）。
