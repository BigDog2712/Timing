# ADR-028：待办行「点哪改哪」+ 两项时间可见可空置；时间浮层截断冒泡

## Status

Accepted（2026-10-19，V0.3.10）

## Background

ADR-027 落地「新增待办卡 + 待办行去圆点」之后，用户同一轮提出两条：

1. 「在事项组件右键唤起事项菜单后，新增待办的逻辑有误」；
2. 「编辑事项时，应可编辑事项时间、名称，点击哪里可以改变哪里」。

追问后口径收敛为两句：「**待办时间写不进去，待办时间应可空置**」+「**名称 / 开启时间 / 截止时间三项都能点开改**」。

排查结论（三条都被代码/测试证实）：

- **`todos.remind_at`（开启时间）自 V0.3.9 起从未被渲染过**。新增卡把它写进库，行上却只画 `planned_at`，
  用户既看不到也改不了，于是判为「写不进去」——不是写入失败，是**写进去以后没有任何地方能看见 / 修改**。
- 两条时间此前**没有任何事后入口**：`todoStore.rename` 只改标题，`todo_update` 的 `plannedAt` / `remindAt`
  在契约里本来就有，只是一直没有 UI 调用它。
- **真 bug（组件测试抓到的，不是推理）**：`DateTimePicker` 用 `createPortal` 挂到 `body`，但 portal **只改 DOM 位置、
  不改 React 的冒泡路径**。此前它在新增卡里没人接 `onClick`，所以相安无事；一旦放进「整行点击 = 勾选完成」的待办行，
  「点日历上的某一天」会顺着组件树冒到行上，把这条待办一起勾成已完成。

## Decision

### 1. 待办行改成两枚时间胶囊，铃铛归位

- `开启时间` → `bell`（12px `--color-warn`）+ 时刻；`截止时间` → 时刻 / 「已逾期」/ 「未设时间」。
  只看得到 `planned_at` 的那一半，正是「时间写不进去」的观感来源。
- 提醒铃从名字后**挪进开启胶囊**：铃铛表达的本来就是 `remind_at`，贴着时间才读得懂。
- 只用 `--ink-4` / `--todo-overdue` / `--todo-no-time` 三档语气，仍然不引入图标语法；截止项继续跟 `data-tone`。

### 2. 编辑模式下「点哪改哪」，只读模式不添乱

底栏「编辑事项」= 行内编辑模式，开关打开后：

| 点击面 | 行为 |
|---|---|
| 名称 | 就地换 `InlineEditBar` 改名（`Enter` 提交 / `Esc` 取消）。**行尾铅笔删除**——改名面就是名字本身 |
| 开启胶囊 | 弹 `DateTimePicker`，只写 `remind_at` |
| 截止胶囊 | 弹同一个浮层，只写 `planned_at` |
| 行尾 `trash` | 乐观删除 + 撤销条（AC-32，不变） |

- 胶囊一律 `stopPropagation`：点时间不会顺手把待办勾成完成；整行其余区域仍是开关（`role="checkbox"` 不变）。
- 只读模式下胶囊**纯读数**（点了不做事、也不渲染空位），避免「随便一瞄就弹浮层」。
- 编辑态截止胶囊显示**具体时刻**（语气色仍表达逾期）；只读态才用「已逾期 / 未设时间」这类措辞。

### 3. 两项时间都可空置、都可清空

- `null` 是合法值：`todo_update` 的 `TodoPatch` 已有 `double_option` 三态（缺省=不改 / `null`=清空 / 有值=改），
  前端只要**显式把 `null` 放进 patch** 就能落成 SQL `NULL`。
- 编辑模式里未设的一项渲染虚线空位（开启画小铃铛、截止画小时钟 —— 两枚并排的「+」分不清谁是谁），
  点开即可补；设过的能点浮层里的「清除」改回空。
- 未设截止仍显示「未设时间」而不是空白，保留 V0.3.9 的语气提示。

### 4. 校验收敛到一个纯函数

`lib/todoTimes.ts::todoTimePatch(todo, 'remind' | 'planned', ms) → { ok, patch } | { ok: false, error }`：

- 唯一规则「**截止不能早于开启**」（与新增卡 `TodosComposeCard.submit` 同一条），任一侧为空就不比较；
- 非有限数直接拒；`ms = null` 视为「清除」，不是「不改」；
- 提交被拒时浮层**立刻收起**，避免浮层里的草稿与已落库的值分叉（`TodoTimeChip.onCommit` 返回 boolean 正是为此）。

### 5. `DateTimePicker` 根节点截断鼠标事件（真 bug 修复）

浮层根节点补 `onClick / onDoubleClick / onContextMenu` 的 `stopPropagation`，与既有的 `onKeyDown` 同一收口位置。
放在浮层里而不是调用方：新增卡、行内改时间、以后任何消费者都自动受益。

### 6. 数据层只加一个动作，契约零改动

- `todoStore.patch(id, patch)`（`rename` 改为走它，行为与报错口径不变）、`todosActions.patch`；
- 复用既有 `todo_update`：**零新命令、零迁移、零错误码**，`check:contract` 60/60 不变。

### 7. Revision（V0.3.11）：显示格式回到「和计时一致」

用户随后一句「待办事项的显示格式应该和计时一样，没指定时间的右侧空白即可，有开始时间的就按开始显示」，
把 §1 的两枚胶囊推翻了 —— 胶囊在 252 面板里既挤（名称只剩约 82px），也不合「和计时一样」的观感。改为：

- **只读态右列 = 一格 `.todo-pend__time`**（等宽 11.5 / `--ink-4`，与 `.todo-row__time` 同款）；
  取值 `remind_at ?? planned_at`，两者皆无则**留白**；逾期时与名字同走 `--todo-overdue`。
- **编辑态才展开**成「开始 / 截止」两个**纯文字**时间位（无胶囊、无图标），未设的那项是虚线「+」。
- **铃铛从待办行彻底移除**（只剩「今日计时」记录行还挂 `items.remind_at`），「已逾期 / 未设时间」措辞随之取消。

保留不变：§2 的「点哪改哪」、§3 的空值语义、§4 的校验纯函数、§5 的 portal 事件边界。

## Consequences

- 待办的两项时间从「只能创建时填、填完看不见」变成「随时可见、随时可改、随时可清空」。
- 「点哪改哪」把改名与改时间的触点都放在数据本身上，行尾只留破坏性动作；代价是编辑态名称可用宽度变窄
  （252 面板里两枚胶囊 + 删除约占 122px），靠 `text-overflow: ellipsis` + `title` 兜住。
- 行内点击现在是**三个不同语义**的触点（勾选 / 改名 / 改时间），因此所有非行级按钮都必须显式 `stopPropagation`；
  `TodosPendingRow.test.tsx` 用「点胶囊不得触发 `onToggle`」把它钉成回归项。
- portal 浮层从此有统一的事件边界：新增任何挂在 `body` 上的浮层，都应照 §5 截断鼠标事件，否则会在带行级点击的容器里复发。
