# ADR-009: 便利贴与独立面板采用「一窗一 WebviewWindow」多窗口管理

## Status

Proposed (2026-10-16) — 待 V0.2.0-1 用户确认后转 Accepted

## Background

V0.2.0 新增「便利贴」（钉桌面可拖动缩放的备注窗）与两项独立面板（事项窗口 / 设置面板三页签）。变更方案明确「每个便利贴是一个独立 `WebviewWindow`」，并要求处理窗口生命周期：创建 / 关闭 / 重启恢复 / 位置持久化 / 多显示器。任务把「便利贴多窗口」列为四个重点架构点之一（最大复杂点）。

候选实现：

- **A**：一张便利贴 = 一个 `WebviewWindow`（label `note-{id}`）；设置窗 / 事项窗为单例窗口（label `settings` / `todos`）。
- **B**：单张全屏透明 overlay 窗口，内部用 DOM 承载所有便利贴。
- **C**：原生 child window（父子窗绑定主窗生命周期）。

约束：不改架构主干；单文件 ≤ 300 行；状态机仍归 Rust；窗口几何须跨重启、跨显示器可靠恢复（K-6/K-15）。

## Decision

**采用方案 A：一便利贴一 `WebviewWindow`，设置/事项为单例窗口。**

**窗口目录（V0.2.0 四类独立 `WebviewWindow`）**：

| 窗口 | label | 尺寸（逻辑px） | 单例 |
|---|---|---|---|
| 主小条 PillBar | `main` | 画布 384×360（沿用）；OS 窗口自适应，见 ADR-014 | 是 |
| 设置面板 | `settings` | 392×660 | 是 |
| 事项窗口 | `todos` | 窗口 492 = 面板 252 + 左侧便利贴预览区 240；高自适应，min 360（V0.3.9 起；原 336） | 是 |
| 便利贴 | `note-{id}` | 320×232（默认，min 160×120） | 否（上限 20） |

四类窗口统一适用：label 路由、几何持久化 + 多显示器钳制、防白闪三件套、主题广播（各窗自订阅 `theme-changed`，主窗不代转）。

> 几何持久化**两路**：便利贴（动态 label）落 DB `notes.pos_x/pos_y/width/height`（REAL，逻辑像素，无 `monitor_id`）；单例窗（固定 label）沿用 `tauri-plugin-window-state` 按 label 自动持久化，不入库。

具体锁定项：

1. **窗口模型**：`label = note-{id}`；`url = index.html?w=note&id={id}`；`App.tsx` 依 `getCurrentWindow().label` 路由根组件。设置窗 / 事项窗 label 固定为 `settings` / `todos`（单例，`open_*_window` 已存在则 `show+focus`）。
2. **配置**：`decorations:false`、`transparent:true`、`shadow:false`、`resizable:true`、`skipTaskbar:true`、`alwaysOnTop:false`、最小尺寸 160×120、`visible:false`（首帧就绪后 `show()`，K-18）。
3. **几何持久化**：落 `notes.pos_x/pos_y/width/height`，**逻辑像素**（物理像素 / `scaleFactor`，K-15）；`Moved`/`Resized` → 300ms 去抖落盘。
4. **多显示器**：恢复时按目标显示器 `work_area` 钳制，越界回落主屏（抽 `infra/windows::clamp_to_workarea`，与 v1 K-6 同源）。
5. **关闭 / 重启恢复**：关闭 = 「收纳」——先落盘内容 + 几何、再 `destroy()` 窗口、置 `is_open=0`；启动时按 `notes.is_open=1 AND deleted_at IS NULL` 逐个恢复。
6. **资源护栏**：`MAX_NOTE_WINDOWS = 20`，超限 `WINDOW_LIMIT_EXCEEDED`；关闭即销毁（不留隐藏窗）；便利贴窗口不加载 PillBar 全量 store、不订阅 `timer:state-changed`（K-14/K-21）。
7. **职责分离**：`note_create` 只建数据行，窗口由 `open_note_window` 负责（数据 vs 窗口解耦）。

## Consequences

正面：
- 原生拖动 / 缩放 / 最小化 / 跨显示器 / `skipTaskbar` 一等支持，实现最简，与变更方案一致。
- 窗口独立于主窗存亡，符合「钉桌面备注」的产品语义。
- `notes` 表结构（含 `is_open`）与渲染方式解耦：未来若改方案 B，数据层零改动。

负面 / 需处理：
- **内存随窗口数线性增长**（每 WebView ≈ 20–40MB）。缓解：上限 20 + 关闭即销毁 + 精简便利贴窗口的加载面（K-14）。
- **`app.emit` 会广播所有 webview**，便利贴/待办窗必须按 label 过滤或忽略无关事件（K-21）。
- 每个新窗口都需「内联主题脚本 + `visible:false` + 兜底背景」三件套防白闪（K-18）。
- 几何事件为物理像素，换算错误会导致跨屏漂移（K-15）。

回退路径：若内存成硬瓶颈，迁移到方案 B（单 overlay）——`notes` 表不变，仅换渲染层（预估 v0.3）。
