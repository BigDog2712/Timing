# ADR-019：便利贴置顶状态持久化（`notes.is_pinned` + schema v3）

## Status

Accepted（2026-10-18；关闭 `OPEN-DECISIONS` #9「便利贴『置顶』开关状态未持久化」）

## Background

设计稿 `pages-V0.2.0/sticky-note.md §3.2` 对置顶的表述是两句话：

> **置顶（AC-64）**：**默认 always-on-top = 是**（否则被工作窗口盖住就失去意义）。
> 用户可在头按钮区（hover 时出现 `[pin]`）取消置顶；状态持久化进 `notes`。

实现只做了前半句：

| 项 | 设计 | V0.2.x 实际 |
| --- | --- | --- |
| 默认置顶 | 是 | 是（`window_spec::NOTE.always_on_top = true` 硬编码） |
| 用户可取消 | 头按钮 `[pin]` | **无入口**（V0.2.1「零文字」重构时把标题栏按钮全删了，只剩删除/隐藏两枚圆点） |
| 状态持久化 | `notes` 列 | **无列**，前端曾用 `useState(true)` 兜着，后来连状态都没了 |

于是 AC-64 只达成「默认置顶」，「可取消 + 持久化」这一半长期悬着，登记为 OPEN #9。
`notes` 表任何版本都没有 pin 列，加列属于表结构变更，需要单独走迁移评审。

## Decision

**加列 `notes.is_pinned INTEGER NOT NULL DEFAULT 1`，并把置顶做成「落库 + 推窗口」一次完成。**

1. **迁移（schema v2 → v3）**
   - 加列走 `MIGRATE_COLUMNS_V3` + `ensure_column`（`PRAGMA table_info` 守卫）。
     SQLite 没有 `ADD COLUMN IF NOT EXISTS`，纯 SQL 重复执行会报 `duplicate column name`（K-13）。
   - **顺序硬约束**：`notes` 表由 `0002_v020.sql` 创建，所以「补 v3 列」必须排在它之后，
     否则 v1 老库上 `ALTER TABLE notes` 会报 `no such table`。
   - `0003_v030.sql` 只做版本推进（`schema.version = 3`）与历史行兜底回填，
     不在 SQL 里写加列语句——理由同上。
2. **默认值 1**：V0.2.x 的便利贴窗口硬编码 `always_on_top: true`，默认 1 让老数据升级后
   行为**完全不变**；只有用户主动点 pin 才落 0。这比「默认 0 + 迁移时全部刷成 1」
   少一次全表写，也让「新行默认」这件事由 DDL 保证而不是应用层记得。
3. **建窗时按列值**：`open_note_window` 从 `spec.always_on_top`（静态 true）改为
   `note.is_pinned`（行值）。`spec` 的那个字段保留，只作「新行列默认值 = 1」的说明性对齐。
4. **改值时推窗口**：`note_update` 落库后，若 patch 含 `isPinned`，调
   `window::apply_note_pin` → `set_always_on_top`。窗口没开则静默跳过——
   用户可能在清单里改状态而窗未开，这不该是错误。
5. **UI**：`NoteHeader` 补第三枚圆点（`data-tone="pin"`），与红黄两点同为 10px：
   实心 = 置顶中，空心环 = 已取消。仍然零文字，靠形态 + `title`/`aria-label` 表达。
   放在最左侧，让「删除」不因挤进新按钮而更靠近「隐藏」。

## Alternatives considered

- **前端 `useState` + localStorage 持久化**：绕开数据库，看起来最省事。但便利贴的
  其余状态（几何、关联、打开态）全在 `notes` 行里，置顶单独存 localStorage 会造成
  「一份数据两个真相源」——换机 / 清缓存 / 多窗并存时必然不一致。
- **不做持久化，每次开窗都置顶**：等于删掉 AC-64 的后半句。用户取消置顶的意图
  在重开窗口时被抹掉，属于「看得见的功能」，不能长期缺失。
- **用 `settings` KV（`ui.note_always_on_top`）**：这是**全局**开关，而置顶按便利贴
  逐张决定（一张要浮着、另一张可以沉下去）。KV 表达不了这个维度。

## Consequences

- `schema.version` 由 2 变 3；`migration.rs` / `migration_v2.rs` 的版本断言随之更新，
  并新增「升级后应补 `notes.is_pinned`」的列存在性断言。
- `Note` / `NotePatch` 的 DTO 变化属**加字段**（非破坏）：老前端忽略 `isPinned` 仍可用；
  后端对缺省 `isPinned` 的 patch 视为「不改」，与 `itemId` 的三态处理并列。
- 新增 4 条前端单测（`noteStore.test.ts`）锁住「乐观翻转 / 落库 / 失败回滚」；
  后端 2 条（`pin_toggles_and_survives_reload` / `close_does_not_reset_pin`）锁住
  「列值真的变了」与「收纳不顺手改置顶」。
- 弹窗层级与数据一致性之间的时序：乐观 UI 先翻转、IPC 失败则回滚，避免
  「看着是置顶、实际没落库」的假象。
