# ADR-027：事项窗便利贴预览区（492）+ 待办新增卡 + 待办行去圆点；设置两处收口

## Status

Accepted（2026-10-19，V0.3.9）

## Background

ADR-026 落地「常用摸鱼内置 / 摸鱼菜单瘦身 / 常用事项框回归」之后，用户在同一轮里又提出七条：

1. 设置里调「最短记录时长」时，输入框整体变高亮（蓝框），要去掉；
2. 设置右上角的关闭按钮删掉；
3. **默认存在一张便利贴** —— 每次启动都莫名多出一张开的贴，要查原因；
4. 便利贴应**默认绑定事项**（不要默认「随记」）；
5. 待办事项要像「新增常用摸鱼 / 常用事项」那样**同步创建 UI**（一张表单卡），
   区别是可以设**截止时间与开启时间**，也可以都不设；
6. 在事项菜单（右键事项组件唤出的 `todos` 窗）里，鼠标悬停在事项上时，
   若该事项有便利贴，应在**事项左侧**预览便利贴；
7. 事项菜单里的待办事项显示效果应**如计时行一致，去掉左侧圆点**。

第 3 条是 bug 排查，第 6 条牵动窗口几何，其余是口径收口。

## Decision

### 1. 「最短记录时长」输入框不再整体高亮

两处叠加导致：`GeneralTab` 的 `onFocus={(e) => e.currentTarget.select()}`（聚焦即全选 →
选区蓝底）+ 全局 `:focus-visible { box-shadow: var(--focus-ring) }`（`outline: none`
盖不掉 box-shadow，所以只改 `outline` 无效）。

- 删掉 `select()`：数字框聚焦不该顺手全选，用户是来微调的；
- `.num-field:focus-within` 的描边由 `--accent` 降为 `--line`（容器只做「激活」暗示）；
- 补 `.num-field__input:focus-visible { box-shadow: none; }`（数字框本体不再画 focus ring）。

### 2. 设置面板右上角关闭按钮删除

`SettingsPanel` 的 `.settings__bar` 只留标题；`XIcon` 导入与
`settings-panel.css` 的 `.settings__close` / `:hover` 一并删除。关闭走 `Esc` 或点窗外
（两条路径原本就有）。

### 3. 「默认存在一张便利贴」的根因：启动时恢复了上次 `is_open`

不是新建逻辑多建了一张 —— `notes` 表里确实有历史行，真凶是启动流程第 ⑨ 步的
`jobs::restore_notes::restore_open`：它把上次退出时 `is_open = 1` 的贴**重新拉起**成可见窗口。
用户感知就是「我没开它，它自己在那儿」。

- `services::note::reset_open(pool)`：`UPDATE notes SET is_open = 0 WHERE is_open = 1`；
- `bootstrap` 第 ⑨ 步改为调 `reset_open`；`AppState::new(pool.clone())`（原 `pool` 被 move）；
- `jobs/restore_notes.rs` 删除，`jobs/mod.rs` 去掉声明（ADR-016 的 jobs 清单同步）；
- 语义确认：**数据不删**（历史贴还在列表里），只是不再自动弹窗。`list_open` 保留但启动不再用它。

### 4. 便利贴默认绑定当前事项

`noteActions.currentItemId()` 读当前事项（`lastItemId`）；`openNewNote()` 默认用它，
**只有显式传 `null`** 才是「随记」。用户口径：开贴八成是为了记当前这件事，
默认不绑反而每次都要手选。

### 5. 新增待办改「表单卡」，与摸鱼/常用事项同构

早先是待办区首行就地塞一个输入框（`InlineEditBar` 复用），与「新增常用摸鱼」的表单卡不一致。
改为 `TodosComposeCard`：

- 字段：**名称**（必填，`TODO_TITLE_MAX_CHARS`）、**开启时间**、**截止时间**
  （后两个**都可留空**；输入控件见 5.1 —— 首版用 `datetime-local`，当轮即换自绘）；
  底部「取消 / 添加」+ 右上 `x`；
- 落库映射（易混，需记住）：**截止 → `todos.planned_at`**（`pendingTone` 的逾期判定与
  右列计划时刻都用它）；**开启 → `todos.remind_at`**（到点提醒，行上小铃铛）；
- 校验：提交时若截止早于开启 → inline 报「截止时间不能早于开启时间」，不落库；
- 键盘：卡内 `Enter` 提交、`Esc` 只收卡（窗级 `keydown` 对输入框内事件直接 return，
  避免把整窗关掉）；`autoFocus` 落在名称。
- 契约零变更：`todo_create` 本就带 `plannedAt` / `remindAt`，只是前端第一次给它们入口。

### 5.1 两个时间字段改为自绘选择器（原生 `datetime-local` 做不到三条）

用户补充三条：① 新建待办时时间默认在今天；② 点开日历后下面额外显示「x 天后」；
③ 可切上午 / 下午，分钟每 5 分钟一档。

原生 `<input type="datetime-local">` 是 Chromium 的原生面板，**无法**在面板里加自定义提示行，
中文环境也固定 24 小时制（切不了上午 / 下午）。`step="300"` 勉强能约束分钟步进，但前两条无解。
于是换自绘（`DateTimeField` + `DateTimePicker`，样式 `styles/todos-datetime.css`）：

- **默认今天**：打开时 `draft = value ?? defaultPickerValue(now)`（今天 + 下一个 5 分钟档），
  但**不落值** —— 字段仍显示灰字 `今天（未设）`，不点就不写 `remind_at` / `planned_at`
  （否则「可留空」这条口径就废了）；
- **x 天后**：日历下方一行 `relativeDayLabel`（今天 / N 天后 / N 天前），右侧「清除」；
- **上午 / 下午 + 5 分钟档**：`上午|下午` 分段 + 小时 1–12 + 分钟 `00,05,…,55`；
  `to12h` / `to24h` 是纯函数并单测（12 上午 = 0 点，12 下午 = 12 点）；
- **字段读数仍走 24 小时制**（`formatFieldLabel`），与「今日计时」行同一口径 ——
  上午 / 下午只是**选择时的习惯**，不是读数格式，避免同一窗口两套时间写法；
- **几何**：浮层 `position: fixed` + portal 到 body（`.todos` 有 overflow/backdrop，绝对定位会被裁），
  宽 = 卡片宽，**横向右对齐卡片右沿**（对齐字段会把 232 宽顶出 492 的窗口），
  纵向**贴卡片**而不是贴字段（贴字段会盖住标题输入框）；
- **改动即生效**（无「确定」按钮），撤销走「清除」；
- **选中日不做实心蓝块**：`--accent-wash` 底 + `--accent-line` 内描边 + `--accent-ink` 字
  （品牌蓝实心底压白字仅 2.45:1，设计系统里 `.btn--primary` 已经规避过一次；走查在浅色主题
  下发现「实心蓝 + accent-ink」把数字吃没了，遂按既有口径改回淡底）；
- **Esc 只在 document 捕获阶段拦**：按 Esc 时焦点通常还在字段按钮上，事件不经过浮层，
  只写浮层的 `onKeyDown` 会连卡片和窗口一起关掉（走查抓到过）；
- **互斥按元素身份**判断：点另一个字段要先收掉前一个浮层，否则两个同时挂。
- 纯逻辑全部落在 `lib/datetime.ts`（+ `lib/pickerBox.ts` 几何），16 条单测覆盖
  取整 / 日差 / 12 小时制往返 / 月历网格 / 浮层贴边。

### 6. 事项窗宽度 252 → 492 = 面板 252 + 左侧预览区 240

「在事项左侧预览便利贴」需要一块画布，而 `todos` 窗是 `resizable: false` 的固定尺寸窗口。
两条路：另开一个 `note-preview` 窗（要多一条窗口生命周期 + 跟随主窗移动的同步），
或在同一窗里预留透明区。选后者：

- `infra/window_spec.rs`：新增 `TODOS_PANEL_W = 252.0`、`TODOS_PREVIEW_INSET = 240.0`；
  `TODOS` 的 `width` / `min_width` / `max_width` = **492**；
- `PanelPlacement` 新增 `BelowMainInset(f64)`，`below_main_position(app, left_inset)` 里
  `x = pos.x / scale - left_inset`：窗口锚在主窗正下方后**再左移 240**，使可见的 252 面板
  仍与主窗左对齐，透明区探到主窗左侧（预览卡就落在那儿）；
- 前端：`.todos` 固定 `width: 252px` + `position: relative`，
  `html[data-window="todos"] .win` 改 **flex 右对齐**（面板贴右，左边 240 留空）；
- 预览实现：`useNotePreview`（`listNotes()` 一次缓存 → `noteOf(itemId)` 取 `updated_at`
  最新一张；`hoverStart` / `hoverEnd` 160ms 防抖；缓存未命中按 `itemId` 补拉；`keepOpen`
  让鼠标能移进预览卡）+ `NotePreview`（`createPortal(body)` + `position: fixed`）；
  几何算在 `lib/notePreview.ts: notePreviewBox(anchorTop, viewportH)`（宽 224、高 ≤264、纵向夹视口）。
- **无便利贴的事项悬停不弹卡**（不是弹一张空卡）。

### 7. 待办行去掉左侧圆点，与「今日计时」记录行同构

用户口径：「待办事项的显示效果应如计时一致，去除左侧圆点」。记录行的圆点本就已删（同名口径），
这次把待办行对齐：

- `TodosPendingRow` 改 grid 三列（名 / 时刻 / 编辑态动作），删 `TodoMark`；
  `TodoMark.tsx` 组件与 `.todo-mark*`、`.todo-pend__mark` 样式一并删除；
- **整行点击 = 勾选切换**（圆点没了，点击面就是开关）：`role="checkbox"` +
  `aria-checked` + `cursor: pointer`，键盘 `Space` 同；行尾图标按钮 `stopPropagation`
  避免点「改名/删除」被当成勾选；
- 状态改由**名字色 + 删除线**表达（`data-done` → `--todo-name-done` + line-through）；
- `--todos-mark-*` / `--todo-mark-*` **令牌保留**：主窗「今日摘要」的 `.today-digest__mark`
  仍在用（那是个跨窗口摘要，不是本页）。

## Consequences

- 契约不变：60 命令 / 15 错误码 / 9 事件；版本号 0.3.0；无迁移。
- `todos` 窗从 336 → 252 → **492**，`resizable: false` 不变；`tauri-plugin-window-state`
  按 label 持久化，老用户首次打开会被旧尺寸覆盖一次，之后按 492 记。
- 启动行为变化（用户可见）：上次开着的便利贴**不再自动重开**；数据仍在便利贴列表里。
- `jobs` 层少一个任务（`restore_notes`），ADR-016 清单需同步。
- 待办无圆点后，`aria-checked` 与整行点击是**唯一**的状态入口 —— 后续若再加图形状态，
  必须同时保留 `role` / `aria-checked`，否则无障碍退回。
- 走查（无头 Chrome + CDP 真实事件）：492 窗 `.todos` 252 靠右（left=240）、待办行
  `marks: 0`、新增待办卡 234×188 带 3 个输入、填 21:30 落行「走查新待办 21:30」、
  悬停记录行预览 left=8 / 224 宽并显示事项名与「（空白便利贴）」；
  设置窗 `.settings__bar` 只剩标题（`closeBtns: 0`），聚焦数字框无 focus ring 且 `selected: 0`。
