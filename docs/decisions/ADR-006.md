# ADR-006: Windows 打包与代码签名策略

## Status

Accepted (2026-10-16)

## Background

Timing 需产出 Windows 安装包。Tauri 可产出 NSIS / MSI / 单 exe。未签名的可执行文件会触发 Windows SmartScreen「未知发布者」警告，影响安装信任度。需决定打包格式与是否签名，并评估成本。

## Decision

**打包**：使用 Tauri `bundle` 产出 **NSIS 安装包**（主）+ MSI（备），并为未预装 WebView2 的环境内嵌 WebView2 bootstrapper（`bundle.windows.webviewInstallMode`）。

**签名**：MVP 内测阶段可**先不签名**（接受 SmartScreen 提示）；正式分发按预算选择：

| 证书类型 | 价格区间（参考） | 特点 |
|---|---|---|
| 不签名 | 0 | 触发 SmartScreen「未知发布者」 |
| OV 代码签名 | 约 ¥1200-2800/年 | 移除「未知发布者」，非立即获 SmartScreen 信任，需累积信誉 |
| EV 代码签名 | 约 ¥2000-6600/年（Certum/GlobalSign/DigiCert） | 需硬件 UKey/云签名，**立即**获 SmartScreen 信任 |

建议路径：MVP 内测不签名 -> 首个对外版本起用 **OV**（性价比）-> 若需零警告体验升级 **EV**。

## Consequences

正面：
- NSIS 安装包体积小、安装体验好；内嵌 WebView2 bootstrapper 覆盖老 Win10。
- 分级签名策略让成本随产品阶段增长，避免 MVP 阶段过度投入。

负面：
- 未签名版本有安装阻力，需在分发页说明。
- 启用签名需管理私钥（UKey/云签名）并接入 CI 签名流程，增加构建复杂度。
- 2025 起全球代码签名证书有效期缩短，需规划续期。
