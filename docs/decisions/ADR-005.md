# ADR-005: 系统集成方案（托盘 / 全局快捷键 / 开机自启 / 窗口状态 / 单实例）

## Status

Accepted (2026-10-16)

## Background

Timing 需要 5 项 Windows 系统集成能力，且要求稳定、可配置、失败可降级：系统托盘、全局快捷键、开机自启、窗口位置记忆（多显示器）、单实例。需决定用「官方插件」还是「手写 Win32」。

## Decision

全部采用 **Tauri 2 官方插件/内建能力**：

| 能力 | 方案 | 版本 |
|---|---|---|
| 系统托盘 + 菜单 | 内建 `tauri::tray`（feature `tray-icon`） | 随 core 2.12.4 |
| 全局快捷键 | `tauri-plugin-global-shortcut` | ^2 |
| 开机自启 | `tauri-plugin-autostart` | ^2 |
| 窗口位置/尺寸记忆 | `tauri-plugin-window-state` | ^2 |
| 单实例 | `tauri-plugin-single-instance` | ^2 |

关键实现约束（与 ARCHITECTURE §9 一致）：
1. **热键在 Rust `.setup()` 预注册**，不受前端刷新影响；注册失败必须捕获并提示+允许改键（禁止 `unwrap()`）。
2. **拦截窗口关闭事件为「隐藏」**，仅托盘「退出」真正 `app.exit(0)`。
3. **单实例**防止多开抢占托盘图标与热键。
4. 窗口位置以**逻辑像素**存储（move/resize 事件为物理像素，需除 `scaleFactor`），恢复时按显示器 work_area 钳制，越界回落主屏。
5. 全部插件在 `capabilities/default.json` 逐项放行。

## Consequences

正面：
- 零 Win32 P/Invoke，集成代码量小、可维护性高、跨平台无额外成本。
- 官方插件与 core 同步维护，升级路径清晰。

负面：
- 全局热键存在被系统/他应用占用的固有风险，须做失败降级（W-2）。
- 多显示器 + 混合 DPI 需自行实现钳制逻辑（插件不覆盖所有边界，见 K-6）。
- 依赖 `capabilities` 白名单正确配置，漏配会在运行时被拒（K-4）。
