# ADR-040：小圆点回到纯图形（秒表），今日事项按名字认

## Status

Accepted（2026-11-05，V0.11.1）

## Background

V0.11.0 把收起态圆点做成 76px「环 + 时分」，理由是「移植手机端小圆点，复现环 + 分钟显示」。
用户看到实物后否掉了一半：

> 环是图形化语言，不应放时间；你应参考安卓端的图形化语言。
> （附图：一枚秒表 —— 外圈细灰轮廓、内部蓝色圆头进度弧、中心一根指针，没有任何数字）

同一天的第二条口径则是关于事项身份的：

> 名称只按今日事项看。今日事项如「写周报」写了两段，在事项菜单中按时间排序写两段，
> 在数据库和 md 文档中合并。

## Decision

### 一、圆点只做图形，不承载读数

三层，各司其职：

| 层 | 画什么 | 表达什么 |
|---|---|---|
| 表盘 `.dot__rim` | 1.25px 细环，恒灰（`--line-3`） | 「这是一个表」，不表达状态，不随四色主题变 |
| 进度弧 `.dot__arc` | 3.5px 圆头弧，`stroke: currentColor` | 状态（颜色）+ 进度（弧长 / 行进），复用 `MainButton.arcSpec` |
| 指针 `.dot__needle` | 2.2px 圆头短线 + 中心 1.6px 圆点 | 「在走」：正计时 60 秒一圈，倒计时按已用比例前进 |

- 尺寸从 76 收到 **44px**：不带字之后，76 只剩一圈空环，反而占桌面。
- **读数不进图形**：`title` 保留「时长 · 事项名」，悬停可看。要看数字就用悬浮条形态。
- 指针角度不新立语义：暂停时 `useTimerTick` 不再给新值，指针自然冻结；空闲 / 结束回 12 点。

被否掉的方案：环内保留小字号 `MM:SS`（V0.11.0 的实现）。问题是 44px 下 `MM:SS` 只有 15px、
跨小时要降到 11px，读数既看不清又把「图形语言」降级成「小号文字框」。

### 二、事项身份按「今日名字」，分段时间只在展示层

`lib/todayGroups.ts` 的分组键从 **itemId** 改为 **名字**：

- 今天里叫同一个名字 = 同一件事。用户在手机上新建的「写周报」（新 itemId）与电脑上那条
  会并排显示在同一件事下，不再出现两行同名、右键只改到其中一条的割裂感。
- 名字查不到（事项已删，调用方给 `未归类` / `已删除事项`）时**退回按 id**，
  否则一堆已删记录会挤成同一行。
- 「两段」仍然分行：`CONTIGUOUS_GAP_MS`（60s）内的记录算连续、合并成一行；
  上午一段下午一段就按开始时间升序列两行 —— 用户口径「按时间排序写两段」。
- **数据层不拆**：数据库里仍是各自独立的 `records` 行、事项仍是一条；
  md 侧 `export::timers` 本来就按 `item_name` 归并（`push_interval` + 多段 `intervals`），
  一天一个文件 —— 用户口径「在数据库和 md 文档中合并」。

被否掉的方案：给待办 / 记录加「所属事项」列，做真绑定（V0.11.0 `待决事项` 第 1 条的建议）。
用户明确否了这条，改为「名称只按今日事项看」——不引入 schema 迁移，代价是改名即改身份。

## Consequences

- 圆点的可读性从「读数」退到「状态 + 节奏」，具体分钟数需要展开或悬停。这是用户明确要的取舍。
- `todayGroups` 的调用方（桌面 `TodosPanel`、手机 `ItemsPage`）无需改动：`TodayGroup`
  形状没变，`itemId` 改为「组内最早那条」，右键改名 / 便利贴预览仍指向一个具体事项。
- 同名合并后，改名只作用于组内最早那条，其余同名事项会在下一次渲染里分裂出来 —— 可接受，
  因为「名字就是身份」是本决策的前提。
- 新增 `UNNAMED_FALLBACKS`：以后再加兜底文案要同步这个集合，否则已删记录会被误合并。
