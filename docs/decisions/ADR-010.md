# ADR-010: 提醒由 Rust 侧常驻查询式调度器驱动

## Status

Proposed (2026-10-16) — 待 V0.2.0-1 用户确认后转 Accepted

## Background

V0.2.0 新增「提醒铃」：事项与待办可设提醒时刻，到点弹系统通知。任务要求：Rust 侧常驻定时器扫描提醒、到点触发系统通知，并考虑**休眠唤醒后的补偿**；通知用 `tauri-plugin-notification` 的**实际可安装版本**。

候选实现：

- **A**：Rust 常驻 `tokio::interval`（15s）+ **查询式**扫描（`remind_at <= now AND reminded_at IS NULL`）。
- **B**：前端 `setInterval` 判定到点。
- **C**：每条提醒起一个 `tokio::sleep` 定时任务。
- **D**：OS 计划任务（Task Scheduler）。

约束：提醒在应用最小化/窗口隐藏时仍需触发；系统休眠唤醒后不得漏提醒；不得重复弹同一条；不改架构主干。

关键设计缺口：**仅存 `remind_at` 无法去重** —— 每 tick 扫描都会命中同一条已到点提醒，导致重复弹通知（沉默逻辑错误）。必须引入 `reminded_at` 已触发标记。

## Decision

**采用方案 A：Rust 常驻 `tokio::interval(15s)`（`REMINDER_SCAN_INTERVAL_SECS = 15`）+ 查询式扫描；数据层引入 `reminded_at` 去重标记；通知用 `tauri-plugin-notification` 2.7.0。**

具体锁定项：

1. **调度器**：`infra/reminder.rs::spawn_reminder_watcher(app)`，与既有 15s `flusher` 并行的独立 tokio 任务。
2. **扫描（查询式，非计数式）**：每 tick 查 `items` 与 `todos` 中 `deleted_at IS NULL AND remind_at IS NOT NULL AND reminded_at IS NULL AND remind_at <= now` 的行，按 `remind_at` 升序处理。
3. **触发顺序**：① 先 `UPDATE ... SET reminded_at = now`（先置位）→ ② 系统通知（`app.notification().builder()...show()`）→ ③ emit `reminder-fired`（payload 为 `Reminder`）。
4. **休眠唤醒补偿**：因扫描是**查询式**（条件 `remind_at <= now`），不依赖「漏了几个 tick」；系统休眠期间 ticker 暂停，唤醒后下一 tick 立即扫出所有逾期未触发提醒并补发（迟到但必达、无累计误差）。
5. **去重**：`reminded_at` 保证一条提醒只弹一次、且崩溃重启不重弹（K-19）；`reminder_set` 重设提醒时清 `reminded_at=NULL`（复活）。
6. **失败处理**：通知发送 `Err` 时**回滚** `reminded_at`（保留待下 tick 重试），绝不静默丢提醒；同时应用内 `reminder-fired` 事件保证有可视提示兜底（不依赖系统通知成功）。
7. **索引**：`idx_items_remind` / `idx_todos_remind` 部分索引（`WHERE remind_at IS NOT NULL AND reminded_at IS NULL`），扫描代价 O(待触发数)。
8. **版本锚定**：`tauri-plugin-notification` crate **2.7.0** / npm `@tauri-apps/plugin-notification` **2.7.0**（已核实为真实存在的最新稳定版，禁止版本幻觉）。

## Consequences

正面：
- 不依赖前端存活，窗口隐藏 / WebView 挂起仍能触发。
- 查询式扫描天然抗休眠：唤醒即补发，无需累计补偿逻辑。
- 与既有 15s 落盘任务同构，实现与维护成本最低。
- `reminded_at` 一并解决「重复弹窗」与「重启重弹」两个沉默逻辑错误。

负面 / 需处理：
- 15s 粒度 → 提醒最多迟 ~14s（判为可接受；若要求更高精度，可降到 5s）。
- 无倒计时时每秒仍有一次空转（实际最坏 15s 一次、单行查询，成本可忽略）。
- **Windows toast 需 AppUserModelID**，dev 态可能不弹、专注助手会吞通知（K-16）→ 打包写 AUMID + 失败回滚 + 应用内事件兜底。
- 通知点击动作（跳转到事项）本期不实现（§1.2 out-of-scope）。
