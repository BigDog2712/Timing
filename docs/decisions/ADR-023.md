# ADR-023：删除日记模块 / 记录阈值与保存策略（契约减量：命令 −4）

## Status

Accepted（2026-10-19；用户口径「日记整套下架，历史数据留着；短时不问、直接忽略」）

## Background

三件事被放在同一次改动里，因为它们是**同一条线**的收口：什么该被记下来、记的时候要不要问。

1. **日记模块从未成闭环**。它由四条命令（`diary_get_config` / `diary_set_config` /
   `diary_today` / `diary_open_today`）、两个 DTO（`DiaryConfig` / `TodayDiary`）
   和两块前端 UI 组成，但：
   - 唯一的 UI 入口是设置页第四个页签「日记」——只能填 vault 路径 / 目录 / 文件名格式；
   - `components/diary/TodayDiaryWindow.tsx` **没有任何挂载点**，是纯死组件（`index.html`
     的分流表里没有它，`App.tsx` 也不按 label 渲染它）；
   - 写文件这一步**从未实现**：`diary_today` 只负责拼出「今天应该叫什么文件」，
     `diary_open_today` 文件不存在就报 `IO_ERROR`。也就是说，用户配好路径后，
     应用不会替他建文件、也不会往里写一个字。
   结论：这不是"功能不完善"，而是**配置了一个不会发生的动作**。留着它，等于在设置页
   放一个 100% 无效的页签。
2. **「倒计时到点是否自动结束」这个开关是伪选择**。倒计时的目标时长是用户自己定的，
   到点不结束反而要用户再点一次「结束」——而那次点击得到的时长（`target + 误差`）
   与"钳到 target"在语义上没有区别，只是多了一次操作和一个数据库字段。
3. **短记录弹条（`SHORT_RECORD_SEC = 60`）在问一个用户不想回答的问题**。
   原来的形态是：结束计时后若累计 < 60 秒，撤销条变成「只记了 N 秒，要留下吗？保存 / 丢弃」。
   实测痛点很清楚——**短到需要被问一句的会话，本来就不该被记录**；而真正值得留的记录
   （>= 60 秒）已经有 3 秒撤销兜底，用户真按错了也救得回来。

## Decision

1. **日记模块整体下架，历史数据保留**。删除清单：
   - 后端：`commands/diary_cmd.rs`、`services/diary.rs`、`models/diary.rs`（三文件整删）、
     `lib.rs` 的四条注册、三个 `mod.rs` 的对应 `pub mod`；
   - 前端：`components/diary/TodayDiaryWindow.tsx`、`components/settings/DiaryTab.tsx`、
     `services/diaryActions.ts`、`services/api.ts::diaryApi`、`services/ipc.ts` 四条实现、
     `IpcApi` 四条声明、`DiaryConfig` / `TodayDiary` 两个接口、`SettingsPanel` 的
     `TabId`/`TABS`/渲染分支、`browserMock` 的四条 mock 键与 `diaryConfig` 状态；
   - **历史数据不删**：日记配置从来**没有独立表**——它走的是 `settings` 键值表的四个 KV
     （`diary.vault_root` / `diary.relative_dir` / `diary.file_name_format` /
     `diary.editor_path`）。这四行留在老库里只读不删：`migrations/` 一律不改（历史不可回改），
     服务层不再读写即无害。要清理得写一条只做删除的迁移，收益为零。
   - 契约：命令 **64 → 60**（事件 9 / 错误码 15 不变）。
2. **新增「最短记录时长」`ReferenceSettings.minRecordSeconds`，默认 30 秒**
   （字段早已存在，默认值由 5 改为 30）。判定收敛成**一个函数**
   `services::timer_stop::should_ignore(pool, accumulated_sec)`，两处调用：
   - 手动结束 `services::timer::stop`：`accumulated < threshold` → `session::discard`
     （软删）+ 返回 `discarded: true`，**不入库、不给撤销条**；否则走原 `finalize`，
     返回 `discarded: false`。
   - 切换事项的分段 `services::timer::switch`（`EndAndStart`）：旧段同样过阈值——
     换事项是顺手动作，旧段只有几秒就是误触级的。被判定忽略时
     `repositories::record_session::end_and_start(..., discard_old = true)` 在同一个事务里
     把旧段置 `saved + 软删 + 真实 accumulated`，**新会话照常开始**（切换不能因此中断）。

   `stop_timer` 返回类型由 `TimeRecord` 变为 **`StopResult { record, discarded }`**。
   设置页「通用」新增一个数字输入框（5–300 秒，手动输入，单位 S；V0.3.5 由滑杆改来）。
3. **阈值只过滤「非显式保存」的短会话**——手动结束、切换事项分段。
   两条**显式声明要留下**的路径不受限：
   - 倒计时到点：`services::countdown::tick` 直接 `finalize`，不看阈值，`ended` 恒为 `true`；
   - 崩溃恢复的「结束并保存」：`resolve_open` 的 `Close` 分支直接 `finalize`。
   两者的理由相同：用户已经明确说过"这段要记下来"，把它丢掉比多记一条十几秒的记录更糟。
   例外只有这两条，落库旁路没有第三条。
4. **删「倒计时到点自动结束并保存」开关，恒为保存**：`Settings.countdownAutoEnd`、
   `SettingsPatch.countdown_auto_end`、`KEY_COUNTDOWN_AUTO_END`、
   `services::settings::countdown_auto_end()`、`settingsActions.setCountdownAutoEnd`、
   设置页那一行，全链路删除。
5. **撤销条只保留一种形态**：`已记录 <时长> · <事项名>` + 「撤销」。
   删 `SHORT_RECORD_SEC`、`isShort` 判定、`data-short` 属性、`handleDiscard`。
6. **「扩展」改名「插件」，且不展示任何内置功能**：`ExtensionsTab.tsx` →
   `PluginsTab.tsx`（类名 `.ext__*` → `.plg__*`，样式拆到 `settings-plugins.css`），
   删掉「内置快捷计时」区块与 `PluginListResult.builtin` 字段／`usePluginStore.builtin` 状态；
   `builtin_quick_timers()` 仍作为合并底座留在后端（摸鱼菜单那三条预设来自它）。
   空列表时给一行说明而不是留白。
   **同时：仓库不再随包示例包（推翻 V0.3.2「首次自动创建并写入示例包」的行为）。**
   - **为什么删**：示例包让插件页的**空态永远不可达**——用户一个插件都没装，页面上却有一行
     `moyu-kit`，这与「插件页只反映用户装了什么、不展示任何内置功能」直接冲突，
     那条空态文案从落地那天起就是死代码；
   - **删了什么**：仓库里的 `plugins/moyu-kit/` 整个目录；`infra::plugin_fs` 的
     `SAMPLE_MANIFEST` / `SAMPLE_README` / `sample_id_taken()` 与播种块；以及那条依赖
     `include_str!` 的**编译期硬依赖**（连带那个单测——改成不碰磁盘的内联 JSON 用例，
     顺带把「启动头字段名映射」这条真正要守的东西留下）；
   - **现在是什么**：`plugins/` 保留 `.gitkeep` 占位（用户得知道往哪放），`ensure_user_dir`
     只做 `create_dir_all`；全新安装首次打开插件页，看到的就是那条空态文案。
   格式指引留在 `docs/plugin-spec.md` §2/§7（"自己在插件目录里新建文件夹"），
   宿主不再替用户往目录里丢文件。

## Alternatives

1. **日记：补完而不是删掉**（实现"开始计时即往 md 追加一行"）。
   代价是要重新决定一套格式、时区、并发写、vault 不存在时的降级，而它已经三次被
   排到别的功能之后。用户口径是"整套下架"，且历史配置仍留在库里，将来重做时不必迁移。
   同时保留四条命令而只删 UI，正是 ADR-022 里否掉的形态：契约继续宣称一项没人调用的能力。
2. **阈值为什么不管倒计时到点，也不管崩溃恢复的「结束并保存」？**
   阈值过滤的是**用户没打算保存**的会话：手动结束的时长是他被动得到的结果
   （点错了、试了一下、被叫走），切换事项时那段更只是顺手动作的副产物。
   这两条路径的用户意图是"停一下/换个事项"，短到没意义就该丢掉。
   而**显式声明要留下**的路径完全不同：
   - 倒计时的时长是**用户主动设定的目标**（选了 3 分钟就是想要 3 分钟），到点丢弃
     等于把他明确表达的意图判为无效；哪怕目标只有 60 秒，那也是一次完整的"我只想专注 1 分钟"；
   - 崩溃恢复对话框上他点的就是「结束并保存」，之后再让这条记录消失，用户会认定
     "我选了保存却没记录"，这比多记一条 12 秒的记录坏得多。

   所以例外恰好两条：`countdown::tick` 与 `resolve_open(Close)`，代码里都没有阈值判断。
   换一个说法记一遍边界：**阈值只过滤非显式保存的短会话；显式说要保存的，一律落盘。**
3. **为什么不再问「要不要留下」？**
   询问的成本（一次额外点击 + 一个需要被理解的二选一 + 两套撤销条 UI）高于收益：
   - 短记录本就该被忽略 → 「最短记录时长」已经把它变成**不会发生的事**，
     用户根本看不到那一条，也就不需要回答；
   - 超阈值的记录有 3 秒撤销兜底（`undo_stop`）→ 真按错了仍然救得回来；
   - 两个机制回答的是同一个问题（"这条要留吗"），留两个入口只会让短会话出现
     "先被问一次、再被撤销一次"的双重路径。
4. **`SHORT_RECORD_SEC=60` 与 `minRecordSeconds=30` 是什么关系？**
   前者是**询问**的触发条件（前端常量，< 60s 就弹二选一），后者是**记录**的门槛
   （后端设置项，< 门槛就软删）。本次改动把"询问"整条删除，用"门槛"取代它：
   - 数值变小（60 → 30）是刻意的：不再需要"多留一点余量好让用户有得选"，
     门槛只需过滤掉"误触级别"的会话；
   - 位置从**前端常量**挪到**后端设置项**：判定必须在数据落库那段代码里
     （`services::timer_stop::should_ignore`），否则托盘「结束」这类与界面无关的入口
     仍会写入短会话；
   - 因此 `SHORT_RECORD_SEC` 被删除，而不是被改名——它服务的那套 UI 已经不存在了。
5. **阈值判定读设置失败时为什么"放行"（fail-open）？**
   `should_ignore` 里 `get_reference` 出错就返回 `false`（当作"不忽略"）。
   反过来的写法看起来更"安全"（读不到阈值就不记），但代价是把一条**真实存在的计时**
   因为一次 DB 抖动丢掉，而用户完全无法察觉——他点的是"结束并保存"。
   两害相权：多记一条短记录可撤销、可删除；丢一条记录无法挽回。
   这是**刻意的取舍**，不是漏判、也不是分支漏写——改回 fail-close 前请先读这一段。
   没有单测覆盖它：要构造"会话读得到、设置读不到"的半坏库，代价高于收益；
   口径由 `should_ignore` 的文档注释与本节共同守住。

## Consequences

- **契约减量**：命令 64 → 60。`check:contract` 输出 `命令 60 / 60 / 60 / 60`，
  日记域四条命令在 `lib.rs` / `IpcApi` / `ipc.ts` / `browserMock` 四处同时消失。
- **`stop_timer` 的返回形状变了**：前端 `hooks/useTimerActions.ts::stop` 按 `discarded`
  分支——`true` 时只给一条中性提示「不足 N 秒，未记录」，**不**调用 `beginUndo`。
  任何未来新增的停止入口都必须读这个字段，否则会给一条不存在的记录开撤销条。
- **`browserMockDiary.ts` 更名 `browserMockDaily.ts`**：该文件原本混装日记 / 日状态 /
  丢弃计时 / 计时窗四类 mock。只删日记部分、保留其余，否则 `check:contract` 的
  「Rust 有命令、mock 没实现」会红（`daily_status_*` / `discard_timer` / `open_timer_window`
  三条命令仍在）。
- **后端测试的极化**：状态机用例不关心阈值，统一用 `tests/support.rs::allow_short_records`
  把阈值关到 0；阈值本身由 `tests/timer_threshold.rs` 守住——低于即忽略 / 等于阈值照常保存 /
  可配置 / 分段短也忽略且切换不中断 / 崩溃恢复的「结束并保存」不受限，
  倒计时的例外由 `tests/countdown.rs::tick_ignores_min_record_seconds` 守住。
- **设置页稳定为三项**：外观配色 / 插件 / 通用。「通用」现在是一个开关（开机自启）
  加一个数字输入框（最短记录时长），不再有任何"看起来像开关但其实是死字段"的项。
- **用户可感知的变化**：短于 30 秒的计时结束后**不会**出现任何可撤销的记录，
  只在底部提示条上说明原因；计时中换事项时，短于阈值的旧段同样不会出现在记录列表里
  （但新事项的计时照常开始）；倒计时到点后一律自动结束并保存，不再有"到点了但还在跑"的状态。
