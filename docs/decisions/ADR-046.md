# ADR-046：小圆点缩到 22px，外环当秒针、内针当分针，点开是临时条

## Status

Accepted（2026-11-05，V0.11.4）

## Background

V0.11.1 把圆点从「76px 环 + 时分」改成「44px 纯图形秒表」，当时的口径是
「环是图形语言，不应放时间」。落地后有两处不对：

1. **太大**。44px 是按「看得清指针」定的，真机桌面上占地方，用户要求「缩小一倍」。
2. **转速读不懂**。原实现里，环靠 `stroke-dashoffset` 每 3.2 秒滑一段（`dot-march`），
   指针按 `seconds % 60` 走（60 秒一圈）。两处都是「在动」，但拼起来不像任何一只表：
   环在爬、针在转，语义互相打架。用户给的口径是钟表：**外环一分钟一圈、内针一小时一圈**。

另外「点圆点展开」在 V0.11.1 之后是**粘性**的：点一下变条，就一直是一条，得再点回来。
用户要的是「临时看一眼」：点开，鼠标移开就恢复圆点。

## Decision

**尺寸**：`--dot-size` 44 → 22px，`CollapsedDot` 的半径/长度常量等比减半，
描边只减到 0.75 / 1.8 / 1.1（不完全减半，否则 1x 屏上糊成一团灰）。

**转速**：

| 部件 | 周期 | 实现 |
|---|---|---|
| 外环（表盘 + 进度弧，`<g class="dot__ring">`） | 60 秒/圈 | CSS `dot-turn` 动画 |
| 分针（圆心到外缘的针） | 3600 秒/圈 | `displaySec % 3600` → 一秒 0.1° |

暂停的处理是这条决策的重点：**`data-turn` 只切 `animation-play-state`**，不撤动画。
撤掉会让环瞬间弹回 12 点，视觉上是「重置」而不是「停住」。

倒计时不套 3600s 口径，仍按「已用比例 × 360°」整圈走完 —— 倒计时的「一圈」就是
它的总时长；换成钟表口径反而读不出还剩多少。

**临时展开**：小圆点形态下，`mouseleave` → 300ms 后收回（移回来即取消）。
300ms 是一个必要的缓冲：展开瞬间窗口从 22px 变成一条，指针可能正好落在新窗口外面，
不等一下就收，表现成「点了没反应」。

收之前先问 `uiStore.hasOpenSurface()`：面板 / 倒计时菜单 / 提醒卡 / 便利贴清单 /
事项菜单 / 摸鱼菜单 / 常用事项 / 内联命名 / 恢复框 / 撤销条，任意一个开着就不收。
判断集中在一个函数里，新增浮层只改那一处。

**悬浮条形态**：整段短路 —— 不渲染圆点、不装 `mouseleave` 收起逻辑。

## Consequences

- 22px 的点击靶很小（远低于 44px 的建议触摸靶）。桌面鼠标场景可接受，而且圆点本来就
  不是高频操作；真要高频操作，用户会选悬浮条形态。
- 环的转动是纯 CSS 动画，不跟着 `useTimerTick` 的秒跳。所以**环与针的相位不保证对齐**
  （针按秒跳、环匀速转），这是刻意的：两条独立的时间轴，各读各的。
- `prefers-reduced-motion` 下环不转，只留针——不动的环仍然靠弧长表达状态。
- 临时条依赖鼠标事件，触摸板 / 遥控器不适用；这份形态本来就只服务桌面鼠标。
- 事件订阅的 `unlisten` 需要 `core:event:allow-unlisten`。白名单里只有 `allow-listen`
  时，每次组件卸载都会抛 unhandled rejection，被全局钩子显示成红色「界面异常」条。
  这是本轮一并修掉的，记在这里是因为它和「小圆点形态频繁挂载/卸载」是同一批症状。
