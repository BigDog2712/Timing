# ADR-015：权限最小化——移除 `plugin-sql` / `plugin-store`，数据访问只走四层

## Status

Accepted（2026-10-18，架构评估 P0「权限面过大」项；对应任务 T11）

## Background

`tauri.conf.json` 的 `capabilities/default.json` 在 V0.2.x 里放行了：

```
sql:allow-load, sql:allow-execute, sql:allow-select, sql:allow-close
store:allow-get, store:allow-set, store:allow-save, store:allow-delete
```

而 `src-tauri/src/lib.rs` 同时注册了 `tauri_plugin_sql` 与 `tauri_plugin_store`。核实结果：

1. **前端从未调用过这两个插件**。全库 grep `@tauri-apps/plugin-sql` / `plugin-store`，只命中 `package.json` 的依赖声明，`src/` 下 0 处 import；`browserMock` 也没有对应分支。
2. **权限已经在，能力就存在**。Tauri 2 的 capability 是「前端能不能调」的开关，不是「代码里有没有调」。只要 `sql:allow-execute` 在，任何一行注入到 WebView 的脚本都能直接 `Database.load(...).execute("DELETE FROM time_records")`，**完全绕过** `commands -> services -> repositories` 四层带来的全部约束（单 active 会话不变量、`uq_records_open` 之外的业务校验、时间口径、事件广播）。
3. 也就是说：四层架构守的是「正常调用路径」，而这两个权限在旁边开了一扇永久不锁的侧门。

## Decision

**删掉插件与权限，不给前端任何直连数据库 / 键值存储的通道。**

具体：

1. `src-tauri/Cargo.toml` 移除 `tauri-plugin-sql`、`tauri-plugin-store`。
2. `src-tauri/src/lib.rs` 移除两个 `.plugin(...)` 注册。
3. `src-tauri/capabilities/default.json` 移除全部 `sql:allow-*` / `store:allow-*`，只保留窗口（`core:window:*` 中实际用到的子集）、事件、开机自启所需项。
4. `package.json` 移除 `@tauri-apps/plugin-sql`、`@tauri-apps/plugin-store` 两个前端包——依赖在 `package.json` 里留着，下一个人就会以为它能用。

## Consequences

正面：

- 前端不再有任何「绕过四层」的路径。想改数据必须走 `invoke`，因此必然经过服务层的校验与事件广播。
- 依赖面缩小：少两个 crate、少两个 npm 包、少一组 capability 条目；`tauri build` 体积与启动期插件初始化都往下走。
- 审计变简单：`src-tauri/src/commands/` 的 62 个函数就是**全部**外部可触达面，`check:contract` 能机械枚举。

负面 / 已接受的代价：

- 如果将来确实需要前端直连 SQL（例如做数据导入导出向导），必须重新加回插件并**在 ADR 里说明为什么四层不适用**，不能顺手加权限。
- 已发布的旧版本升级上来时，如果用户在旧版的 WebView 里塞过自定义脚本依赖这两个插件，会失效。本项目无此用户，接受。
