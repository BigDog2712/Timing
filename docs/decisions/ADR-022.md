# ADR-022：下架全局快捷键与窗口置顶开关（契约减量：命令 −2 / 事件 −1 / 错误码 −1）

## Status

Accepted（2026-10-19；用户口径「快捷键和置顶开关都去掉，别留着占位」）

## Background

两项能力都是 V0.1.0 就登记、但从未真正落地的**占位**：

1. **全局快捷键**（`register_shortcut` / `Settings.shortcuts` / `shortcut:triggered` /
   `SHORTCUT_REGISTER_FAILED`）从 v0.1.0 起就写在契约里，标注 `[P1]`。实际实现是
   `infra/shortcuts.rs::register` **恒返回 `false`**——`capabilities/default.json` 从未放行
   `global-shortcut`，`tauri-plugin-global-shortcut` 也只是一条默认关闭的 optional 依赖。
   前端为此维护了一张「动作 → 加速键」表，渲染成三行永远显示「未注册」、编辑按钮永远 `disabled`
   的只读 UI；`useAppBootstrap` 还订阅了一个后端从不 emit 的事件，靠
   `check-contract.mjs` 的 `EVENT_ALLOWLIST` 打补丁才没被判成死常量。
2. **窗口置顶开关**（`set_always_on_top` / `Settings.alwaysOnTop` / 设置页「保持窗口置顶」）：
   它只对**主窗**生效，浮层窗口（`settings` / `todos`）的 `always_on_top` 是硬编码 `false`。
   于是「关掉置顶」= 主条能被遮挡，「打开置顶」= 主条压在最上面，而设置窗与事项窗始终
   不置顶——用户拉一下设置面板就会被别的窗口盖住。开关给出的控制力与其实际作用面不匹配。
   再加上 0.3.1 删掉「显示 / 隐藏」后，主条已经常驻显示，置顶与否不再有使用场景差异。

两条共同的代价不是"多写了 200 行"，而是**契约说谎**：文档与命令表宣称存在的能力，
用户点下去得到的永远是「未注册」或「没反应」。每次契约评审都要为它们重新确认一遍
"本期到底做不做"，`check:contract` 的 allowlist 也为它们开了一个不该存在的口子。

## Decision

1. **全局快捷键整套下架，不保留占位**。删除清单：
   - 后端：`infra/shortcuts.rs`（整文件）、`models::enums::ShortcutAction`、
     `models::settings::ShortcutMap`、`Settings.shortcuts`、`SettingsPatch.shortcuts`、
     `commands::system_cmd::register_shortcut`、`KEY_SHORTCUT_*` 四常量、
     `ErrorCode::ShortcutRegisterFailed`（枚举 + `as_str` + 构造器）；
   - 前端：`IpcApi.registerShortcut`、`ipc.registerShortcut`、`RegisterShortcutParams`、
     `ShortcutAction`、`ShortcutMap`、`ShortcutTriggeredPayload`、`IPC_EVENTS.shortcutTriggered`、
     `useAppBootstrap` 的订阅、`browserMock` 的 `register_shortcut` 键、设置页「全局快捷键」整块 UI；
   - 门禁：`scripts/check-contract.mjs` 的 `EVENT_ALLOWLIST` 清空为 `new Map([])`。
2. **窗口恒定置顶**。`infra::window_spec` 的 `always_on_top` 全部改为 `true`（主窗由
   `tauri.conf.json` 的 `alwaysOnTop: true` 承担，不重复声明）；删除
   `commands::system_cmd::set_always_on_top`、`infra::window::set_always_on_top`、
   `services::settings::set_always_on_top`、`Settings.always_on_top`、`SettingsPatch.always_on_top`、
   `KEY_ALWAYS_ON_TOP`、设置页「保持窗口置顶」开关、前端 `setAlwaysOnTop` 全链路。
   **便利贴的 `notes.is_pinned` 是独立特性，保留**：它是单窗级的"这张贴纸浮在最上面"，
   与"主条要不要置顶"不是一回事（AC-64 / ADR-019）。
3. **顺带删除「感知壁纸自动提高不透明度」**（`Settings.opacityEnabled` / `KEY_OPACITY_ENABLED` /
   `settingsActions.setOpacityEnabled`）：该字段同样从未被任何代码读取，是 W-4 的设计残留。
   三个字段（`shortcuts` / `alwaysOnTop` / `opacityEnabled`）一起下架，`Settings` 回到
   「自启 + 显示器 + 主题四件套 + 倒计时」的实际形态。
4. **契约数字三处同步变小**：命令 66 → **64**、事件 10 → **9**、错误码 16 → **15**。
   `check:contract` 的四处比对（`generate_handler!` / `IpcApi` / `ipc.ts` / `browserMock`）
   与三处错误码、事件三方一致性仍然全部咬死，减量与加码一样要过一次契约评审。

## Alternatives

- **保留占位，等 P1 真做**：占位已经跨了三个版本，每次评审都要重新确认"做不做"；而它带来的
  唯一实际产出是让 `EVENT_ALLOWLIST` 多一条豁免、让用户多看见一行灰按钮。
  真要做时按新能力重新登记（新 ADR + 新码），成本并不比现在维护占位更高。
- **只删 UI、保留命令与字段**：契约文档会继续宣称「有 register_shortcut」「Settings.alwaysOnTop
  可切换」，但没人调用——这正是 ADR-021 里已经否掉的形态（"留一个永远返回不了的码，等于给
  调用方假的失败契约"）。`check:contract` 只能保证三处清单互相一致，抓不到"清单与行为脱节"。
- **置顶改成"按窗口类型分别可切"**：能保留控制力，但用户要为此理解"主条置顶"和"浮层置顶"
  两个开关的差别；实测的诉求是"别挡住我就行"，而 0.3.1 之后主条常驻、不占工作区，
  两个开关都不再有使用场景。

## Consequences

- **契约减量**：命令 66 → 64、事件 10 → 9、错误码 16 → 15。三处（`lib.rs` / `IpcApi` /
  `ipc.ts` / `browserMock`）与错误码两处、事件三方必须同步——这条由 `check:contract` 机械保证。
- **依赖与 npm 包已同步移除**：`src-tauri/Cargo.toml` 的 optional
  `tauri-plugin-global-shortcut` 与 `[features] p1-shortcuts` 已删除（源码里也没有任何
  `#[cfg(feature = "p1-shortcuts")]` 残留——唯一使用者 `infra/shortcuts.rs` 已随功能下线），
  `package.json` 的 `@tauri-apps/plugin-global-shortcut` 一并移除并刷新了 `package-lock.json`。
  `Cargo.lock` 由下一次 `cargo` 构建自动收敛。
- **`EVENT_ALLOWLIST` 变为空 Map**：此后前端声明的每个事件都必须有真实 emit 点，
  不再有"特性关闭时先留着订阅"这种口子。
- **v1/v2 数据库残留 key 只读不删**：`ui.always_on_top` / `ui.opacity_enabled` / `shortcut.*`
  仍在老库的 `settings` 表里。迁移文件一律不改（历史不可回改），`ensure_defaults` 也不再写它们，
  没有任何读取路径 —— 留着无害，删了要写一条只为清理的迁移，收益为零。
- **窗口行为变化（用户可感知）**：设置窗、事项窗现在都压在其他窗口之上；关掉设置需要点「完成」
  或按 Esc，点别的窗口不会把它盖下去。这是本次决策的显式取舍。
- **`window_spec` 的置顶不再有分支**：`/tests/window_spec.rs` 新增
  `every_window_spec_is_always_on_top` 守住这条不变量，防止将来有人给某个窗单独改回 `false`
  而不改文档。
- **前端不再有"加速键"这个概念**：设置页少了一整块只读 UI，「通用」页签只剩两个真开关。
