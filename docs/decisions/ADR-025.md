# ADR-025：状态环形状改为超椭圆（曲率连续的 squircle），路径运行时生成

## Status

Accepted（2026-10-19，V0.3.7；用户口径「不太像小米的弧度感觉，再圆一点」）

## Background

V0.3.3 把状态环从圆形改成「小米 logo 式圆角方形」，`01-primitives.css` 里写着
「16px 边长取 ~31% 圆角（5 / 16 ≈ 31%，对应小米 logo 的 90° 圆角比例）」。

31% 这个比例是照着小米 logo 的**观感**取的，但落地的几何是**圆角矩形**：

```
M 8 1.2 H 11 A 3.8 3.8 0 0 1 14.8 5 V 11 ... （四段四分之一圆 + 四条直线）
```

圆角矩形的曲率沿路径是**分段常数**的：直线段 k=0，圆弧段 k=1/3.8，切点处从 0 突跳到 1/3.8。
16px 视口下这道接缝只有亚像素宽，但放大看（或在高 DPI 屏上）就是四个「直线突然变弯」的折点，
观感偏硬、偏方——这正是用户说的「不太像小米的弧度」。

小米 logo 的形状是**超椭圆**（superellipse）：

```
|x/R|ⁿ + |y/R|ⁿ = 1
```

曲率沿路径连续变化——四边近乎平直、靠近角部逐渐收弯，没有切点。n=2 是正圆，
n→∞ 退化为正方形；小米 logo 的观感落在 **n ≈ 3**。

## Decision

**1. 形状换成超椭圆，取 n = 3。**

中线口径（描边 2.4、inset 1.2）半边长 `R = 6.8`，中心 (8, 8)。参数式采样：

```
x = 8 + R·sgn(cos t)·|cos t|^(2/n)
y = 8 + R·sgn(sin t)·|sin t|^(2/n)      t 从 −π/2 起，顺时针
```

选参数式而不是解方程：`t` 均匀取点时，点按**角度**分布，角部（曲率最大处）自然获得更密的采样；
直接对 x 均匀取点会在角部欠采样。

**2. 路径运行时生成，不硬编码坐标。**

`squirclePoints()` 采样 → Catmull-Rom 样条转三次贝塞尔（曲线**过每个采样点**）→ 路径串。
每象限 8 段、整圈 32 段，实测最大径向偏差 0.0098px（16px 环上不可辨）。

这么做的核心理由不是「代码短」，而是**可验证**：`ringGeometry.test.ts` 把路径里每个曲线端点
代回超椭圆方程，残差必须 < 1%。旧的硬编码路径没人验得动——V0.3.3 曾把切点写成 5.4，
SVG 照样渲染，只是四段弧被拉成椭圆，tsc / lint / 契约门禁全部放行。

副产品：`n` 成了唯一旋钮。用户觉得还不够圆，把 `SQUIRCLE_N` 改成 2.6 即可；
想更方取 3.4。改一个数字，15 条几何断言立刻复核。

**3. 全状态单一载体：idle / ended 也走 SVG 弧，`border` 彻底退场。**

初版方案只把计时态换成超椭圆，idle / ended 留在 CSS `border` 上。实施时发现这是半吊子：
**空环恰恰是用户最常看到的状态**（空闲待命），只改计时态意味着环在 idle ↔ running
切换时会「变脸」——超椭圆 ↔ 圆角矩形两种形状。所以裁决升级为：

- `.ring` 的 `border: 0`，弧由 `arcSpec` **恒返回非 null**（idle 未待命 = 整周弧无轨；
  ended = 整周弧无轨 + `data-thick` 加粗描边到 3px，取代原 `border-width: 3px`）；
- `data-arc` 属性删除（它只在「有 border 回落分支」时才有意义）；
- `--ring-radius` 5 → 5.6px，**只服务 `::before` 命中区的同心外扩取形**（SVG 不用它）；
  5.6 是超椭圆 n=3 的视觉等效：超椭圆外沿（半边长 8）角部内缩
  `8·(1 − 2^(−1/3))·√2 ≈ 2.334px`，圆角矩形角部内缩 `r·(√2−1)`，反解 r ≈ 5.64。
- **附带收益（直接收掉 ADR-024 的 F2 遗留）**：
  ① 环的粗细只剩 SVG 一处（2.44px），不再有 `border-width: 2.4` 被 Chromium 吸附成
  2.00px 的 18% 偏差（且该偏差随 DPR 翻转，无法定单一基线）；
  ② `inset` 相对 padding box，border 归零后 padding box = 16，
  `::before` 命中区终于真的等于 24×24（原 19.2×19.2）；
  ③ 消除 idle→running 的「换载体瞬间」（border 消失 + svg 出现两件事 → 同一载体换色）。

**4. 起点与行进语义不变。** 路径仍从顶边中点 (8, 1.2) 起、顺时针闭合；
`pathLength=100` 归一，`dasharray` / `dashoffset` 与路径实际周长解耦；
`ring-march` 靠 dashoffset 推进（ADR-024 的裁决），换成超椭圆后弧依然是真实路径的一段。

## Alternatives

**A. 只把圆角半径加大（5 → 6.5），仍是圆角矩形。否决。**
角部看起来会变大，但切点处的曲率突跳还在——用户要的是「弧度感觉」而不是「角更大」。
改完仍然不像，等于白改一轮。

**B. 硬编码一条超椭圆路径字符串。否决。**
1000+ 字符挤在源码里，占行数、没法读、没法调；改动只能靠外部工具重新生成再粘贴。
更糟的是它重新打开「写错一位仍然渲染」的口子，而这正是 ADR 里要堵的洞。

**C. 用 SVG `A`（椭圆弧）拼出超椭圆。否决。**
`A` 只能画椭圆弧，椭圆弧的曲率沿弧长连续但**两端与直线段仍然突变**；
要模拟超椭圆的变曲率，需要几十段不同 rx/ry 的椭圆弧——比贝塞尔更长的路径、更差的精度。

**D. 用 CSS `border-radius` 的百分比 + `corner-shape: squircle`。否决（暂不采用）。**
`corner-shape` 是 CSS Borders 4 的新属性，Chromium 139+ 才有；
本项目跑在 WebView2（版本随用户机器），不能假定支持。
即便支持，它也只作用于 `border` 载体，SVG 那条还得自己画——会重新分叉成两套形状。

**E. 用折线（每象限 32 段）逼近。否决。**
几何上够准（每段 0.1px），但 128 个 `L` 命令让路径变成 1500+ 字符，
且 dash 会沿折线累积长度误差；贝塞尔版本代码更短、曲线更真。

**F. 把 n 调到 2.6，直接更圆一档。暂不采用，保留为旋钮。**
n=2.6 时角部更饱满（角部内缩 2.25px vs n=3 的 1.98px），但四边开始明显外鼓，
离「小米那种四边很直」更远。先交 n=3，用户要更圆就改这一个常量。

## Consequences

- **形状**：四边近乎平直、角部曲率连续。视觉上比圆角矩形「更圆」，但四边更「直」——
  两者同时成立，这正是超椭圆与「大圆角矩形」的区别。
- **可调性**：`SQUIRCLE_N` 是唯一旋钮，配套 15 条几何断言；改完跑 `vitest` 即知是否还成立。
- **文件行数**：`ringGeometry.ts` 97 → 约 190 行（仍在 300 行内）。路径是运行时字符串，
  不占源码。
- **性能**：`ARC_PATH` 在模块加载时算一次（32 段 × 4 点），可忽略。
- **测试口径变化**：旧断言「四段弧半径 3.8 / 切点 5 与 11 / 直线段只连切点」全部删除——
  那些是圆角矩形的特征，对新形状不成立。新断言见 `ringGeometry.test.ts` 第一组。
- **F2 已随全状态单载体收掉**：环的粗细只剩 SVG 一处，2.00 vs 2.44 的 border 吸附偏差
  与「随 DPR 翻转」的问题从结构上消失；命中区从 19.2×19.2 修正为 24×24。
- **测试口径变化**：`MainButton.test.tsx` 的「idle / ended 不渲染 svg」3 条断言改为
  「恒渲染 svg、idle 无轨、ended 加粗」；`data-arc` 断言随属性删除。
- **已知偏置不变**：`stroke-linecap: round` 让短弧有约 5% 周长的视觉下限（见 ADR-024）。
  换成超椭圆后周长略长，但 `pathLength` 归一，偏置比例不变。
