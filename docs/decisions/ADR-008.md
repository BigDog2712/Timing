# ADR-008: 系统托盘与开机自启纳入 MVP（P0-5 / P0-6）

## Status

Accepted (2026-10-16)

## Background

PRD v1 将「系统托盘 / 全局快捷键 / 开机自启」列为 P1；而团队简报将其列为关键技术诉求。Phase 1 架构在 §5(F-2/F-3/F-4) 对三项能力做了**预置设计**（全部采用 Tauri 官方插件/内建能力），并作为待裁决项 A-1 上报。

考虑因素：
- 系统托盘原始 RICE = 6.00，为全表最高；TickBar 是"常驻可见"的桌面应用，**没有托盘的常驻应用体验缺失明显**（无入口恢复被隐藏的窗口、无退出路径）。
- 开机自启是"永远可见 / 随手可用"叙事的必要组成，且实现成本极低（`tauri-plugin-autostart` 写 HKCU Run）。
- 全局快捷键 RICE = 4.27，相对较低，且存在被系统/他应用占用的固有风险（W-2），可留 P1。

用户于 2026-10-16 确认三文档时裁决：**托盘与开机自启进 MVP，全局快捷键仍留 P1**。本 ADR 记录该范围变更及其约束。

## Decision

**将「系统托盘」与「开机自启」由 P1 提升为 P0（MVP），形成 P0-5 / P0-6；全局快捷键保持 P1。**

1. **系统托盘（P0-5）**：启用内建 `tauri::tray`（feature `tray-icon`）。
   - 图标常驻；菜单含「显示 / 隐藏、新建事项、设置、退出」。
   - 左键单击切换悬浮条显隐（`show_menu_on_left_click(false)`）。
   - **关闭窗口拦截为「隐藏」**（`CloseRequested` → `hide_window`），仅托盘「退出」调 `quit_app`（`app.exit(0)`，K-5）。
2. **开机自启（P0-6）**：采用 `tauri-plugin-autostart`（写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）。
   - 暴露命令 `set_autostart` / `get_autostart`；设置面板开关；**关闭时完全移除启动项，不留隐藏残留**（AC-21）。
3. **全局快捷键仍 P1**：命令 `register_shortcut` / 错误码 `SHORTCUT_REGISTER_FAILED` / 事件 `shortcut:triggered` / `Settings.shortcuts` 本期仅保留**结构与默认值**，不注册实际热键。
4. **capabilities 逐项放行**：`autostart:allow-*` 及相关窗口/托盘权限必须在 `capabilities/default.json` 放行（K-4）。

## Consequences

正面：
- 补齐常驻应用应有的入口与退出路径，使"永远可见"叙事闭环。
- 成本极低（官方插件/内建能力，ADR-005 已确认零 Win32 P/Invoke）；对包体积/内存影响可忽略。
- 自启 + 托盘使冷启动即可见，强化"随手可用"体验。

负面 / 需处理：
- MVP 交付范围与工作量增加（托盘图标/菜单、关闭拦截、自启读写与设置联动）。
- 需正确拦截关闭事件，否则关窗即退出、托盘失效（K-5）。
- 自启涉及注册表写入，需保证"可一键移除"，避免留下用户不可见的启动项（隐私与信任要求）。
- IPC 契约需同步：`set_autostart` / `get_autostart` 归入 MVP；`register_shortcut` 明确标 [P1]（见 IPC-CONTRACT-v2 §3.5 / §3.6）。
