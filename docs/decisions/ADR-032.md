# ADR-032：待办区只显示「今天」，过期改为降透明度 + 一道横线

## Status

Accepted（2026-10-20，V0.3.14）

**Superseded by ADR-034（§1 的显示范围）；§2 的逾期视觉保留**

## Background

用户口径（原话）：

> 待办事项内仅显示今天事项  过期事项透明度降低且有一条横线表示过期

背景：事项窗本来就是「今日计时」的今日面板（今日记录 + 待办），但待办区此前拉的是**全量**
（`todo_list` 不带时间过滤），于是下周的、上个月的待办都挤在今天的时间线里；
同时「逾期」此前只用红色（`--todo-overdue`）表达 —— 在一个本来就密集的小面板里，
红色是在喊「更醒目」，而逾期其实该是「已经过去了」的语气。

## Decision

### 1. 只显示今天：`lib/todoToday.ts`

判定（纯函数，5 条单测）：

- **任一时刻落在今天** → 今天：开始时间 `remind_at`、截止时间 `planned_at` 任一满足即可
  （只判 `planned_at` 会让「只设了开始时间」的待办凭空消失）；
- **两个时刻都没有** → 也算今天。未排期的待办不属于任何一天，若一并隐藏，它在这个窗口里
  **完全消失**（没有第二个入口能看到它），这比「混在今天里」更糟；
- 边界按自然日 `[今天 00:00, 明天 00:00)`，与 `useTodayRecords` 的今日区间同口径。

过滤发生在 `TodosPanel`：`splitTodos` 之后再滤，所以「待办事项 · N」与「已完成 · N」的计数
自动跟着变；空态判定也改成「今日记录为空 **且** 今日待办为空」。

### 2. 过期 = 降透明度 + 横线，不再是「更红的红」

```css
.todo-pend[data-tone="overdue"] { opacity: 0.62; }
.todo-pend[data-tone="overdue"] .todo-pend__title {
  color: var(--todo-overdue);
  text-decoration: line-through;
  text-decoration-color: var(--todo-overdue);
}
```

- 整行降透明度（文字、时刻、圆圈一起淡），**名字加一道横线** —— 一眼能看出「这条已经过去」；
- 颜色仍取可配的 `--todo-overdue`，但被透明度压住，不再和「进行中」的强调色抢注意力；
- 已完成的横线仍走 `--todo-name-done` + `--line-3`（在「已完成」分组里），两者靠分组和颜色区分。

## Consequences

- **未来的待办在它们的日子里之前不可见**：面板是「今天」的截面，这是刻意的。
  代价是「我上周建的、定在下周的待办去哪了」需要一个答案——目前靠改时间把它挪到今天，
  或者等那天到来。真要全量视图，应另开「全部待办」入口，而不是把今天的面板撑大。
- 过期判定仍是 `planned_at < now`（`pendingTone`）：只设开始时间的待办不会「过期」，
  因为开始时间不是截止承诺。
- 截止时间在**昨天**的待办今天不会出现（它不属于今天），这与「过期也要能看见」存在张力；
  如果实际用起来希望「昨天的未完成继续挂在今天」，只需把 `isTodoToday` 改成
  「今天 ∨ 已逾期且未完成」，一处改动。

## Revision V0.3.15：过期待办自动删除

用户追加口径（原话）：「过期待办自动删除」。

**规则**：`jobs::nudge`（已是 15s 的待办生命周期扫描）每 tick 调
`services::todo::purge_overdue(pool, clock::start_of_today_ms())`，把
**`planned_at < 今天 00:00` 且未完成**的待办批量软删除。

- **为什么是「跨天」而不是「一过截止时刻就删」**：上一条要求刚把过期项做成
  「降透明度 + 一道横线」的**可见**样式，若一到点就删，这个样式根本没有机会被看到。
  与「只显示今天」共用同一条自然日边界，三条口径才自洽：
  **今天之内继续淡化展示 → 跨天自动清掉**。
- **只看 `planned_at`**：没有截止时间的待办不会过期（与 `pendingTone` 同口径）；
  已完成的不清（那是当天的成果）；只有开始时间的不算过期（开始时间不是截止承诺）。
- **软删除**：走 `soft_delete`（`deleted_at`），行还在库里，误删可查；不做物理删除。
- **触发时机**：跨零点后 15s 内生效；应用没开则下次启动第一次 tick 补齐 ——
  关了一周再打开，这一周攒下的过期项会一次性清掉。
- **零契约改动**：没有新命令 / 事件 / 错误码，只是既有 service + repo 的一个定时调用。
- 前端零改动：面板本来就按「今天」过滤，被清掉的行早已不在视图里；窗口重新获得焦点时会重拉。

**代价**：待办一旦过期就**没有撤销入口**（提醒浮出卡那次是人工动作，这个不是）。
若以后需要「回收站」，应当在设置里加「保留 N 天」，而不是把这条清理逻辑改回去。
