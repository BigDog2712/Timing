# ADR-002: 使用 React 19 + TypeScript + Zustand 作为前端与状态管理

## Status

Accepted (2026-10-16)

## Background

Tauri 前端技术栈可选 React、Vue、Svelte 等，Tauri 对前端框架无绑定。TickBar 前端体量小（药丸条 + 事项选择器 + 设置面板 + 记录列表），但需要：类型安全、低运行时开销、组件化、与 Tauri 官方脚手架契合。状态管理需覆盖计时 UI 状态、事项列表、设置。

## Decision

选择 **React 19.3.0 + TypeScript + Vite 8.3.4 + Zustand ^5**。

理由：
1. React 生态最成熟，`create-tauri-app` 原生模板支持，社区示例最多。
2. Zustand 体积极小（约 1KB），契合「低占用」诉求；API 简单，无需 Provider 层层包裹。
3. TypeScript 一等支持，DTO 类型可与 Rust serde 模型严格对齐，降低 IPC 传参错误。
4. 状态边界：前端 Zustand 仅存 **UI 状态**；计时状态机的事实来源在 Rust（见 ARCHITECTURE §3.2），避免双写不一致。

备选：Vue 3 + Pinia（团队若更熟 Vue 可整体替换，不影响分层与 IPC 契约）；Svelte 5（生态与模板较少，不选）。

## Consequences

正面：
- 生态成熟、迭代快、类型安全；Zustand 开销极小。
- 与 Tauri 官方脚手架无缝，减少配置成本。

负面：
- React 19.3 为较新版本，个别第三方库兼容性需实测（锁定主版本）。
- 需严格约束「组件不直连 invoke」，否则状态分散（见硬规则 §3.4-8）。
