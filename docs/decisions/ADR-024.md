# ADR-024：统一正计时 / 倒计时状态环的动画语义与结构（单轨 SVG 弧 + 显式 data-spin）

## Status

Accepted（2026-10-19，V0.3.6；用户口径「两种模式的环要看起来是同一个东西，倒计时不能被转」）

## Background

状态环（`components/pill/MainButton.tsx`，16×16 圆角方形）同时服务正计时与倒计时。
V0.2.0 加倒计时时，是在正计时的环上**叠了一条 SVG 弧**，没有把两套语义合并；V0.3.3 又把
「环」从圆形改成圆角方形并引入 `lib/ringGeometry.ts` 的 `ARC_PATH`。两次叠加之后留下五处缺陷，
其中一处是功能性的：

1. **D1（P0）倒计时弧被旋转**。`visual` 由 `toVisualState(status)` 得到，倒计时运行时
   `status` 仍是 `running`，于是命中 `.ring[data-state="running"] .ring__arc { animation: ring-spin }`。
   递减弧一边按剩余比例缩短、一边绕圈——**弧的终点位置每 0.1 秒都在变，用户读不出剩余量**。
   这是「用状态选择器表达动画意图」的典型代价：`data-state` 描述的是计时状态机，
   而不是「这条弧应不应该动」。
2. **D2（P1）底环两套实现**。正计时 running / paused 用 CSS `border`（同色 35% 透明）当底环、
   且 `track: false`；倒计时用 SVG `ring__arc-track`（37%）。两套载体在**分数 DPI** 下抗锯齿
   方式不同（SVG 走 subpixel 裁剪、`border` 走像素对齐），同一个 16px 盒里一条会显得更实、
   另一个更糊；透明度口径也多出一个 35% 的近似值，没有和第二处对齐的依据。
3. **D3（P1）暂停态两套语言**。正计时 paused = 270° 静弧（Timing `RingPause` 暖橙）；
   倒计时 paused = 冻结的进度弧（可能停在 63%）。同是 warn 色，弧长含义完全不同：
   前者说「暂停」，后者说「还剩 63% 且暂停」。用户需要先判断当前是哪种模式，才能读懂环。
4. **D4（P2）待命态误用进行时**。`armedIdle`（时长已选好、尚未开始）传 `countdown=true`、
   `progress=1`，于是环被画成「满弧 + 满轨」；弧色写死 `--color-running`（亮绿），
   而轨道取 `currentColor`（此时是 `--state-idle` 的 ink），再叠加 `data-state="idle"` 时
   border 被置透明——一个「还没开始」的环，看起来比「进行中」还满、还是两种颜色。
5. **D5（P2）归零残留圆点**。`stroke-linecap: round` 下零长度 dash 会渲染成直径 = 描边宽
   （2.4）的圆点；倒计时归零那一瞬间，环上会留一个亮点。
6. **D6（P0，V0.3.3 引入、V0.3.6 继承）行进用 `transform: rotate()` 转整个 `<svg>`。**
   圆形时代这是零成本近似（圆的旋转对称连续）；换成 squircle（只有 90° 对称）之后，
   正计时运行时**整个环被转成歪框、弧还浮出轨道**。详情与修法见 Decision 第 3 条。

另外 `tokens/05-typography-rules.css` 的 reduced-motion 块里还留着
`.ring[data-state="running"]{stroke-width:3px}` / `.ring[data-state="paused"]{stroke-dasharray:4 3}`
两条 V0.3.3 之前的死代码（`.ring` 是 `<button>`，`stroke-*` 对 HTML 元素无效）。

## Decision

1. **单一结构：只要有弧，就一律「SVG track + SVG bar」。**
   新增 `data-arc`（与「是否渲染 `<svg>`」同源，由 `arcSpec()` 返回非 null 决定），
   `.ring[data-arc="true"] { border-color: transparent }`。计时态不再用 `border` 当底环；
   `border` 只保留给 **idle 未待命**（细环）与 **ended**（`--color-done` 加粗）。
   删掉 `surfaces.css` 里 35% 的 `border-color` 两条，底环透明度只剩 `ring__arc-track` 的 37% 一处。
   ——**为什么不让 track 与 bar 各走一条通道**：底环的作用是「给出全长参照」，它必须和弧
   同一条路径、同一套抗锯齿，否则「弧走到一半」这件事在视觉上会漂移。

2. **弧语义统一（顶边中点起顺时针）**，`arcSpec(state, countdown, progress)` 的映射表：

   | 情形 | frac | track | march（行进） | 载体 / 动画 |
   | --- | --- | --- | --- | --- |
   | 倒计时 running | `progress`（剩余比例） | ✓ | **false** | SVG，静态 dashoffset |
   | 正计时 running | 0.25（90°） | ✓ | **true** | SVG，`ring-march` 推进 dashoffset |
   | paused（两模式） | 0.75（270°） | ✓ | false | SVG，静态 |
   | idle + 待命（armedIdle） | 1（全周） | ✓ | false | SVG，静态 |
   | idle 未待命 | — | — | — | border 细环 |
   | ended | — | — | — | border done 加粗 |

3. **「行进」用 `stroke-dashoffset` 沿路径推进，不用 `transform: rotate()`。**
   这是本次真正的技术裁决点。V0.3.3 把环从圆形改成圆角方形（squircle）时，
   `rotate()` 加在整个 `<svg>` 上的旧实现没有跟着改，于是留下两个**静默回归**：
   - **底轨一起被转 → 整个环歪掉**。圆的旋转对称是连续的，怎么转都一样；
     **squircle 只有 90° 旋转对称**。转到 41° 时四条边既不水平也不垂直，视觉上就是个歪框
     （QA 实测 `matrix(0.752, 0.659)` ≈ 41°，截图可证）。这是一条可量化的判据：
     未旋转时墨迹包围盒 = **16.0**；转 41° 后 = 只有**直边段**在投影上被拉伸
     （`6.0 × (cos41°+sin41°) = 6.0 × 1.4108 = 8.46`），四角圆弧与描边不随旋转增长
     （`+ 2 × 3.8 + 2.4`），合计 **≈ 18.47**（QA 实测 18.50）。
     —— 注意别套用「锐角正方形」的 `16 × 1.4108 = 22.6`：那是把整条边长都当直边算的，
     squircle 的 16 里有 7.6 是圆角半径、2.4 是描边，它们旋转后不增加包围盒。
   - **弧出轨**。90° 的弧段只在 90° 整数倍上与轨道曲率吻合；转到中途，这段弧的曲率与底下
     静止的轨道不匹配，弧会浮在轨道内外。
   改成 `stroke-dasharray: "25 75"`（可见 25 + 空白 75）+ `@keyframes ring-march`
   把 `stroke-dashoffset` 从 `0` 推到 `−100`：dash 段**始终是真实路径的一段**，
   所以弧永远贴着轨道走、过弯自然，而 track 一个像素都不动。动画落在 **bar** 上，
   `.ring__arc` 不再有任何 `transform`。
   ——两侧口径也因此分开且显式：静态弧用 `dasharray: 100` + 静态 offset 表达「还剩多少」；
   行进弧用 `dasharray: 25 75` + 动画 offset 表达「正在进行」。由 `arcSpec.march` 决定，
   CSS 不猜（`arcDashArray()` 在 `lib/ringGeometry.ts`，有单测钉住 `"25 75"` 与浮点尾巴）。

4. **「是否行进」显式化**：`arcSpec` 返回 `{frac, track, march}`，DOM 上落 `data-spin="true|false"`
   （属性名沿用了本版早期的历史命名，语义已是「弧沿轨道自行推进」，与 transform 无关），
   CSS 只写 `[data-spin="true"] .ring__arc-bar { animation: ring-march … }`。
   `data-state` 回归它本来的职责（描述计时状态机），**不再兼任动画开关**。
   ——这是 D1 的根因修复：只要未来再加一种「running 但不该动」的局面，
   忘了改 CSS 的代价从「弧乱动」变成「弧不动」，是可接受的失败方向。

5. **D5：`frac` 低于阈值就整条 bar 不渲染。** 新增 `ARC_MIN_FRAC = 0.001`（万分之一周 ≈
   pathLength 0.1 个归一单位）与 `isArcVisible()`，判定收在 `lib/ringGeometry.ts` 里供单测。

6. **弧色与轨色同源 = `currentColor`。** `ring__arc-bar` 的 `stroke` 由写死
   `var(--color-running)` 改为 `currentColor`，轨道本来就是 `color-mix(currentColor 37%)`。
   于是「环是什么色」只剩 `.ring` 上的一处 `color`：running → `--color-running`、
   paused → `--color-warn`、`data-warn` → `--color-danger`、idle 待命 → `--color-running`
   （新增 `.ring[data-state="idle"][data-arc="true"]`）。D4 的「亮绿弧 + ink 轨道」分叉随之消失。
   令牌色值一个都没改，`data-warn` 的 blink 仍同时作用于弧与轨道，paused 仍不切红。

7. **美观约束（结构不动的前提下）**：track / bar 的 `stroke-width` 都是 `var(--ring-stroke)`；
   bar 保留 `stroke-dashoffset var(--dur-tick) linear`（每秒 tick 平滑过渡，给倒计时用；
   行进态把 dashoffset 从 transition 里摘掉、只留 `stroke` 的颜色过渡，动画驱动的变化本来
   也不会触发 transition，但摘掉可以省掉「切到 running 第一帧」那次多余插值），track 不加
   transition（底轨是静态参照物，跟着一起动会让整环看起来在抖）；
   **不加发光 / drop-shadow / 渐变**——16px 盒上加光影只会糊成一团。

8. **暂停是「瞬时定格」，不是过渡**（N2）。只在 `[data-state="paused"]` 的 bar 上把
   `stroke-dashoffset` 从 `transition` 里摘掉（留 `stroke` 的颜色过渡）：CSS transition 取
   **变化后状态**的 declaration，于是 running→paused 命中这条、弧长在一个 rAF 内直接到位；
   倒计时 running 的每秒 tick 平滑不受影响（基准规则里的 `--dur-tick` 仍在）。
   为什么：暂停的语义是「停住」，1s 线性渐变等于告诉用户「还在动」；更糟的是倒计时剩 20% 时，
   弧会从 72° 缓缓长到 270°，**看起来像进度回退了**。正计时那边本来就是硬切，改完两边手感一致。

## Alternatives

- **行进继续用 `transform: rotate()`**（V0.3.3 的既有做法）。否决：squircle 只有 90° 旋转对称，
  转起来 ① 底轨一起歪、② 90° 弧段的曲率与静止轨道不吻合而浮出去。这是本版最严重的一条
  视觉缺陷，也是「不美观」的主因之一——机器判据：墨迹包围盒从 16×16 涨到 ≈22.6。
- **只把 bar 挪出旋转容器、track 不转**（即"只转弧、不转底轨"）。否决：只解决了①，
  ②照样存在——`rotate()` 是刚体旋转，转到 41° 时弧的曲率与轨道依然不吻合，弧仍会浮出去。
- **`offset-path: path(ARC_PATH)` + 动画 `offset-distance`**。否决：offset-path 移动的是
  **一个元素**而不是"一段 dash"，要画出 90° 弧仍需另给一个路径/描边，等于把 `ARC_PATH`
  复制成第二处定义，与 `ringGeometry.test.ts` 的逐段验算分叉。SMIL `<animate>` 同理，
  且不受 CSS 媒体查询（reduced-motion）统一管辖。
- **在 CSS 里用 `:not([data-countdown="true"])` 关掉行进**，不加 `data-spin`。
  否决：它把语义写成「不是倒计时就动」，而真实规则是「正计时 running 才动」。将来出现
  「倒计时到点后的瞬时确认」「暂停前的收尾」这类 running 变体时，这个选择器会静默放行。
  `data-spin` 是白名单，失败方向安全。
- **保留 border 底环，只把 35% 改成 37% 对齐**。否决：透明度对齐了，抗锯齿口径还是两套
  （subpixel vs 像素对齐），D2 的「两个号」在 125%/150% 缩放下依旧存在；而且 bar 一旦跨过
  90° 就需要和底环同径同源，border 做不到「与弧端点严丝合缝」。
- **倒计时暂停保留冻结进度弧**（信息量更大：「还剩 63% 且已暂停」）。否决：与正计时 paused
  的 270° 形成两套语言，且用户此刻最需要的是「已暂停」这个状态而不是精确百分比——
  百分比在 `timer-digits` 上本来就有数字。统一成 270° 后，暂停读起来只有一种含义。
- **D5 改为 `frac → 0` 时临时切 `stroke-linecap: butt`**。否决：`stroke-dashoffset` 每秒 tick 一次
  过渡，在过渡中途切换端点形态会让端点闪一下（round → butt 的宽度差正好是 2.4px）；
  整条 bar 不渲染更干净，且 `track` 仍在，环不会「塌成半圈」。
- **用 SVG `<circle>` + `stroke-dasharray` 自绘圆角方形**。否决：`ARC_PATH` 已经和
  `lib/ringGeometry.ts` 的算术互相验证过（`ringGeometry.test.ts` 逐段验算切点与半径），
  换载体等于把这条防线推倒重来，收益为零。

## Consequences

- 倒计时环现在只表达「还剩多少」，正计时环只表达「正在进行」；paused 在两模式下读起来完全一致。
- **正计时环不再歪**：`getComputedStyle(.ring__arc).transform === "none"`，且多个相位的墨迹包围盒
  恒为 16.0（旋转状态下 ≈18.5，实测 18.50）；90° 弧在任何相位都与轨道同宽同径、过弯自然。
  行进速率实测 ≈ −31.25 归一单位/秒（3.2s 走完 100），连续无阶梯。
- `data-spin` / `data-arc` / `stroke-dasharray` 是可以被测试断言的**结构契约**：
  `src/components/pill/MainButton.test.tsx` 用 `createRoot` + `act`（不用
  `renderToStaticMarkup`——zustand v5 的 `useSyncExternalStore` 在 SSR 下会读到初始 state）
  覆盖「倒计时不行进 / 正计时行进（dasharray `25 75`）/ 两模式暂停 270° / idle 两副面孔 /
  ended / 归零不画残点」；`lib/ringGeometry.test.ts` 钉住 `arcDashArray` 的两套口径。
- 代价：弧色改为 `currentColor` 后，「弧与环不同色」这件事在 CSS 里不再可能——这是**故意的**
  （此前正是靠写死 `--color-running` 才让待命态出现双色）。若将来真需要「亮弧 + 暗轨以外」
  的花样，应当新增 `color` 之外的设计令牌，而不是在 SVG 里写死第二处色值。
- **已知偏置（刻意保留，不是缺陷）**：`stroke-linecap: round` 让 dash 两端各多出
  `stroke / 2 = 1.2` 个归一单位（周长按 100 计），所以短弧的视觉长度有一个**约 5% 周长的下限**：
  倒计时剩 1%（≈3.6°）时肉眼看到约 6%（≈21°），是数值的约 6 倍。
  之所以保留：它与 D5「归零瞬间整条 bar 不渲染」配合，避免尾部出现「弧先没了、数字还在走」
  的空窗（0~5% 区间里，弧始终有可见的最小形状，直到真正归零才整体退场）。
  **若将来要做「弧长严格等于数值」**，必须改成 `linecap: butt`：代价是弧端点变平，
  与行进态（正计时 90° 短弧）的圆头不再同形，看起来像两种笔；届时要么全状态统一 butt，
  要么接受这两种形状并存并写进设计说明。
- 遗留（V0.3.7）：idle / ended 仍由 `border` 承载，而 Chromium 会把 border 宽度吸附到整数
  设备像素（`--ring-stroke: 2.4px` 在 DPR 1 上实测 2.00，SVG 侧 2.44，且在 125% 缩放下差异
  消失）。方向是把这两个状态也并入 SVG 单载体，见下一条 ADR。
- 契约层零改动：命令 60 / 事件 9 / 错误码 15 不变；版本号仍 `0.3.0`（本次是 Unreleased 内的
  V0.3.6 迭代）。
