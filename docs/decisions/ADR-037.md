# ADR-037：插件 API v3 —— 声明式面板（`panels`）与受限动作目录

## Status

Accepted（2026-11-04，V0.4.x / Unreleased）。承接 ADR-033 的「插件不执行代码」边界与
ADR-036 的「插件只做声明」定位。

## Background

ADR-036 把 md 同步收回宿主后，插件只剩 `quickTimers` 一个贡献点——本质是「往已有功能里
填数据」。用户的要求是另一件事：「其他人可以通过创建插件来给应用增加功能」。

当时判断缺口有三处：没有 UI 落点、没有执行入口（`EntryKind::Script` 是明确拒载的预留位）、
没有能力目录。也就是插件能改参数，但加不了任何新东西。

方向确认：插件贡献**独立窗口 + 声明式表单**，按钮绑宿主内置动作。

## Decision

### 1) 面板是数据，不是代码

`contributes.panels` 最多 3 个，每个面板由若干 `blocks` 组成，块类型是**封闭枚举**：

| `type` | 作用 |
|---|---|
| `text` | 静态段落 |
| `stats` | 带条形的排行（数据来自白名单 `source`） |
| `list` | 纯文本列表 |
| `actions` | 按钮组，每项绑定白名单 `action` |

写了没实现的 `type` 会让整个清单解析失败。理由：**半渲染的界面比拒载更难排查**——
用户看到一扇空白窗，只会以为插件没生效。

### 2) 能力是白名单，不是脚本

数据源：`records.byItem`（近 N 天各事项时长）、`todos.pending`。
动作：`timer.start`、`timer.pause`、`todo.add`、`note.create`。

参数用具名字段（`QueryParams` / `ActionParams`），不是自由 JSON。这样校验能落在加载阶段：
`timer.start` 没写 `item` 直接拒载，而不是点下去没反应。

白名单在两个地方各挡一次：`plugin_fs::validate` 管「插件写错了」，`commands::plugin_cmd`
管「调用方绕过清单直接调 IPC」。成本都是一行 `contains`。

### 3) 窗口模型

label = `panel-{pluginId}-{panelId}`，**身份不放 label**（两个 id 都允许含 `-`，反解会切错），
放查询参数 `?w=panel&plugin=..&panel=..`。与设置 / 事项 / 便利贴三类浮层相反，面板窗
**上任务栏**：它是用户主动打开的功能窗。

面板定义从 `plugin_list` 读，不新增「读某个插件」的命令——设置页刚读过的那份清单就是
权威来源，多一条命令只会多一处要同步的词表。

### 4) 入口

「设置 → 插件」每个面板一行「打开「标题」」。手机端不显示（`showPanels={false}`）：
面板窗口是桌面多窗口模型的产物，`plugin_panel_open` 在移动端回 `IO_ERROR`。

## Consequences

- `apiVersion` 升到 **3**。v1/v2 插件不受影响：`panels` 是可选字段，不写就不会被当 v3 解析。
- 新增 3 条命令（`plugin_panel_open` / `plugin_panel_data` / `plugin_action_run`），
  契约从 65 条涨到 68 条，四处（Rust / `IpcApi` / `ipc.ts` / mock）同步更新。
- 新文件：`models/plugin_panel.rs`（schema + 校验）、`services/plugin_panel.rs`（数据源 + 动作）、
  `infra/window_panel.rs`（建窗）、`components/plugin/*`（渲染）。
- 仓储层新增 `record::stats_by_item_named`：面板要直接显示事项名，让前端再拉一次事项表
  就多一次往返、也多一处口径。
- 能力目录是**闭合**的：想加新动作要在 Rust 侧实现 + 升 apiVersion。这是刻意的——
  开放的代价是沙箱、权限模型与崩溃隔离，而收益只是让一个个人应用承担任意代码执行的风险。

## Alternatives considered

| 方案 | 为什么没选 |
|---|---|
| 内嵌 JS 引擎（Boa / QuickJS）跑插件脚本 | 表达力最强，但要 API 注入、超时与内存上限、崩溃隔离；安卓还得另找一套 JVM 侧引擎。第一版先不背 |
| 纯声明 + 更多块类型（表格 / 图表 / 表单绑定） | 会把「加一块 UI」变成「实现一个渲染器」；先看真实插件怎么写，再决定补哪种 |
| 只做动作菜单项（右键菜单加一条命令） | 最轻，但插件只能「多一个命令」，做不了展示型功能（周报、排行） |
| 面板放设置页的新页签 | 不用开新窗口，但「设置」里放功能入口反直觉；且手机端设置只有三页，会挤 |

## 已知限制

- 面板**无状态**：没有插件自己的存储区，也没有跨次打开的表单草稿。需要持久化的场景
  目前只能借 `todo.add` / `note.create` 落到真实数据上。
- 数据块每次打开面板都重新查一次，不缓存。量级很小（一次聚合 + 一次列表查询）。
- 面板之间不能互相跳转，也没有深链接。
