# ADR-017：单文件 ≤300 行 + 机械门禁（体积 / 版本 / 契约 / 分层 / Lint / 测试）

## Status

Accepted（2026-10-18，架构评估 P0「约束只写在文档里，没有机械执行」项；对应任务 T01 / T02 / T03 / T06 / T12 / T13）

## Background

`AGENTS.md` 里写着「单文件 ≤300 行」「版本号六处必须一致」「IPC 契约以 `check:contract` 为准」。评估时逐条核对，实际情况是：

| 约束 | 文档 | 实际 |
| --- | --- | --- |
| 单文件 ≤300 行 | 有 | 4 个文件超限（`types/domain.ts` 552 / `design-tokens.css` 486 / `tests/timer.rs` 347 / `app.css` 301），无任何检查 |
| 版本号一致 | 有 | 6 处字段（`package.json` / `package-lock.json` ×2 / `Cargo.toml` / `Cargo.lock` / `tauri.conf.json`），只能靠人工对 |
| IPC 契约 | 有 `check-contract.mjs` | 只校验**命令**与**错误码**；事件名与 mock 覆盖完全没查 |
| 分层 | 有（散文） | 6 个文件反向依赖，无人发现 |
| 前端 lint | 无 | 没有 `.eslintrc` / `eslint.config.js` |
| 前端测试 | 无 | 没有 `vitest.config.ts`，0 个前端测试 |

结论：**所有架构约束都是「君子协定」**。这才是评估里最该先修的一条——约束不被执行，就等于不存在；而一旦有机械门禁，后续所有重构才有「不会悄悄退回去」的保障。

## Decision

**凡是能机械判定的约束，一律做成脚本 + 进 CI；文档只保留「为什么」，不承担「记不记得住」。**

新增 / 重写六道门禁，全部挂在 `npm run check`：

1. **`scripts/check-size.mjs`（新）**：扫 `src/**`（`.ts/.tsx/.css`）与 `src-tauri/src/**`（`.rs`），单文件 >300 行即失败。
   白名单 `scripts/size-allowlist.json` 每条**必须**带 `owner` + `expires`（到期即红），并且在文件降到 300 行以内后会主动提示「该条目已可删除」——防止白名单变成永久豁免。本次 T12 拆完后白名单已清空。
2. **`scripts/check-version.mjs`（新）**：断言六处版本字段彼此相等，不一致直接列出各自的期望值与实际值。
3. **`scripts/check-layers.mjs`（新）**：6 条 grep 规则（详见 ADR-016）。这条把「依赖只能向下」从散文变成可执行断言。
4. **`scripts/check-contract.mjs`（重写）**：在原有命令 / 错误码之外，增加
   - **事件三方一致**：后端常量 ↔ 前端 `IPC_EVENTS` ↔ 实际 `emit` 调用的字面量；
   - **字面量拒绝**：禁止 `app.emit("timer:state-changed", ...)` 这种绕过常量的写法；
   - **mock 覆盖**：`browserMock` 的键集合必须等于 Rust 注册的命令集合。
   - 事件文件位置可迁移（先找 `app/events.rs`，找不到回退 `infra/events.rs`），避免门禁把目录结构调整当成破坏。
   - 死常量检测用「标识符出现次数 ≥2（声明 + 使用）」判定，而不是脆弱的字符串匹配 —— 否则像 `NOTE_WINDOW_OPENED` 这种**间接引用**会被误报。
5. **ESLint（新，`eslint.config.js`）**：typescript-eslint recommended + `react-hooks`。**刻意不加任何风格规则**（缩进 / 引号 / 排序一律不管）——风格规则会让一次机械化改动淹没真正的 diff，且与 `tsc` 的职责重叠。只保留正确性规则。
6. **Vitest（新，`vitest.config.ts`）**：jsdom 环境，`src/**/*.test.{ts,tsx}`。

配套的**双端黄金用例**（T14）：`tests/fixtures/timer-formula.json` 存 12 条边界（0 / 999 / 1000ms / 跨暂停 / 跨落盘 / 负偏移 / 跨天 / 倒计时剩余 / 暂停中 / 多段落盘 / 撤销后 / >24h），Rust 端 `tests/timer_formula.rs` 用 `include_str!` 读它、前端 `useTimerTick.test.ts` 用 `resolveJsonModule` 读它。**同一份 fixture 锁住两端**，任何一边改了公式，另一边立刻红。

CI（`.github/workflows/ci.yml`）拆三个 job：`gates`（不编译，几十秒出结论，ubuntu）、`frontend`（typecheck + lint + test + build）、`backend`（test + clippy `-D warnings` + `cargo fmt --check`）。

## Consequences

正面：

- **每条门禁都实测「先红后绿」**：写脚本时先让它对着真实违规报错，修完再确认转绿。没有一条是「写完就当它能用」。
- 门禁实际抓到了真问题：`check-layers` 抓到 `infra/window.rs` 残留的 `eprintln!`；`check-contract` 抓到 `app:open-settings` 是**后端从未 emit 的死常量**（前端却一直订阅着），以及 mock 缺 8 条命令（浏览器 dev 下日记 / 丢弃计时 / 日状态直接走不通）；`check-size` 抓到拆分后 `services/timer.rs` 又涨到 302 行。
- 契约面从「62 条命令 + 16 个错误码」扩到「+ 10 个事件 + 62 条 mock 覆盖」，`check:contract` 输出一行可读的计数摘要，改错一眼能看出是哪一类不一致。

负面 / 已接受的代价：

- **CI 时间变长**：多一个 `gates` job（ubuntu，~40s）与前端 lint/test。因为 `gates` 不编译，它是 PR 上最先返回结果的那个，实际体验是「更快知道架构层有没有破」。
- **白名单机制是一把双刃剑**：`expires` 到期会让 CI 变红，维护者必须回来处理。这是刻意设计（宁可红一次，也不要永久豁免），代价是到期那天需要一个 5 分钟的 action。
- **`cargo fmt --check` 需要全库先格式化一次**。本次执行了 `cargo fmt`（20 个文件、96 行纯格式差异），提交后 CI 的格式检查才有意义。若将来改动 `rustfmt.toml` 的 `max_width`，会引发全库重排，必须单独一次提交。
- **`-D warnings` 让 clippy 从「建议」变成「阻断」**。本次顺手修掉 4 条（`is_multiple_of`、`Range::contains`、文档列表缩进），以后每加一个新依赖都可能引入新 lint，需要有人跟。
- 门禁只覆盖「能 grep / 能计数」的约束。语义类约束（例如「服务层不得直接发事件」）仍要靠 code review。
- E2E（T18）**没有做**：`tauri-driver` + WebDriver 在单人项目里的维护成本高于收益，改用「5 条手测清单」（见评估报告 §4）。自动更新（T19）与安装包签名（T20）依赖证书采购与外网托管，代码侧已留出位置，未启用。
