# ADR-043：跨零点的会话在结束时分段落库

## Status

Accepted（2026-11-05，V0.11.3）

## Background

`time_records` 的归属口径一直是「按 `started_at` 所在的那一天」。导出到日记时，
`records_for_day(from, to)` 也只按 `started_at` 过滤。于是 23:40 开始、00:20 结束的会话
整条算在昨天，今天的日记里完全看不到它。

`export.rs` 顶部原本把这件事写成「已知限制」，并说明了另一个方案（导出时把 start 裁到今天 0 点）
为什么被否掉：那样会让一条会话同时出现在两天，一旦停止就带着昨天的 `started_at` 落库、
从今天的区块里消失，用户会以为「刚停就丢了」。

用户口径（V0.11.3）：「跨零点分段记录」。

## Decision

**在落库时拆，不在渲染时裁。** 会话结束时判断是否跨越本地零点，跨了就切成多条独立的
`saved` 记录，每条都落在同一天之内。

具体规则：

1. 切点取**本地零点**（`platform::clock::day_bounds`，与 md 按天取数共用同一条日界，
   含 DST 缺口兜底）；
2. 累计秒数按**墙钟占比**分配，余数归最后一段 —— 整数除法只少分不多分，所以总和恒等于原累计；
3. 原记录 id 保留给**最后一段**（撤销条、「刚结束的那条」、md 导入对位都还指着它），
   前面各段作为新行插入；
4. 中间段 `target_sec` 置 NULL（倒计时的目标只属于真正结束的那一段），`mode` 整段复制。

覆盖四条结束路径：手动结束、倒计时到点、崩溃恢复的「结束并保存」、切换事项的「结束并开始」。

## Consequences

- 日记里每一天都只出现属于那一天的时间，统计按天汇总就是对的。
- 分割按墙钟比例而非真实暂停点：跨夜挂机的会话（中间睡了 8 小时）会把时长按墙钟摊开。
  要精确到暂停点，就得在每次暂停时也写一条分段——那等于让暂停变成写库操作，不值得。
  误差不会丢数据（总和守恒），只会让零点前后的归属略有偏差。
- 跨天会话会变成多条记录，用户如果在记录列表里看到「同一事项两条相邻记录」，那是预期的。
- 撤销只撤最后一段。跨零点的会话通常早已超出撤销窗口（`UNDO_WINDOW_MS`），可接受。
- 历史数据不追溯拆分：改写老记录是破坏性操作，用户没要求，也不该替他做。
