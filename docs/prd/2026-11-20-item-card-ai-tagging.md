# PRD：事项管理卡合并 + AI 打标优化（0.12.6）

| 项目 | 内容 |
| --- | --- |
| 版本 | 0.12.5 → 0.12.6（仅 Windows 桌面端） |
| 范围 | 分析窗「主界面」今日视图卡片板 + AI 打标规则 |

## 1. 目标与非目标

**目标**
1. 把「待办事项」和「今日时间线」合成一张卡，减少一块重复板位，用户一天的事只在一个地方看和改。
2. 把卡片从「今天的记录」升级为「事项资产」：常用事项沉淀下来、可绑应用、开应用自动计时。
3. 打标从「人工点」变成「AI 一键 + 越用越准」，并让工具类应用不污染统计。

**非目标（本轮不做）**
- 手机端 / Android 端任何改动。
- AI 直接无预览写库（必须保留预览 + 逐条摘除 + 可撤销）。
- 跨设备同步（事项、标签、绑定的云端同步）。

## 2. 用户故事

| # | 故事 |
| --- | --- |
| 1 | As 每天用计时条的人，I want 待办和时间线在一张卡里上下分区，So that 我不用在两块板之间来回看同一件事。 |
| 2 | As 长期用户，I want 常做的事项存成可复用条目并直接点一下就开始计时，So that 我不用每次重新输名字和时间。 |
| 3 | As 不想手工打标的人，I want 一键让 AI 给未打标事项分类并先给我看结果，So that 我能低成本把标签补全又不怕它乱写。 |
| 4 | As 按应用计时的用户，I want 事项和应用双向绑定、开应用就自动计时、关应用就自动结束，So that 我不需要记得手动点开关。 |
| 5 | As 装了很多工具软件的人，I want 下载器/终端/截图工具这类被识别为「工具」并不计入时间统计，So that 我的分类分布不被这些软件拉歪。 |

## 3. 需求池

### P0（Must have）

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| P0-1 | **时间线卡**：原「待办事项」+ 原「今日时间线」合成**一张卡**，上「待办」、下「今日时间线」，中间一条浅横线 | 卡片板上不再同时出现原 todos 与 timeline 两张卡；新卡一块区域到底，横线贯穿卡宽 |
| P0-2 | **旧布局迁移**：存量 todos → 「事项管理」卡、timeline → 「今日时间线」卡，各自**保留原矩形**；只有一张旧卡时不凭空加卡 | 升级后旧两卡各归其位；用户自定义摆位不丢；不出现重复卡；旧卡种 uid 失效不报错；迁移幂等 |
| P0-3 | **待办能力并入时间线上区**：待办以「未开始」行出现在上区，可就地勾选完成，时间/提醒/3 秒撤销/编辑弹层全部保留 | 新建待办后立刻在上区以未开始行出现；勾选后行为与旧待办一致（含撤销提示） |
| P0-4 | **事项管理为一张全新独立卡**：常用事项（置顶）＋ 历史事项两组；支持新增、编辑、事项管理；**不设时间**；与时间线卡是两张卡，可各自摆位 | 卡片板上「事项管理」是独立卡片，不是时间线卡的一个区；该卡新建事项无时间/提醒字段；置顶项排在最前 |
| P0-5 | **事项点击起停计时**：点事项即开始计时，再点结束，产生今日时间线记录 | 点击后下区新增一条进行中的记录；再次点击落库为一段记录，用时正确 |
| P0-6 | **AI 一键分类按键**：置于事项管理卡动作组，只处理**未加标签**事项，先预览后落库、可逐条摘除、可撤销 | 已带标签的事项不被覆盖；预览中取消则零写入；写入后可整体撤销 |
| P0-7 | **事项 ↔ 应用双向绑定**：任一侧绑定/解绑，另一侧同步；重复绑定不产生双份 | 事项侧绑 A 应用后，应用排行行的标签/绑定区立即显示该事项；应用侧解绑后事项侧同步消失；同一对重复绑定仍为一条 |
| P0-8 | **绑定即自动计时**：切到已绑定事项的应用 → 自动开始该事项计时；该应用进程退出 → 自动结束该段 | 切换后时间线出现进行中记录；退出后该段自动收尾且起止时间正确；不产生 0 秒碎片记录 |
| P0-9 | **工具标签**：「工具」加入一级标签白名单；应用带「工具」标签时其时长**不计入**分类分布 / 趋势 / 总量 | 打「工具」的时长在分布、趋势、总时长中消失；应用排行仍显示该应用并标注「工具」 |
| P0-10 | **AI 打标规则升级**：见 §3.1 | 用 Chrome / 燕云十六声 / Obsidian / Snipaste 四个样例验证输出符合规则 |

### 3.1 AI 打标规则（P0-10 细则）

| 规则 | 要求 |
| --- | --- |
| 参考顺序与依据 | 先匹配已有候选标签（意思对得上就复用原样 label，不改写不同义词）→ 再新建；依据必须包含**软件的作用与简介**，不只靠进程名/窗口标题 |
| 多标签 | 多功能应用可打多个一级标签（Chrome → 工作 / 生活 / 学习 / 娱乐） |
| 单一倾向 | 游戏只打「娱乐」（燕云十六声 → 娱乐/燕云）；学习管理类可生活/学习/娱乐（Obsidian） |
| 自动建标 | 事项打标时允许自动创建两级标签，形式固定「父/子」（吃饭 → 生活/吃饭） |
| 白名单 | 一级只允许 生活 / 工作 / 学习 / 娱乐 / 复盘 / **工具**；最多两级；不写 #、不带空格 |
| 习惯沉淀 | 结果落库后成为下次候选；同类事项稳定命中同一标签，重复整理不漂移 |

## 4. 界面结构（文字线框）

```
┌─ 今日时间线（原待办 + 原时间线合并） ────────────────────┐
│ ▸ 待办事项                        3 条待办             │  ← 上区·标题行
│   [新建待办]                                           │
│   ○ 写周报            14:00 提醒    [✓] [编辑] [删]    │  ← 待办行（未开始）
│ ────────────────────────────────────────────────────  │  ← 浅横线（贯穿卡宽，固定不动）
│ ▸ 今日时间线                          总用时 6h12m     │  ← 下区·标题行
│   ● 进行中  吃饭             10:20 → —                  │
│   ✓ 已完成  刷题             09:00–09:40   40m  [改起止]│
└──────────────────────────────────────────────────────┘

┌─ 事项管理（独立新卡） ─────────────────────────────────┐
│ [新增] [编辑] [事项管理] [✦ AI 一键分类]                │
│ ★ 常用：吃饭 · 写周报 · 刷题        ← 置顶，点一下起停   │
│   历史：项目复盘 · 整理照片 …                            │
└──────────────────────────────────────────────────────┘
```
- 横线位置：时间线卡内两区的分隔线，不随滚动移动；待办区高度随内容自适应但有上限，超出则上区内部滚动。
- 时间线卡可点动作：新建待办、勾选完成/取消、编辑/删除待办、改起止时间、撤销删除。
- 事项管理卡可点动作：新增、编辑、事项管理、AI 一键分类、条目点击起停、条目绑定应用。

## 6. 边界与异常

| 场景 | 预期行为 |
| --- | --- |
| 无 AI 配置 | AI 分类按键置灰 + 提示「未配置 AI，去设置」；不影响其他功能 |
| AI 失败 / 超时 | 报错提示 + 原标签不变；可重试，不产生半截数据 |
| 事项/应用无标签 | 事项参与一键分类且不阻塞手动打标；应用行显示未分类，仍可手动打标 |
| 绑定的事项被删除 | 应用侧自动解绑 + 提示「原绑定事项已删除」，不残留悬空绑定 |
| 绑定应用切换 / 秒开秒关 | 已在计时中再切换不新建第二条记录；不足 10 秒的段不落库 |
| 统计为 0（全为工具类） | 分布/趋势显示「本期无可统计时长」，不显示 0% 环图 |
| 一键分类时无未打标事项 | 按键置灰，提示「没有需要分类的事项」 |

## 7. 待确认问题

1. 一个应用同时绑定多个事项时，自动计时以哪个为准——取最近绑定、还是弹选？
2. 「工具」标签下是否需要细分二级（如 工具/下载、工具/系统）？还是保持单层扁平？
3. 事项管理区是否允许删除常用事项但保留其历史时间线记录（只解除引用）？
